# docs/help: MATSU Editor のヘルプを書く人へ

利用者向けのヘルプ（mdBook で作り、Pagefind で検索し、あとで GitHub Pages に出す）の置き場です。決めたことは [ADR-0031](../adr/README.md) にあります（ADR の一覧に載るまでは、PR #394 を見てください）。このファイルは本の一部ではありません。ページを書く担当（エージェント）が従う決まりです。

## 置き場所

```
docs/help/
  book.toml        本の設定（題名、検索の設定、1 ページ版）
  README.md        このファイル
  ja/              日本語の本のソース（あとで en/ を足せる）
    SUMMARY.md     目次。未執筆のページは `- [名前]()` の下書きの章
    about.md       「このヘルプについて」（ライセンスと成り立ち）
    ...            各ページ
```

ビルドと検査の道具は、版を固定して CI に入れています（`.github/workflows/ci.yml` の `help` ジョブ）。ローカルで試すときは、mdBook 0.5.4 と Pagefind 1.6.0 の公開の実行ファイルをダウンロードし、自分の作業用の場所に置きます（システムには入れない。`cargo install` もしない）。

```sh
mdbook build docs/help                       # 出力: target/help/ （版によっては target/help/html/）
pagefind --site target/help/html --root-selector main --force-language ja
cargo xtask help-check --sakura <サクラの clone>   # 検査（下の「検査」）
```

## ページの書き方

### サクラのヘルプの文を写さない

サクラエディタのヘルプは GFDL 1.1 以降です。MATSU のヘルプは MIT OR Apache-2.0 で、サクラの文を写すことはできません。言い換えて写すことも、写すのと同じに扱います（ADR-0031 の「サクラのヘルプの文を写さない書き方」）。

- サクラのヘルプの本文を読まない。見ながら書かない。読んでしまった文を、別の言葉にして書くのも禁止
- 動きは、次から調べる
  1. MATSU のコードと試験（`crates/`）
  2. サクラのソース（`.claude/upstream/sakura`、zlib License）。コマンドは `sakura_core/cmd/CViewCommander*.cpp`、機能の一覧は `sakura_core/Funccode_x.hsrc`、既定のキー割り当ては `sakura_core/func/CKeyBind.cpp`、検索は `sakura_core/agent/CSearchAgent.cpp`
  3. 実際にサクラエディタを動かした結果（Windows Sandbox など。版も書く）
  4. 実際に MATSU Editor を動かした結果
- 例の文、説明の順序、見出しの組み立て、言い回しを、サクラのヘルプに合わせない。ページの組み立ては、MATSU の動きに合わせて自分で決める
- サクラのヘルプへ触れてよいのは、ページ名だけ（例: `HLP000081.html` に同じ項目がある、と「根拠」に書く）。本文は引かない
- メニュー・機能・マクロの関数・設定の項目の名前は、サクラと同じに書く（名前は文章ではない）
- 動きの主張には、必ず根拠を付ける（次の節）。根拠のない主張は書かない
- 仕様が分からないときは、推測で書かない。「分からない」と調整役に返す

### 根拠

どのページも、終わりに「根拠」の節を置きます。読む人が、書いてあることを確かめる場所です。

```md
## 根拠

- サクラのソース: `sakura_core/cmd/CViewCommander_Edit.cpp` の `CViewCommander::Command_UNDO`
- MATSU のコード: `crates/matsu-commands/src/commands/edit/undo.rs`
- 試験: `crates/matsu-commands/src/commands/edit/undo.rs` の `undo_restores_the_selection`
- サクラで確かめた: Sakura Editor v2.4.2 build 4203 で、…したところ…になった（2026-11-13）
```

- 書くのは、実際に確かめたものだけ。使わなかった行は書かない
- 場所はファイルとシンボルの名前で書く。行番号は、ずれるので書かない
- サクラの版は、確かめたもののコミットか版（v2.4.2 build 4203 など）を書く

### 名前

- メニューの名前、機能の名前（`F_FILEOPEN` など）、マクロの関数の名前（`FileOpen` など）、設定の項目の名前は、サクラと同じに書く。表は `crates/matsu-commands/src/sakura/`（`functions.rs`、`main_menu.rs`、`macro_functions.rs`）にある
- MATSU だけの名前（MATSU の機能・設定）は、MATSU の画面と同じ文字にする
- 製品名は [ADR-0021](../adr/0021-rename-to-matsu.md) の表に従う。英字で書く場所は「MATSU Editor」、カタカナで書く場所は「マツエディタ」。小文字のもの（`matsu.ini`、`matsu-*`、アプリの識別子）はそのまま。改名前の古い製品名は使わない（`crates/matsu/tests/leftover_names.rs` が見つける）
- サクラエディタを指すときは「サクラエディタ」と書く

### 文体

`CLAUDE.md` の「書き方」に従います。

- 平易な日本語で、短い文にする。1 文に 1 つのことを書く
- 「です・ます」で書く
- コードは必ず ``` で囲む（囲みの外の字下げでコードを書かない。検査は字下げのコードを本文として扱い、中のリンクや文を検査してしまう）
- 生の HTML でアンカーやリンクを書かない（`id`・`name`・`href` の属性を持つタグは、検査が間違いとして止める）。アンカーは見出しの id（`## 見出し {#id}`）、リンクは Markdown のリンク（`[文字](行き先)`）で書く。HTML のコメント（`<!-- -->`）や、属性のない HTML は使ってよい
- 手順は番号の付いた箇条書き、設定や対応は表にする
- 画面の文字は「」で囲む。キーは `Ctrl+S` のようにコード書式にする
- サンプルのコードのコメントと識別子は英語。ページの文は日本語

### ページの単位

- 1 つの機能（コマンド）または 1 つのダイアログに、1 ページ
- ADR-0031 が表にまとめると決めたもの（マクロの関数。名前・引数・戻り値をコードの表から作る）は、グループごとの表にする。1 関数 1 ページにはしない
- ページのファイル名は半角英数字とハイフン（例: `file-open.md`）。見出しは日本語でよい

### 本に足すとき

1. ページを `docs/help/ja/` に置く
2. `SUMMARY.md` の下書きの章 `- [名前]()` を `- [名前](path.md)` に変える。章の並びは変えない（ほかの担当と衝突するため）。章が足りないときは、ほかの章を動かさずに子の項目を足す
3. ページ同士のリンクは Markdown のリンクで、相対パス（`../edit/undo.md`）、同じページ内は `#見出し`。アンカーは見出しの文字から作られる（空白は `-`、記号は消える、英字は小文字）。`{#id}` で決めてもよい
4. `cargo xtask help-check` を通す。mdBook のビルドが通ることも見る

## 検査

CI の `help` ジョブ（と、手元の `cargo xtask help-check`）が、次を確かめます。失敗したら PR は通りません。

### リンク

ページ同士のリンクと `#アンカー` が、実在するものを指していること。`SUMMARY.md` に載っていないページがないこと。mdBook はアンカーを確かめない（ページのリンクだけ）ので、ここで確かめています。

### サクラのヘルプと同じ文がないこと

サクラの `help/` の HTML と MATSU の Markdown を、文字だけにして比べ、**同じ文字列が 20 文字以上続いたら失敗**にします。失敗したページは、サクラの文を見ずに、動きの根拠から書き直します（言い換えるだけでは直りません）。

比べる前の整え方は次のとおりです。

1. HTML のタグ・コメント・スクリプトを除き、実体参照（`&nbsp;` `&lt;` など）を元の文字にする。Markdown のコードブロック、リンク先、画像、HTML のタグ、`{{#include}}` の行を除く（インラインのコードの文字は残す）
2. 空白（全角を含む）と句読点・記号をすべて除く。段落の中の改行や、「、」と「,」の違いで、写しを隠せない。全角の英数字は半角にし、英字は小文字にする
3. **名前を 1 つの印にする**。サクラの機能・メニューの名前（`functions.rs` と `main_menu.rs` の表示名）、マクロの関数の名前（`macro_functions.rs`）、ダイアログの部品の文字（`sakura_core/sakura_rc.rc`）。名前だけが並んだページは、サクラと同じ文字列になるが、長さに数えない。文の中に名前があるだけなら、名前の前後の文字は数えるので、写した文は見つかる。名前を別の名前に替えた写しも見つかる（どちらも同じ印になるため）
4. 長さに数えるのは、名前の印と ASCII の英数字を除いた文字。英数字は、識別子・パス・URL・コード（プラグインのイベント名、`matsu.ini` のキーなど）で、同じことを書けば同じになる事実であるため

#### 20 文字にした理由（2026-11-13 に測った）

サクラの `help/`（767 ページ、コミット `48db6c7c`）に対して測りました。

- **偶然の一致の上限**: リポジトリの文書（`docs/` と ADR など 40 ファイル。サクラの機能を、サクラのヘルプを写さずに書いたもの）がサクラのヘルプと共有する最長の文字列は **14 文字**。

  | 長さの下限 | 12 | 14 | 16 | 18 以上 |
  |---|---|---|---|---|
  | 一致の数 | 6 | 1 | 0 | 0 |

  （14 文字の 1 つは「ステータスバーのメッセージ部」で、画面の部品の名前に近い言葉）
- **写しをどこまで見つけるか**: サクラの文（40 文字以上の文を無作為に 60 本）を写したものを検査にかけた。数字は、見つかった一致の数。

  | 写し方 | 16 | 20 | 24 | 32 |
  |---|---|---|---|---|
  | そのまま | 60 | 59 | 59 | 43 |
  | 10 文字ごとに 1 文字替える | 0 | 0 | 0 | 0 |
  | 20 文字ごとに 1 文字替える | 35 | 3 | 0 | 0 |
  | 26 文字ごとに 1 文字替える | 72 | 26 | 8 | 0 |
  | 40 文字ごとに 1 文字替える | 81 | 66 | 51 | 8 |

- 20 にした理由: 偶然の最長（14 文字）より 6 文字長いので、偶然の一致で失敗することはまずない（長さが 2 文字増えるごとに一致が 6〜7 分の 1 になる並びで、ページ数が 10 倍になっても、1 件出るかどうか）。一方 16 では偶然との差が 2 文字しかなく、24 では、少し手を入れた写しを見逃す量がふえる。20 は、サクラの文の中央値（22 文字）より短い
- 限界: 数文字ごとに言葉を替えた言い換えは、この検査では見つからない。だから「見ながら書かない」が決まりの本体で、この検査は、うっかりの一致を見つける網

長さは `xtask/src/help_shared.rs` の `MIN_SHARED_CHARS` にあります。手元で別の長さを試すには `cargo xtask help-check --sakura <clone> --min <文字数>`、いまの最長の一致を見るには `--longest` を付けます。

### あとで足す検査

ページに書いた機能名・マクロの関数名が、コードの表にあること（今はページがないので作っていない。`xtask/src/help_check.rs` の先頭に、足す場所を書いてある）。

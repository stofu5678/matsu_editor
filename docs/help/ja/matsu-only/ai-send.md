# 生成 AI に送る

選んでいる文字列（選んでいないときは文書全体）を、生成 AI のコマンドに通し、答えを文書かログのタブに入れます。送り先は、共通設定の「生成 AI」ページに登録します。送る前に確認の窓が出て、送った内容と答えがログのタブに残ります。

たとえば、選んだ文の英訳を頼むコマンドを送り先に登録すると、訳が選んだ文の次の行に入ります。

この機能は、ワンライナーとは別です（ADR-0035）。仕組みは[ワンライナー](oneliner.md)と共有していますが、メニューも設定のページも、設定ファイルの節（`[AI]`）も、別にあります。以前の版でワンライナーに付けた「生成 AI に送る」の印は、[起動のときの移し](#move)で `[AI]` に移ります。

## 動き

1. メニューの「生成 AI」の「そのまま送る」から送り先を選びます。機能 `F_AI_PROMPT_0` から `F_AI_PROMPT_49`、マクロ `AiPrompt0()` から `AiPrompt49()` でも呼べます。選んだ文字列をそのまま、プロンプトとして送ります（モード a。指示は足しません）。
2. 確認の窓が出ます。窓の上に、「選んだ文字列が、そのままプロンプトとして送られます」と出ます。「送る」を押すまで、何も送りません。
3. 作業用の空のフォルダを作り、そこでコマンドを動かします。選んだ範囲（なければ文書全体）を標準入力に渡します。
4. 終わったら、答えを結果の置き場所に入れます。送った内容と答えは、ログのタブに記録します。

選んだ範囲も文書も空のときは、何も送らず、状態バーで知らせます。

AI のツールを動かすのは、利用者が書いたコマンドです。MATSU Editor は、どのツールを動かすかを決めません。ツールを同梱することも、入れ方を案内することもしません。

文字列は、標準入力だけで渡します。コマンドラインにも環境変数にも入れません。API キーなどの認証は、ツール自身に任せます。MATSU Editor が、キーを渡したり、保存したりすることはありません。

指示をつけて送るモード b は、[次の節](#ask)です。

## 指示をつけて送る（モード b） {#ask}

メニューの「生成 AI」の「指示をつけて送る...」（機能 `F_AI_ASK`、マクロ `AiAsk()`）で、窓を 1 つ開きます。選んだ文字列（なければ文書全体）を材料にして、入力した指示で加工させます。モード a と同じ送り先が使えます。送り先は、窓の中で選びます。

窓には、次のものが並びます。

- 指示の欄。複数行を入れられます。`Enter` は改行で、送りません
- 送り先の一覧。最初に選ばれているのは、この起動中に最後に使ったものです。なければ、一覧の最初のものです。`Tab` で一覧に移ると、`↑` `↓` で選べます。クリックでも選べます
- これまでの指示の一覧（あるとき）。クリックすると、その指示が欄に入ります。欄が空のとき（または、一覧から入れた指示を直していないとき）は、`↑` `↓` でも順に選べます。新しいものが先です。`↓` で新しいほうへ戻り、いちばん新しいものの次は、空の欄に戻ります
- 送る内容の確認。[確認の窓](#confirm)と同じもの（送り先、コマンド、文字数、行数、大きさ、最初の 10 行と最後の 5 行、秘密に見える行の警告）を、実際に標準入力で送る形で出します。行の番号は、その標準入力の行の番号です
- 「送る」と「送らない」

標準入力に渡るのは、指示、空行、`---` の行、材料の順です。引数にも環境変数にも、指示は入れません。

```text
指示（前後の空白は取り、改行は LF にそろえる）

---
材料（選んだ文字列。改行は LF にそろえる）
```

- 指示が空（空白だけも空）のあいだは、「送る」を押せません。灰色で出て、`Enter` でも送りません
- `Esc`、「送らない」、窓を閉じるは、何も送りません。コマンドは動かず、文書も変わらず、指示の履歴にも入りません
- 材料が 100 KB を超えるときは、最初のフォーカスが「送らない」にあります。急いで `Enter` を押しても、送りません。指示を入れるには、`Shift+Tab` で欄へ戻ります
- 「次から聞かない」の箱は、ありません。この窓が確認を兼ねるので、送り先の「送る前に確認する」は、モード b には効きません
- `Tab` と `Shift+Tab` は、欄、送り先の一覧、「送る」、「送らない」の順に動かします（欄には、タブ文字を打てません。貼り付けは使えます）
- 材料と結果の置き場所は、モード a と同じです。箱形の選択は、箱の文字列です。文書が編集できないときは、結果を文書に入れる送り先は、窓に出ません（ログのタブだけの送り先は出ます）。使える送り先がないときは、窓を開かず、状態バーで知らせます。選んだ範囲も文書も空のときも、何も送らず、状態バーで知らせます
- 答えは、結果の置き場所に入ります。置き換えるときと次の行に入れるときは、取り消し 1 回で戻ります。ログのタブには、モード（指示つき）と指示の文も記録します

### 指示の履歴 {#ask-history}

窓の「これまでの指示」は、この起動中に「送る」を押した指示を、新しいものを先に、20 件まで持ちます。同じ指示（前後の空白と改行の種類をそろえたあとで同じもの）は 1 件にまとめ、新しいほうへ動かします。

指示には、文書の中身や個人の事柄が入ることがあるので、履歴はメモリにだけ持ちます。`matsu.ini` にも、セッションのファイルにも、ログのファイルにも、書きません。MATSU Editor を終えると、消えます。

マクロ `AiAsk()` は、この窓を開くだけです。指示の文字列をマクロから渡す手段は、ありません（指示は人が入れます）。キーマクロに記録しても、指示は記録に入りません。

## メニュー {#menu}

右クリックのメニューと、メインメニューの「ツール」に、サブメニュー「生成 AI」があります。「ワンライナー」のすぐ次です。

| 項目 | 動き |
|---|---|
| そのまま送る | 登録した送り先が並ぶサブメニューです。選ぶと、選んだ文字列（なければ文書全体）を、そのままプロンプトとして送ります（機能 `F_AI_PROMPT_0` から `F_AI_PROMPT_49`）。登録がないときは、「(なし)」が灰色で出ます |
| 指示をつけて送る... | [指示を入れる窓](#ask)を開きます（機能 `F_AI_ASK`、マクロ `AiAsk()`。モード b） |
| （区切り線） | |
| AI ログを表示 | [AI ログ](#ai-log)のタブへ移ります（機能 `F_AI_LOG_SHOW`） |
| 生成 AI の設定... | 共通設定を開きます（機能 `F_AI_SETTINGS`）。「生成 AI」のページで開きます |

- 「そのまま送る」の送り先は、文書が編集できないとき（閲覧モードなど）は、結果を文書に入れるもの（「置き換える」と「次の行に入れる」）が灰色になります。結果をログのタブだけに出す送り先は、選べます。ほかの実行（コマンドや、別のワンライナー）が動いている間も、灰色です。
- 「指示をつけて送る...」は、使える送り先が 1 つもないとき（登録がない、文書が編集できず、残りが文書に入れる送り先だけ、など）と、ほかの実行が動いている間は、灰色です。
- アクセスキーは、右クリックのメニューの「生成 AI」が `8`、メインメニューの「生成 AI」が `G` です。サブメニューの中は、「そのまま送る」が `P`、「指示をつけて送る...」が `I`、「AI ログを表示」が `L`、「生成 AI の設定...」が `S` です。macOS では、メニューの名前にアクセスキーは付きません。
- 「ワンライナー」のサブメニューにあった「AI ログを表示」は、ここに移りました。機能の名前と番号は同じなので、キー割り当てやメニューに入れてあれば、そのまま動きます。
- 「ワンライナー」のサブメニューでは、`[OneLiner]` にまだ「生成 AI に送る」の印が残っている枠が、灰色で並びます（次の節）。

保存してあったメニューには、サブメニュー「生成 AI」が 1 回だけ足されます。右クリックのメニューは版 4、メインメニューは版 6 です。

- 右クリックのメニューでは「ワンライナー」の次に、メインメニューでは「ツール」の「ワンライナー」の次に入ります。「ワンライナー」を消してあるメニューには、足しません。
- アクセスキーは、同じ階層の別の項目が使っているときは付けません。
- 足したあとで消すと、戻りません。メニューは、消したまま保存されます。
- 共通設定の「カスタムメニュー」と「メインメニュー」のページでは、この項目は、特別な項目（機能 `F_AI_PROMPT_LIST`）として出ます。

## 起動のときの移し {#move}

以前の MATSU Editor は、生成 AI に送る送り先を、ワンライナーの枠に「生成 AI に送る」の印（`[OneLiner]` の `AI[nnn]=1`）を付けて持っていました。いまは、送り先は `[AI]` に持ちます。印の付いた枠が `[OneLiner]` に残っていると、起動のときに、次のとおり `[AI]` に移します。

1. 先に、数えます。印の付いた枠の数が `[AI]` の空きの数以下かを、何も変えずに調べます。
2. 入るときは、印の付いた枠を、名前、コマンド、結果の置き場所、「送る前に確認する」ごと、`[AI]` の同じ番号（使われていれば、空いている最初の番号）に写します。同じ書き込みで、`[OneLiner]` のその枠を消します。書き込みは 1 回です。設定ファイルの、ほかの節と、知らないキーは、そのまま残ります。「アウトプットに出す」だった枠は、「ログのタブだけ」になります。
3. 入りきらないときは、何も移さず、何も消しません。一部だけ移すことも、しません。どれを先にするかは、MATSU Editor が決めないためです。
4. 印の付いた枠は、`[OneLiner]` に残っている間、ワンライナーとしては動きません。確認の窓なしで送ってしまうのを防ぐためです。メニューでは灰色になり、キーやマクロから呼ぶと、状態バーに「この枠は生成 AI の枠です。生成 AI の設定に移してください。」と出ます。
5. 起動のとき、状態バーで知らせます（古い名前の設定を引き継いだときの知らせと同じ場所で、20 秒ほど出ます。標準エラー出力にも、同じ文を出します）。移したときは、移した数と、移した枠を呼んでいたキー割り当て、カスタムメニュー、ツールバー、マクロ（`F_ONELINER_n`、`OneLinern()`）が、もう届かなくなることを書きます。入りきらなかったときは、`[AI]` が満杯で、いくつ移せなかったかと、その枠が動かない状態であることを書きます。入りきらなかったときの知らせは、空きができるまで、起動のたびに出ます。
6. 移したあとの `[OneLiner]` には印がないので、次の起動では、何も起きません。入りきらなかったときも、`[AI]` に空きを作れば、次の起動で 1 と 2 が動きます。

移した枠に付けていたキー割り当て、カスタムメニュー、ツールバー、マクロを、MATSU Editor が書き換えることはしません。利用者のデータを、推測で書き換えないためです。「ワンライナー n は登録されていません。」と状態バーに出たら、機能 `F_AI_PROMPT_n`、またはメニューの「生成 AI」の「そのまま送る」に、付け替えてください。移した枠の番号は、`[AI]` で見られます。

古い版の MATSU Editor に戻すと、その版は `[AI]` を知らないので、移した枠は見えなくなります。

設定ファイルが書き込めないなどで移せなかったときは、その理由を同じ場所に出します。枠は、移せるまで動きません。

## 登録する

共通設定の「生成 AI」ページで登録します。送り先は 50 個まで、番号は 0 から 49 です。ページの欄は[共通設定: 生成 AI](../common-settings/page-ai.md)にあります。要点は、次のとおりです。

- 欄は、名前、Id（枠の番号）、コマンド、結果の置き場所、「送る前に確認する」、ひな形です。コマンドは、標準入力からプロンプトを読めるものを 1 行で書きます。
- 結果の置き場所は、「置き換える」「次の行に入れる」（既定）「ログのタブだけ」の 3 つです。「ログのタブだけ」は、文書を変えません。
- ひな形は、Claude Code と Codex CLI です。コマンドを、ツールを使わせず会話の記録を残さない形にして入れます。

設定ファイルでは、`matsu.ini` の `[AI]` に、`Name[nnn]`、`Command[nnn]`、`Output[nnn]`（0 が置き換え、1 が次の行、2 がログのタブだけ。既定と、ほかの値は 1）、`AskBeforeSend[nnn]`（0 のとき確認の窓を出さない。既定は 1）で書きます。知らないキーは、そのまま残ります。

- ひな形のフラグは、2 種類です。1 つは、ツールにできることを狭めるものです。Claude Code の `--tools ""` は、ツールを使えなくします。Codex CLI の `--sandbox read-only` は、ファイルの変更を制限するものです。道具を使えなくするものではなく、Codex は、制限の中でファイルを読んだり、コマンドを動かしたりできます。もう 1 つは、ツールが会話の履歴を残さないためのもの（`--no-session-persistence`、`--ephemeral`）です。
- 送る文字列に、AI への命令のような文が入っていると、AI は、その制限の中で従うことがあります。
- フラグはツールの版で変わります。動かなくなったら、ツールの説明を見て直してください。
- 「ワンライナーを入力して実行」から登録したワンライナーは、ふつうのワンライナーです。生成 AI の送り先にはなりません。
- コマンドの中に指示を持つ送り先（`claude -p ... "訳せ"` のようなもの）も、そのまま動きます。モード a は、標準入力に材料だけを渡します。

## 確認の窓 {#confirm}

「AI に送る前の確認」の窓です。エディタのウィンドウの中に出て、文書を覆います。窓が出ている間、文書にキーは届きません。

窓に出るものは、次のとおりです。

- 送り先（送り先の名前）
- 実行するコマンド
- 文字数、行数、大きさ
- 送る文字の最初の 10 行と最後の 5 行。間は「（n 行を省略）」と出ます。1 行は 200 文字までで、長い行は途中で切ります
- 秘密に見える行があれば、その警告（次の節）
- 次の 2 つの注意。「MATSU は、このコマンドのフラグが AI のツールを本当に切るかを確かめられません。」と、「秘密に見える行の検査は形によるものです。見つけられない秘密もあります。」

| 操作 | 動き |
|---|---|
| 「送る」を押す | 実行します |
| 「送らない」、`Esc`、窓を閉じる | 何も送りません。コマンドは動かず、文書も変わりません |
| 「次から聞かない（この送り先だけ）」 | 「送る」を押したときだけ効きます。この送り先の「送る前に確認する」をオフにします。次からは、窓を出さずに実行します。窓が開いている間に、設定でこの番号のコマンドなどが変わっていたときは、書きません |

- キーは、`Tab` と `Shift+Tab` で、チェック、「送る」、「送らない」の順に動かします。`Space` でチェックを切り替え、`Enter` か `Space` で、いまのボタンを押します。
- 「送る」を選ばずに終わらせたときは、状態バーに「生成 AI に送らないので、実行しませんでした。」と出ます。ログのタブには、送らなかったという記録が残ります。
- 「次から聞かない」を取り消すには、共通設定の「生成 AI」ページで、「送る前に確認する」をオンに戻します。
- 窓が読む量には、上限があります。大きな選択で窓が固まらないためです。先頭の約 4 MiB だけを調べ、それを超えるときは、文字数を「以上」と出し、「大きいので、秘密に見える行の検査は先頭の一部だけです。」と添えます。

### 大きな文字列

送る文字が 100 KB を超えるときは、窓が赤い文字で知らせます。このとき、最初にフォーカスがあるのは「送らない」です。急いで `Enter` を押しても、送りません。

### 秘密に見える行の警告

文字列に、API キーやトークンの形が見つかると、その行を一部伏せて窓に出します。見つかった行の番号と、種類が出ます。出す行は 20 行までで、残りは「ほか n 行」と数だけ出ます。警告が出ても、送るかどうかは利用者が決めます。止めることはしません。

見つける形は、次のとおりです。

| 種類 | 形 |
|---|---|
| API キー | `sk-` ではじまる長い文字列（`sk-ant-`、`sk-proj-` を含む） |
| GitHub のトークン | `ghp_`、`gho_`、`ghu_`、`ghs_`、`ghr_`、`github_pat_` |
| GitLab のトークン | `glpat-` |
| AWS のアクセスキー | `AKIA` か `ASIA` と、大文字と数字の 16 文字 |
| 秘密鍵 | `-----BEGIN ... PRIVATE KEY-----` から `-----END` まで（`OPENSSH` と PGP の鍵も） |
| Slack のトークン | `xoxb-`、`xoxa-`、`xoxp-`、`xoxr-`、`xoxs-` |
| Google の API キー | `AIza` ではじまる文字列 |
| Stripe のキー | `sk_live_`、`rk_live_` |
| JWT | `eyJ` ではじまる、ドットで区切った 3 つの部分 |
| Bearer トークン | `Bearer` のあとの長い文字列 |
| URL の中のパスワード | `scheme://user:password@host` |

この検査は、形を見るだけです。ここにない形の秘密は、見つかりません。普通の文章や日本語、コードを、秘密と間違えないように、長さと文字の混ざり方も見ています。送る前に、自分の目でも確かめてください。

## 作業用のフォルダ

生成 AI の送り先は、文書のあるフォルダではなく、実行のたびに作る空の一時フォルダを、コマンドの作業フォルダ（カレントフォルダ）にして動かします。AI のツールには、作業フォルダの設定を読み込むものがあるためです。これで、ツールが、文書の隣のファイルや、プロジェクトの設定を、自分から読むことはありません。

ただし、フォルダの外を隔てるものではありません。ほかの場所のファイルには、ツール自身の権限が許す範囲で、手が届きます。

- フォルダは、OS の一時フォルダの中に作ります。名前は `matsu-ai-` ではじまります。Unix 系の OS では、自分だけが入れる設定で作ります。
- 実行が終わると、結果を入れたあとで、フォルダを消します。失敗、中断のときも消します。
- 作れなかったときは、実行せず、メッセージの箱で知らせます。

ふつうのワンライナーは、これまでどおり、文書のフォルダで動きます。

## AI ログ {#ai-log}

AI に送った内容と答えを並べる、読み取り専用のタブです。タブの名前は「AI ログ」です。

### 開く

- 生成 AI に送ると、ログのタブがなければ開きます。このとき、フォーカスは文書に残ります。
- サブメニュー「生成 AI」の「AI ログを表示(L)」で、タブへ移ります。タブがなければ開きます。機能名は `F_AI_LOG_SHOW` です。右クリックのメニューにも、メインメニューの「ツール」にもあります。macOS では、メニューの名前に `(L)` は付きません。
- ログのタブは、1 つのウィンドウに 1 つだけです。

実行している間も、記録は先に出ます。「状態: 実行中」と、動かしているコマンドの行が見えます。裏でコマンドが動いていることを、ここで確かめられます。

### 記録の中身

1 回の実行が、1 つの記録です。新しいものが下に並びます。

| 項目 | 内容 |
|---|---|
| 名前、番号 | 送り先の名前と、ログの中の通し番号 |
| モード | 「a（選んだ文字列をそのまま送った）」か「b（指示をつけて送った）」 |
| 指示 | モード b のときだけ。入れた指示の文 |
| 開始 | 開始した日時 |
| 状態 | 実行中か、終了コードとかかった時間 |
| コマンド行 | 動かしたコマンド |
| 入力 | 送った文字列（モード b は、指示と `---` の行をつけた、標準入力の全体） |
| 答え（標準出力） | コマンドの標準出力 |
| 標準エラー | コマンドの標準エラー出力 |

- 標準エラーは、文書の答えには混ぜません。ログに記録し、標準エラーがあるときは、アウトプットにも出ます。
- 「送らない」を選んだときは、送らなかったことが記録に残ります。
- コマンドが終了コード 0 以外で終わったときは、文書に何も入れません。終了コードと標準エラーが、アウトプットに出ます。ログにも記録が残ります。
- 1 つの文字列は 256 KiB までです。これより長いものは、先頭だけを残し、記録に切ったことと元の大きさを書きます。
- 記録は 50 件までです。超えたときは、古いものから消えます。

### 文字を選んでコピーする

記録の文字は、選んでコピーできます。コマンド行をコピーして、[シェルのタブ](shell.md)に貼れば、同じコマンドを自分で試せます。

| 操作 | キー（macOS） |
|---|---|
| コピー | `Ctrl+C`（`Cmd+C`） |
| すべて選択 | `Ctrl+A`（`Cmd+A`） |
| AI ログを閉じる | `Ctrl+W`（`Cmd+W`） |

ログのタブがアクティブなときは、メニューバーに「AI ログ(L)」だけが出ます。中身は、コピー、すべて選択、AI ログを閉じるです。

### 残らない

ログは、メモリにだけ持ちます。ファイルには書きません。[自動保存](autosave.md)にも入りません。タブを閉じるか、MATSU Editor を終えると、消えます。ログのタブを閉じても、確認は出ません。動いている実行は止まらず、その終わりの記録だけが、捨てられます。

### ウィンドウの機能のキー

次のウィンドウ（`Ctrl+Tab`）や前のウィンドウ（`Ctrl+Shift+Tab`）などの、ウィンドウの機能のキーは、ログを見ている間も使えます。タブの帯を出さない既定の設定でも、この 2 つで、文書とログのタブのあいだを行き来できます。シェルのタブとプレビューのタブと同じです。

## サクラとの違い

サクラエディタには、生成 AI に送る機能も、ワンライナーもありません。MATSU Editor だけの機能です。

## 守られないこと

- 送った文字列は、AI のサービスの外に出ます。サービスがそれをどう扱うかは、提供元と利用者の間の取り決めです。MATSU Editor は、どれも制御できません。
- ツールの道具が本当に切れているかは、MATSU Editor には分かりません。ひな形のフラグが効かない版も、ありえます。フラグがあっても、ツールが文書の外のファイルを読めないとは限りません。
- 秘密の検査は、形によるものです。
- 端末（シェルのタブ）には、何も送りません。AI のツールは、パイプで動かします。

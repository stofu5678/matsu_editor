# 巨大なファイル

数 GB のファイルを、全部は読み込まずに開きます。開くとすぐに先頭が見え、行の区切りの位置は、後ろで調べます。

この機能に、専用のコマンドはありません。決めた大きさ以上のファイルを開くと、自動でこの方式になります。

## 始まる大きさ

既定では、256 MB 以上のファイルがこの方式で開きます。

共通設定の「ファイル」ページで、変えられます。

- 項目: 「MB以上のファイルは、範囲ごとに読んで開く」（名前: 範囲ごとに読むファイルの大きさ（MB））
- 値: 1 から 1000000
- `matsu.ini` の場所: `[Common]` の `nHugeFileSizeMB`

サクラにもある「開こうとしたファイルが大きい場合に警告する」（`nAlertFileSize`）は、別の設定です。そのまま残っています。

## 開いたあとの様子

1. ファイルを開くと、先頭の部分がすぐに表示されます。ファイルの全体は、メモリに読み込みません。見えている所の近くだけを、そのつど読みます。
2. 後ろで、ファイルの行の区切りを先頭から調べます。この間、状態バーに「改行位置を調べています 35% (約 120,000 行)」のように、進み具合と行数の見込みが出ます。
3. 調べている間は、編集と保存はできません。しようとすると、「改行位置を調べている間は編集できません」と知らせます。
4. 調べ終わると、ふつうの文書になります。編集と保存ができます。

調べている間の行数は見込みなので、「約」が付きます。

### 調べ終わる前に、先へ移るとき

`Ctrl+End` や、まだ調べていない行への移動、スクロールバーのつまみのドラッグでは、その場所のまわり（約 1 MiB）だけを読んで、すぐに表示します。

- この間の表示は、読み取り専用です。
- 行番号の欄は、`~70000` のように、頭に `~` が付きます。状態バーの行数は「約70000 行」のようになります。
- 調べ終わると、行番号が正確になり、全体の文書に替わります。
- 窓が出ている間に付けたブックマークは、調べ終わるときに消えます。
- 窓の中の検索と、すべて選択は、窓の中だけが対象です。

## 長い行

1 MiB 以上の長い行は、画面の上でだけ、4096 バイトごとに折り返して表示します。文書の行と行番号は、ファイルのとおりのままです。折り返しの設定とは関係なく、この幅になります。

## 使えない機能と、ちがう動き

| 機能 | 動き |
|---|---|
| アウトライン解析 | 「巨大なファイルなので、アウトライン解析は使えません」と出ます |
| 色分け | 64 KiB 以上の行には、色が付きません。ブロックコメントなどが、画面の 200 行より上で始まっているときは、色が付かないことがあります |
| Grep | 範囲ごとに読むファイルは、1 MiB ずつ読んで検索します。範囲で開けないファイルは、結果に `file open error [パス]` と理由を出して、飛ばします |
| 差分表示 | どちらかが、範囲ごとに読む大きさか 256 MiB の、小さいほう以上のときは、読まずに断ります |
| マクロ | 調べている間の `GetLineCount` と、調べていない先の `GetLineStr` は、エラーになります。`GetSelectedString` は、256 MiB 以上を断ります |
| ISO-2022-JP と UTF-7 | 範囲ごとには読めないので、全体を読み込んで開きます。時間とメモリがかかります |
| 排他制御 | 範囲ごとに読んでいるファイルでは、「読み書きを禁止する」を「上書きを禁止する」として扱います。開いたあとも、ファイルを読み続けるためです |

## 保存

保存するときは、一時ファイルに書いてから、元のファイルと入れ替えます。

- 書き始める前に、保存先の空き容量を確かめます。足りなければ、書き始めずに「ディスクの空き容量が足りない（最大 … MiB 必要。空きは … MiB）」と知らせます。元のファイルは変わりません。この確認は、巨大なファイルでなくても、すべての保存で行います。
- 保存したあとも、元に戻すは使えます。ただし、文字コードと改行を変えない保存で、文字コードが UTF-8 か Latin1 のときだけです。それ以外では、保存したファイルを読み直すため、元に戻すの履歴は消えます。

## いま届いていないこと

次のことは、まだできていません（ADR-0020 の追記にあります）。

- 行数の表を持たないレイアウト。1 行につき 4 バイトの表を持つので、行の数が非常に多いファイルで、メモリを多く使います。
- 1 MiB 以上の長い行を、1 つの文字列にして扱う所（IME の入力、行単位のコマンド、箱選択など）は、時間とメモリがかかります。
- 「すべて置換」を、新しいファイルに書き出す方式にすること。いまは全体を読む方式です。
- クリップボードへのコピーと切り取りの上限。
- 折り返す設定で、調べ終わったあとの文書が、折り返さずに桁で切れる不具合が知られています。

## サクラとの違い

サクラエディタには、範囲ごとに読んで開く方式がありません。MATSU Editor だけの機能です。

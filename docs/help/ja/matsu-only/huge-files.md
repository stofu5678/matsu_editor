# 巨大なファイル

数 GB のファイルを、全部は読み込まずに開きます。開くとすぐに先頭が見え、行の区切りの位置は、後ろで調べます。

この機能に、専用のコマンドはありません。決めた大きさ以上のファイルを開くと、自動でこの方式になります。

## 始まる大きさ

既定では、256 MB 以上のファイルがこの方式で開きます。

共通設定の「ファイル」ページで、変えられます。

- 項目: 「MB以上のファイルは、範囲ごとに読んで開く」（名前: 範囲ごとに読むファイルの大きさ（MB））
- 値: 1 から 1000000
- `matsu.ini` の場所: `[Common]` の `nHugeFileSizeMB`

サクラにもある「開こうとしたファイルが大きい場合に警告する」（`nAlertFileSize`）は、別の設定です。そのまま残っています。

## 開いたあとの様子

1. ファイルを開くと、先頭の部分がすぐに表示されます。ファイルの全体は、メモリに読み込みません。見えている所の近くだけを、そのつど読みます。
2. 後ろで、ファイルの行の区切りを先頭から調べます。この間、状態バーに「改行位置を調べています 35% (約 120,000 行)」のように、進み具合と行数の見込みが出ます。
3. 調べている間は、編集と保存はできません。しようとすると、「改行位置を調べている間は編集できません」と知らせます。
4. 調べ終わると、ふつうの文書になります。編集と保存ができます。

調べている間の行数は見込みなので、「約」が付きます。

### 調べ終わる前に、先へ移るとき

`Ctrl+End` や、まだ調べていない行への移動、スクロールバーのつまみのドラッグでは、その場所のまわり（約 1 MiB）だけを読んで、すぐに表示します。

- この間の表示は、読み取り専用です。
- 行番号の欄は、`~70000` のように、頭に `~` が付きます。状態バーの行数は「約70000 行」のようになります。
- 調べ終わると、行番号が正確になり、全体の文書に替わります。
- 窓が出ている間に付けたブックマークは、調べ終わるときに消えます。
- 窓の中の検索と、すべて選択は、窓の中だけが対象です。

## 長い行

1 MiB 以上の長い行は、画面の上でだけ、4096 バイトごとに折り返して表示します。文書の行と行番号は、ファイルのとおりのままです。折り返しの設定とは関係なく、この幅になります。

この表示は、範囲ごとに読む方式で開いたファイルだけでなく、**すべての文書**で同じです（数 MB から数百 MB の 1 行を持つふつうのファイルも、同じように扱います）。1 MiB より短い行は、これまでどおり、折り返しの設定の桁数で折り返します。

- キー 1 つで読むのは、キャレットのまわりと、画面に見える行（4096 バイトずつ）だけです。200 MiB の 1 行でも、キーに 0.02 秒ほどしかかかりません。
- 長い行の中の桁は、バイトの数で出ます（半角の文字だけなら、文字の数と同じです。全角の文字があると、状態バーの桁は少しずれます）。
- 文字コードが UTF-8 以外でも同じです。長い行の途中の場所は、最初に使うときに、64 KiB ごとの目印を作って（長い行だけ、1 回だけ）調べます。
- 色分けは、画面に見えている部分だけを調べます。長い行の中で、コメントや文字列の始まりが画面より前にあると、色が変わることがあります。画面の中で始まったコメントは、続く行（4096 バイトの折り返し）にも続けて色が付きます。長い行の中で開いたまま閉じていないコメントは、次の行には続きません。ミニマップも同じです。

## 使えない機能と、ちがう動き

| 機能 | 動き |
|---|---|
| アウトライン解析 | 「巨大なファイルなので、アウトライン解析は使えません」と出ます |
| 色分け | 範囲ごとに読むファイルでは、64 KiB 以上の行には、色が付きません。ブロックコメントなどが、画面の 200 行より上で始まっているときは、色が付かないことがあります。範囲ごとに読まないファイルの 1 MiB 以上の行は、上の「長い行」のとおり、画面に見える部分に色が付きます |
| Grep | 範囲ごとに読むファイルは、1 MiB ずつ読んで検索します。範囲で開けないファイルは、結果に `file open error [パス]` と理由を出して、飛ばします。1 行が 64 MiB を超える行は、読み込まず、結果に「N行目が長すぎる（… MB。上限は 64 MB）ので検索しませんでした。 [パス]」と出して、次の行へ進みます |
| Grep 置換 | 範囲ごとに読むファイルは、全体を読み込まず、1 行ずつ読んで、新しいファイルへ書きながら置換します（メモリは、いちばん長い行の分です）。ヒットのないファイルには何も書きません。1 行が 64 MiB を超える行は、置換せず、そのまま新しいファイルへ写して、結果に「N行目が長すぎる（… MB。上限は 64 MB）ので検索も置換もせず、そのまま残しました。 [パス]」と出します。範囲で開けないファイルは、Grep と同じく、結果に理由を出して飛ばします |
| 差分表示 | どちらかが、範囲ごとに読む大きさか 256 MiB の、小さいほう以上のときは、読まずに断ります |
| マクロ | 調べている間の `GetLineCount` と、調べていない先の `GetLineStr` は、エラーになります。`GetSelectedString` の選択範囲と、`GetLineStr` の行は、256 MiB 以上を断ります |
| コピーと切り取り | 選択範囲（箱選択は、その行のテキスト）が 256 MiB 以上のときは、「選択範囲が大きすぎる（… MB。上限は 256 MB）ので、コピーできません。」と知らせ、クリップボードを変えません。切り取りは、文字を削除せずに断ります。行番号つきのコピー、選択範囲内の色付き HTML のコピー、選択のない行のコピーも同じです。色付き HTML は、作った HTML が 256 MiB に届いた時点でも断り、範囲で開いていない文書で 1 MiB 以上の行にかかる選択（行の頭で終わる選択も、その行の配置が要るので同じ）も断ります（行の色を、行全体でまとめて作るため）。「選択範囲に長すぎる行（… MB。上限は 1 MB）があるので、色付きHTMLをコピーできません。」と出ます |
| ファイル内容比較 | 1 MiB 以上の長い行は、1 MiB ずつ読んで比べます。最初に違う所まで読んで、止まります |
| 検索のダイアログに入れる文字列 | 選択のない長い行では、キャレットの前後 4 KiB だけから、キャレットの下の単語を取ります（端で切れた単語は短くなります） |
| 箱選択の貼り付け | 長い行の行末の改行を、行の索引だけで調べます（行を読み込みません） |
| `$x`（ヘッダー、タイトル、`ExpandParameter`） | 長い行では、バイトの桁を UTF-16 の桁として扱います（全角の文字があると、少しずれます。状態バーの桁と同じです） |
| ISO-2022-JP と UTF-7 | 範囲ごとには読めないので、全体を読み込んで開きます。時間とメモリがかかります |
| 排他制御 | 範囲ごとに読んでいるファイルでは、「読み書きを禁止する」を「上書きを禁止する」として扱います。開いたあとも、ファイルを読み続けるためです |

## 保存

保存するときは、一時ファイルに書いてから、元のファイルと入れ替えます。

- 書き始める前に、保存先の空き容量を確かめます。足りなければ、書き始めずに「ディスクの空き容量が足りない（最大 … MiB 必要。空きは … MiB）」と知らせます。元のファイルは変わりません。この確認は、巨大なファイルでなくても、すべての保存で行います。
- 保存したあとも、元に戻すは使えます。ただし、文字コードと改行を変えない保存で、文字コードが UTF-8 か Latin1 のときだけです。それ以外では、保存したファイルを読み直すため、元に戻すの履歴は消えます。

## いま届いていないこと

次のことは、まだできていません（ADR-0020 の追記にあります）。

- 1 MiB 以上の長い行を、1 つの文字列にして扱う所（IME の入力、行単位のコマンド（並べ替え、インデント、段落、箱の編集、貼り付けなど）など）は、時間とメモリがかかります。
- 画面の文書の「すべて置換」を、新しいファイルに書き出す方式にすること。いまは文書の中で置換します（Grep 置換は書き出す方式です）。

## サクラとの違い

サクラエディタには、範囲ごとに読んで開く方式がありません。MATSU Editor だけの機能です。

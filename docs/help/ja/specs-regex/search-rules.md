# 検索の仕組みと上限

検索・置換・Grep が、文書をどう読んで一致を探すかの決まりです。どれも、サクラエディタの動きに合わせています。「検索」のダイアログと各コマンドの使い方は、「コマンド: 検索」の章にあります。

## 1 行ずつ探す

- 検索は、文書を 1 行ずつ読んで、行ごとに一致を探します。一致が、次の行へ続くことはありません。
- 正規表現には、行の文字列のあとに、その行の改行も付けて渡します。だから、パターンで改行そのものを探せます（`\r\n`、`[\r\n]+`、`\s`、`[^a]` など）。
- 改行の途中から始まる一致は、改行の先頭から始まった一致として扱います。CR LF の `\r` だけに一致させたときは、置換でも `\n` が残ります（`\n` まで消えることはありません）。
- 行の末尾に改行がない最後の行では、行の末尾から探し始めません。ただし、「すべて置換」の一括置換だけは、改行のあとの位置にも空の一致を探します（`x*` を `-` に置換すると、`ab` + LF が `-a-b-` + LF + `-` になります）。
- 行をまたいで探す検索は、まだありません（将来の拡張として、ADR-0006 に書いてあります）。
- プレーンの検索（正規表現を使わない検索）には、改行を付けない行の文字列を渡します。

## 前へ・次へ・すべて

- 次を探す: 一致した部分の終わりから、続きを探します。空の一致のときは、1 文字進んでから探します。同じ空の一致を、繰り返し見つけないためです。
- 前を探す: 行の頭から順に探して、キャレットより前で始まる最後の一致を取ります。一致が重ならないようにするための、サクラと同じやり方です。
- すべて探す: 行ごとに、「次を探す」と同じ進み方で、最後まで探します。
- 長い検索は、別のスレッドで動き、行と行のあいだで中断できます。1 行の中の照合は、途中で止められません。

## `.` と `$` の置き換え

エンジンは、LF だけを行の終わりと見ます。そこで、サクラと同じに、パターンをエンジンに渡す前に、次のように書き換えます（クラスの中と `\Q...\E` の中は、書き換えません）。

| パターンの中 | 書き換え後 | 意味 |
|---|---|---|
| `.` | `[^\r\n]` | CR と LF 以外の 1 文字 |
| `$` | `(?<![\r\n])(?=\r\|$)` | 行の末尾（CR LF の前も含む） |

- この書き換えのため、`(?s)` を付けても、`.` は CR や LF に一致しません。
- `$` が置き換わると、後読みの中に `$` を書けなくなります。`(?<=$)` は、サクラと同じようにエラーになります。
- `(?#...)` のコメントと、`(?x)` の `#` のコメントの中でも、書き換えは行われます。サクラと同じです。

## パターンの終わりの `\`

エスケープされていない `\` で終わるパターンと置換文字列は、エラーです。`a\` はエラー、`a\\` は正しく、`a\\\` はエラーです。サクラは、パターンのあとに区切りの文字（U+FFFF）を付けてエンジンに渡すので、最後の `\` が区切りを打ち消してしまうためです。bregonig.dll 4.20 で測った結果です。

## 大文字と小文字、単語単位

- 正規表現の検索は、「英大文字と小文字を区別する」を外していると、`i` つきで照合します。
- プレーンの検索で区別しないときは、文字を小文字にそろえて比べます。そろえるのは、基本多言語面（BMP）の文字だけで、ASCII、ラテン文字、ギリシャ文字、キリル文字、全角の英字が対象です。全角と半角は、同じ文字として扱いません（`Ａ` と `a` は別）。BMP の外の文字は、そろえません。
- プレーンの検索の「単語単位」は、パターンを単語に切って、そのうちのどれかが、行の中の 1 つの単語として現れる所を探します。`foo,bar` は、`foo` と `,` と `bar` を、別々に探します。空白、タブ、全角の空白は、単語を分けるだけです。
- 正規表現のときは、「単語単位」は使いません。サクラは、このチェックボックスを灰色にします。
- 空のパターンは、何にも一致しません。

## 置換の進め方

- 「すべて置換」には、2 つの進め方があります。「「すべて置換」は置換の繰返し」のチェックで切り替えます（既定はオフ）。
  - オフ（一括置換）: 1 行を、置換する前の状態のまま最後まで調べて、見つけた一致をまとめて置換します。後読みや `\b` は、置換前の文字を見ます。
  - オン（置換の繰返し）: 1 つ置換して、変わった文字列に対して、続きを探します。後読み、`\b`、`\G` が見る文字が、置換のたびに変わります。
- 置換文字列に改行を入れると、行が分かれます。置換で行が合わさったときは、置換後の文字列の終わりから、続きを探します。
- 選択範囲の中の置換は、選択の終わりで止まります。置換で選択の終わりの位置が動いても、それに追従します。
- 「すべて置換」は、途中でやめられます。やめたときは、文書を変えません。
- 置換の記法は、[置換文字列の書き方](regex-replace.md) にあります。

## 上限

- 照合の件数に、上限はありません。Onigmo の「照合のスタックの上限」は、MATSU Editor では上限なしです。
- 1 回の照合が、エンジンの失敗で終わると、「検索に失敗しました」という趣旨のエラー（`the search failed: ...`）になります。一致なしとは別の扱いです。
- パターンの入れ子の深さの上限は、4096 です（Onigmo の既定値）。深すぎるとエラーになります。
- 検索の履歴には、検索条件が 30 件、置換後の文字列が 30 件まで残ります。1 件は 260 文字（UTF-16 の単位）より短いものに限ります。Grep の条件は、「ファイル」「フォルダー」とも 30 件、1 件は 512 文字（同）より短いものです。
- 検索した文字列の強調表示は、描くたびに探しなおします。そのため、64 KiB（65536 バイト）より長い行は、強調表示のために探しません（対応するかっこの強調も同じです）。検索そのものは、長い行でも行います。

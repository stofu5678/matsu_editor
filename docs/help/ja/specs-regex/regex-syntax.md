# 正規表現の構文

「検索」「置換」「Grep」などで「正規表現」にチェックを入れたときの、検索パターンの書き方です。置換文字列の書き方は [置換文字列の書き方](regex-replace.md)、行ごとに照合する仕組みは [検索の仕組みと上限](search-rules.md) にあります。

## 使っているエンジン

- 正規表現のエンジンは Onigmo 6.2.0 です。ソースを `crates/matsu-regex/onigmo/` に取り込んでいます。Unicode の表は 12.1 です。
- 構文は、Onigmo の Perl 構文に、次の 4 つを足したものです（`crates/matsu-regex/c/shim.c`）。
  - 文字クラスの中の `&&`（積集合）
  - `\g<名前>` と `\g<番号>`（部分式の呼び出し）
  - 長さの違う選択肢を持つ後読み（`(?<=a|bc)`）
  - 不在演算子 `(?~...)`
- サクラエディタが使う bregonig.dll と同じ構文を目指しています。文字列のオプション（`i` `x` `a` `R` など）の組み立ては、サクラの `CBregexp::MakePatternSub` に合わせています。
- 名前付きのグループも、名前のないグループも、`(` の並びの順に番号が付きます。

## 区別する・しないの設定

- 「英大文字と小文字を区別する」を外しているとき（既定）は、パターンに `i` を付けて照合します。
- `i` は、英字だけでなく、全角の英字、ギリシャ文字、キリル文字、アクセント付きの文字にも効きます。`ａ` と `Ａ` は同じ文字として扱います。
- パターンの中で `(?i)` や `(?i:...)` を書いても同じ効果です。`(?-i)` で元に戻せます。
- 「単語単位」は、正規表現のときは使いません。単語の境目には `\b` を書いてください。

## 文字

| 書き方 | 意味 |
|---|---|
| `\t` `\r` `\n` `\f` `\a` `\e` | タブ、CR、LF、改ページ、ベル、ESC |
| `\012` | 8 進数の文字コード（この例は LF） |
| `\o{101}` | 波かっこの中の 8 進数 |
| `\x41` | 16 進数 2 桁 |
| `\x{3042}` | 波かっこの中の 16 進数（コードポイント） |
| `\cA` | 制御文字（Ctrl+A） |
| `\Q...\E` | 間の文字をそのまま探す（`\Q` と `\E` の間は特殊文字として読まない） |
| `\` と記号 | その記号そのもの（`\.` `\*` `\\` `\(` など） |

- `\h` `\H` `\v` `\y` `\Y` `\N` `\E`（`\Q` なし）のような、意味のない組み合わせは、後ろの 1 文字そのものを探します。たとえば `\h` は、文字 `h` を探します。16 進数字のクラスではありません。
- `\<` と `\>` も、文字 `<` と `>` そのものです。単語の始まりと終わりの印ではありません。

## 文字クラス

| 書き方 | 意味 |
|---|---|
| `[abc]` `[a-z]` | 並べた文字、範囲の中の 1 文字 |
| `[^abc]` | それ以外の 1 文字（改行の文字も含む） |
| `[あ-ん]` | 日本語の文字の範囲も書ける |
| `[[:alpha:]]` `[[:digit:]]` `[[:graph:]]` `[[:word:]]` | POSIX 形式のクラス。`[[:^digit:]]` は否定 |
| `[a-z&&[^aeiou]]` | 積集合（両方に入る文字）。クラスの入れ子も書ける |
| `\d` `\D` | 数字（全角の数字や、他の文字体系の数字も含む）、それ以外 |
| `\w` `\W` | 単語を作る文字（日本語の文字も含む）、それ以外 |
| `\s` `\S` | 空白（全角の空白 U+3000 や改行の文字も含む）、それ以外 |
| `\p{Han}` `\p{Hiragana}` `\p{Katakana}` `\p{L}` `\p{Alnum}` | Unicode の文字の性質（スクリプト名や一般カテゴリー） |
| `\p{^Han}` `\P{Han}` | その性質を持たない文字 |

- `\d` `\w` `\s` と POSIX 形式のクラスは、既定で Unicode 全体に効きます。`(?a)` を付けると、ASCII だけに限ります。`(?u)` で Unicode に戻せます。
- `.` は、CR と LF 以外の 1 文字です。`(?s)` を付けても、CR や LF には一致しません（[検索の仕組みと上限](search-rules.md) を参照）。

## 位置

| 書き方 | 意味 |
|---|---|
| `^` | 行の先頭 |
| `$` | 行の末尾（改行の直前） |
| `\A` | 行の先頭 |
| `\b` `\B` | 単語の境目、境目でないところ |
| `\G` | 検索を始めた位置 |
| `\K` | ここまでに一致した部分を、結果の範囲から外す（`a\Kb` は、`ab` の中の `b` だけに一致） |

- `\z` と `\Z` は、使わないでください。行の末尾の改行まで含めて照合するので、`a\z` は、改行つきの行 `a` + CR LF に一致しません。行の末尾には `$` を使います。
- 「すべて置換」の「一括置換」では、`\G` は、直前の一致の終わりにとどまります。空の一致を 1 文字進んで越えたあとは、`\G` はもう一致しません。

## 繰り返し

| 書き方 | 意味 |
|---|---|
| `*` `+` `?` | 0 回以上、1 回以上、0 回か 1 回 |
| `{n}` `{n,}` `{n,m}` | n 回、n 回以上、n 回以上 m 回以下 |
| `*?` `+?` `??` `{n,m}?` | なるべく少なく繰り返す（最短一致） |
| `*+` `++` `?+` `{n,m}+` | 戻らずに繰り返す（強欲な繰り返し） |

- `{,m}`（下限を省いた書き方）は、繰り返しではなく、そのままの文字列として探します。`{0,m}` と書いてください。

## グループと参照

| 書き方 | 意味 |
|---|---|
| `(...)` | 番号の付くグループ |
| `(?:...)` | 番号の付かないグループ |
| `(?<名前>...)` `(?P<名前>...)` | 名前付きのグループ（番号も付く） |
| `(?>...)` | 戻らないグループ（アトミックグループ） |
| `(?i)` `(?i:...)` `(?x)` `(?a)` `(?u)` | オプションの切り替え。`(?-i)` のように `-` で打ち消す |
| `(?#...)` | コメント |
| `\1` `\g{1}` `\g{-1}` | 番号による後方参照（`\g{-1}` は 1 つ前のグループ） |
| `\k<名前>` `(?P=名前)` | 名前による後方参照 |
| `\g<名前>` `\g<1>` `(?1)` `(?&名前)` `(?P>名前)` | グループの中身のパターンを、その場でもう一度使う（呼び出し） |

- 同じ名前のグループを複数書いても構いません。
- 後ろで定義されるグループへの参照（`\1(a)`）は、構文として通りますが、何にも一致しません。存在しない番号の参照（`(a)\2`）は、エラーです。
- `(?x)` を付けると、パターンの中の空白と、`#` から行末までのコメントを無視します。ただし、サクラと同じく、`.` と `$` の置き換えは、コメントの中でも行われます。

## 先読み・後読み

| 書き方 | 意味 |
|---|---|
| `(?=...)` `(?!...)` | 先読み、否定の先読み |
| `(?<=...)` `(?<!...)` | 後読み、否定の後読み |
| `(?~...)` | 不在演算子。`...` を含まない範囲の、いちばん長い一致 |
| `(?(1)yes\|no)` `(?(<名前>)yes\|no)` | 条件。グループが一致していれば `yes`、していなければ `no` |

- 後読みの中には、長さの違う選択肢を書けます（`(?<=a|bc)d`）。`*` のように長さが決まらない繰り返しは、エラーです（`invalid pattern in look-behind`）。
- 後読みは、検索を始めた位置より前の文字も見ます。

## そのほかの記法

| 書き方 | 意味 |
|---|---|
| `\R` | 改行（CR LF、LF、CR など）のひとかたまり |
| `\X` | 結合文字を含めた、見た目の 1 文字 |
| `a\|b` | a または b |

## 使えないもの、サクラと同じ癖

- `\<` `\>`（単語の始まりと終わり）、`\h`（16 進数字）、`\v`、`{,m}` は、上に書いたとおり、特別な意味を持ちません。
- `.` と `$` は、エンジンに渡す前に別のパターンに置き換わります。`(?<=$)` のように、`$` が置き換わると構文として成り立たなくなる書き方は、エラーになります。
- パターンの末尾が、エスケープされていない `\` のときは、エラーです。

## 構文の誤り

パターンに誤りがあると、「正規表現エラー」という題の箱が出ます。本文は「正規表現の構文に誤りがあります。」と「詳細：」で、続くのはエンジンの英語のメッセージです。たとえば次のものがあります。

| パターン | メッセージ |
|---|---|
| `(` | `end pattern with unmatched parenthesis` |
| `)` | `unmatched close parenthesis` |
| `[a` | `premature end of char-class` |
| `*` | `target of repeat operator is not specified` |
| `\k<x>`（`x` という名前のグループがない） | `undefined name <x> reference` |
| `(?<=a*)b` | `invalid pattern in look-behind` |
| `(a)\2` | `invalid backref number/name` |

## サクラエディタとの違い

- 実物の bregonig.dll は、ソースを読まずに、説明書（`bregonig.html`）と、実物を動かした結果に合わせています。互換の測定の記録は `crates/matsu-regex/tests/bregonig_compat.rs` と `tools/bregonig-compat/`（bregonig.dll 4.20 を Windows で動かした結果と、その道具） にあります。
- Onigmo は、1 回の照合を途中で止める仕組みを持っていません（[検索の仕組みと上限](search-rules.md)）。
- [docs/sakura-gaps.md](https://github.com/stofu5678/matsu_editor/blob/main/docs/sakura-gaps.md) に、正規表現の互換で残っている確認が書いてあります（複数行の照合の細部、Unicode の表の更新など）。

## 根拠

- サクラのソース: `sakura_core/extmodule/CBregexp.cpp` の `MakePatternSub`（オプションの組み立て）
- MATSU のコード: `crates/matsu-regex/c/shim.c`（構文の組み立て）、`crates/matsu-regex/src/lib.rs`（オプションの対応）
- 試験: `crates/matsu-regex/src/tests.rs` の `bregonig_extensions_are_enabled`、`digits_and_word_characters_include_full_width`、`ascii_range_limits_the_character_classes`、`case_is_sensitive_by_default_and_ignore_case_is_unicode_aware`、`bad_patterns_report_the_engine_message`
- MATSU を動かして確かめた: `RegexMatcher` に、この表の書き方を 1 つずつ渡して、一致の範囲を見た（2026-11-14）。`\h` `\v` `\<` `\N` `{,2}` が文字そのものになること、`a\z` と `a\Z` が CR LF の行に一致しないこと、`(a)\2` がエラーになることは、この確認による
- ADR: `docs/adr/0006-regex-engine.md`

## 背景

- ユーザーの企画（2026-11-11）の 5 番目。「ヘルプ」「GitHub Pages で用意？」「サクラエディタ相当のヘルプに加えてスクリプトのサンプルも欲しい」
- 今の MATSU に、利用者向けのヘルプはない。`README.md` は起動のしかただけで、`docs/` は開発者向け（ADR・台帳・ロードマップ）。`F_HELP_CONTENTS` は GitHub の `docs/` フォルダ、`F_HELP_SEARCH` は ADR の一覧をブラウザで開いて代用している（`crates/matsu-ui/src/support/help.rs`）。ダイアログのヘルプボタンは、共通設定では無効、ほかのダイアログにはない（台帳の型 D）
- サクラの既定では、F1（無印）は本体のヘルプではなく「外部 HTML ヘルプ」で、未設定なら確認が出る。本体のヘルプは Alt+F1（`key_bindings.rs:65`）。MATSU も同じ

## 案と推奨

### 1. 置き場所

- A: このリポジトリの `docs/help/`（`docs/` の下）
- B: このリポジトリの最上位の `help/`（`ci.yml` の `changes` の正規表現に `^help/` を足す）
- C: 別のリポジトリ

推奨は A。理由: ヘルプはコードと同じ PR で直せる（コマンドを変えた PR がヘルプも直せる）。`docs/` の下は、CI の「文書だけの変更」の扱いにそのまま当たり、軽く通る。別のリポジトリは、コードとの同期が崩れる。B は、最上位の見た目はよいが `ci.yml` の変更が 1 つ増える。見送り: C。

### 2. 道具

- A: mdBook ＋ Pagefind（日本語の検索）
- B: Hugo ＋ Pagefind
- C: MkDocs Material、Docusaurus、Zola、Jekyll

推奨は A。理由: mdBook は単一の実行ファイルで、ビルドが速く、1 ページ版（`print.html`）とアプリに同梱するときの `file://` でも動く作りで、Rust の仲間の道具。日本語の検索は mdBook の組み込みが効かないので（実測）、Pagefind で補う。Pagefind は生成の道具に依らないので、あとで Hugo などに替えても検索は残せる。見送り: Zola（日本語の検索がビルドで失敗する。EUPL）、Docusaurus（重い）、MkDocs Material（保守のみ）、Jekyll（検索がない。Ruby）。道具の版は固定する。mdBook と Pagefind は、公開の実行ファイルのダウンロード＋チェックサムで入れる（`cargo install` は CI で遅い）。これは CI の新しい道具なので「判断してほしいこと」に載せる。

### 3. 言語

推奨: 日本語だけで始める。理由: サクラのヘルプが日本語で、CLAUDE.md が文書を日本語と決めている。英語は、日本語が出来てから別の ADR で決める。フォルダは `docs/help/ja/` のように言語で分けておき、あとで `en/` を足せるようにする。

### 4. サクラの文の扱いとライセンス

- A: サクラのページを GFDL の注記つきで写し、MATSU に合わせて直す。写したページは `docs/help/ja/sakura/` のように別に置き、ページごとに印を付ける。MATSU が書いたページは MIT OR Apache-2.0（または CC BY）にする
- B: サクラの文を見ずに、MATSU の動きから全部書く。サクラのヘルプへは「ページ番号の引用」だけで触れる（コードのコメントが今もそうしている）
- C: 写さず、サクラのオンラインのヘルプへリンクする

推奨は **B**（写さない）。MATSU のヘルプは、すべて MATSU の言葉で書き、コードと同じ MIT OR Apache-2.0 にする。

- サクラのヘルプは、動きを知るために読んでよい。文は写さない（言い換えて写すことも、写すのと同じに扱う）。根拠として、ページの名前（`HLP000081.html` など）を挙げる。コードのコメントが今そうしているのと同じ
- 書くもとは、MATSU のコードと試験、サクラのソース（zlib License）、サクラを動かした結果
- サクラの利用者が引けるように、項目の名前（メニューの名前、関数の名前）はサクラと同じにする。名前は文ではない

理由:
- 写すと、写したページは GFDL のままになる。MATSU が書いたページと 1 つのヘルプとしてまとめたとき、どこまでが GFDL の「改変版」になるかが、はっきりしない（GFDL の集め方の条件は、弁護士に確かめていない）。リポジトリのライセンスを 1 つに保てば、この心配がない
- MATSU は、サクラと動きが違うところ（MATSU だけの機能、直した不具合、OS の違い）が多い。写しても、直す手間がかかる
- 書くのは担当（エージェント）で、写すのと書くのとで、手間の差は小さい

代わりの案:
- A（GFDL で写す）を選ぶなら、写したページは `docs/help/ja/sakura/` に分けて印を付け、次を付ける（CLAUDE.md のコードの移植の決まりに合わせた）
  1. 各ページの先頭に、移植元（`sakura/help/sakura/res/HLP000081.html`、取った日付とコミット）、元の著作権表示（`Copyright (c) 2001-2020 Project SAKURA Editor.`）、`GFDL-1.1-or-later`、改変したこと
  2. ページの下に「このページは、サクラエディタのヘルプを元にしています（GFDL 1.1 以降）」
  3. 「このヘルプについて」のページに、GFDL の全文、履歴の節（元の題名「サクラエディタ ヘルプ」と、MATSU のヘルプが別の題名であること）、元の著作権者
  4. 写したページのソース（Markdown）が「透明な写し」になる。リポジトリとサイトにそれがあることを書く
- マクロの関数（329 ページ）は、どちらの案でも写さない。元の S_MACPPA.KHP の権利が分からないため。コードの表（名前・引数・戻り値）から書く

### 5. F1 とヘルプのコマンドが開くもの

- A: オンラインのサイトだけ
- B: 配布物に入れた写し（ローカル）だけ
- C: ローカルを先に、なければオンライン（設定で切り替える）

推奨は C（型 B・C）。理由: ローカルの写しは、版が合っていて、オフラインでも読める（サクラの `sakura.chm` を実行ファイルの隣に置くのと同じ）。オンラインは、開発中の版でも使え、検索（Pagefind）がそのまま動く。配布物に入れないときや壊れているときは、オンラインを開く。決めること:
- `F_HELP_CONTENTS`（Alt+F1）: 目次を開く。`F_HELP_SEARCH`（Alt+Shift+F1）: 検索のページを開く
- `F_EXTHTMLHELP`（F1 無印）と `F_EXTHELP1`（Ctrl+F1）: サクラのとおり、利用者が設定した外部ヘルプを開く。**変えない**（サクラの設定の互換。ADR-0010）。ただし、未設定のときは「今すぐ設定しますか?」の代わりに MATSU のヘルプを開く案もある。この変更は「判断してほしいこと」
- ダイアログのヘルプボタンと、メニューで項目を選んで F1: サクラの `Funccode.cpp` の表（機能コード → ページ）に倣って、機能コード → ヘルプのページの表を 1 か所（`help.rs`）に置く。ページの見出しの ID が変わると壊れるので、検査で切れを見る
- ローカルの検索: Pagefind は `file://` で動くか未確認。動かないときは、ローカルの写しは検索なし（1 ページ版を Ctrl+F）にし、検索はオンラインへ誘導する。アプリが小さなサーバーを立てる案は、新しい作りでセキュリティの判断が要るので、今回は見送る
- 開く道は今ある `cx.open_url` と `cx.open_with_system`。`#アンカー` が `open_with_system` で渡るかは未確認で、実装の PR で OS ごとに確かめる（渡らなければ `file://...#id` の URL で開く）

### 6. 検索

推奨: Pagefind（実測で日本語の語、語の途中でも引けた。順位の質と `file://` は未確認）。mdBook の組み込みの検索は切る（`[output.html.search] enable = false`。日本語が引けず、結果が空のまま残るのは紛らわしい）。代わりの案: 組み込みの検索を残す。見送り理由は、日本語が 1 語も引けないから。

### 7. 版の管理

- A: 最新版（main）だけを GitHub Pages に出す。版ごとの内容は、配布物の中の写しが持つ
- B: 版ごとのフォルダ（`/v0.13/` など）を Pages に出す

推奨は A。理由: 利用者が少ない時期に、版を切り替える仕組み（フォルダの管理、切り替えの表示）は手間に見合わない。ローカルの写しが版と合うので、古い版の人はそれを読める。未リリースの機能は、ページに「0.14 以降」のように書く。利用者が増えたら B を別に決める。

### 8. サンプルとその確かめ方

推奨:
1. サンプルのファイルは、今の `crates/matsu-plugin/samples/` を唯一の置き場にする。ヘルプのページは mdBook の `{{#include}}` で引く（コピーを置かない）。コードを直した PR が、サンプルのテストで落ちる
2. 新しいサンプル（キーマクロ、Lua、言語ごとのレシピ、VBScript から書き換える手引きの例）も `samples/` に足し、`the_sample_macros_run` の表に 1 行ずつ足す。ヘルプに書く出力は、テストの期待値と同じ文字列にする
3. サクラとの比較（oracle）の `.mac` を、キーマクロの例として使う（サクラでも同じ結果、と書ける）
4. ヘルプの検査（`crates/matsu/tests/help_check.rs`、`leftover_names.rs` と同じ形）: ヘルプに書いたコマンド名と関数名がコードの表にある、ページのリンクとアンカーが切れていない、コードが引くヘルプの URL の一覧が実在のページにある
5. 新しい CI のジョブ `help`（Linux）: mdBook のビルド → Pagefind → 検査。処理系の要る確認は今のテストに任せる（Linux x64 では必須）

### 9. 誰がどう直し、どうレビューするか

推奨:
- ヘルプのソースは Markdown で、コードと同じ PR で直す。ユーザーの見える動きを変える PR は、該当するヘルプのページも直す（PR の「判断したこと」に書く）。担当（エージェント）が書く
- 案 4 の A（写す）を選んだときだけ: 写したページ（GFDL）は、ページの先頭の注記を消さない。注記の検査（先頭にライセンスの行がある）を `help_check` に足す
- レビューは、ADR-0014 / CLAUDE.md の push 前のレビュー（Stage 0〜4）に従う。ヘルプだけの変更（`.md`）は、CLAUDE.md の「適用しないケース」に当たり、AI レビューを飛ばしてよい。ただしヘルプの内容がコードの動きと合うかは、人が見るか、サクラや MATSU で確かめる必要がある（文書だけの変更でも、動きの主張にはソースかサクラの確認を添える。CLAUDE.md「判断の方針」）
- 「サクラの挙動についての主張には、ソースの場所か確かめた結果を添える」を、ヘルプにも適用する（ページの末尾の「根拠」に書く）

## 決めたこと

2026-11-13 に、ユーザーが決めた。

1. **置き場所**: このリポジトリの `docs/help/`（案 1 の A）。ユーザーは別のリポジトリも考えたが、その理由は「言葉を直すだけで GFDL を避けられるか」の懸念で、避けられるなら同じリポジトリでよい、とした。避け方は下の「サクラのヘルプの文を写さない書き方」
2. **サクラのヘルプの文**: 写さない（案 4 の B）。MATSU の言葉で、動き（事実）から書く
3. **ライセンス**: MATSU のヘルプは MIT OR Apache-2.0
4. **道具**: mdBook と Pagefind を CI に入れる
5. **公開**: GitHub Pages で出す。リポジトリの設定（Pages の Source を GitHub Actions に）は、ユーザーが切り替える
6. **同梱**: 配布物にヘルプを入れる
7. **F1**: サクラどおり（外部 HTML ヘルプ）。MATSU のヘルプは Alt+F1
8. **ローカルの検索**: アプリに検索のためのサーバーを持たない
9. **英語**: 日本語のあとに、別の ADR で決める
10. **マクロの関数**: グループごとの表にまとめる

### サクラのヘルプの文を写さない書き方

- 著作権が守るのは表現で、機能や動き（事実）ではない。最高裁の判例（江差追分事件、2001-06-28）は、既存の著作物に依拠し、その表現上の本質的な特徴を直接感じ取れるものを「翻案」とし、事実やアイデアが同じだけのものは翻案に当たらないとした。サクラの文を見ながら言い換えると、組み立てや例が残り、翻案になりうる。だから、言い換えでは足りない
- 書く担当は、サクラのヘルプの本文を見ながら書かない。動きの根拠は、サクラのソース（zlib License）、MATSU のコードと試験、サクラを動かした結果から取り、ページの「根拠」に書く
- メニューの名前、関数の名前、設定の項目の名前は、サクラと同じでよい（名前は表現として守られない）
- 例文、説明の順序、言い回しを、サクラのヘルプに合わせない
- CI の検査で、MATSU のヘルプとサクラのヘルプの間に、長く一致する文字列がないことを毎回確かめる（長さの基準と、名前を除く方法は、土台の PR で決める）
- 弁護士には確かめていない（調整役の理解）

## PR の順番

ページの量は、すべてを写した場合で約 800（マクロの関数をグループの表にまとめると約 500）。次の順で、独立に書ける PR に分ける（1 PR は 1 つのメニューか領域）。

0. 土台: `docs/help/` の骨組み、`book.toml`、テーマ、`SUMMARY.md`、Pagefind、検査（`help_check.rs`）、`help` ジョブ、「このヘルプについて」（ライセンス）、注記の型。これだけ先に入れる
1. 概要・インストール・起動・`matsu.ini`・サクラとの違い
2. 基本的な使い方（選択、矩形編集、タブバー、入力補完ほか）
3. コマンド: ファイル
4. コマンド: 編集
5. コマンド: 変換
6. コマンド: 検索
7. コマンド: ツール
8. コマンド: 設定（共通設定）
9. コマンド: 設定（タイプ別設定）とウィンドウ
10. コマンド: ヘルプとメニューに入ってないコマンド
11. 仕様等と正規表現
12. マクロの使い方、キーマクロ、サンプル、VBScript から書き換える手引き
13〜16. マクロの関数（4 つのグループ。名前・引数・戻り値をコードの表から作る）
17. プラグイン（ADR-0026）とスクリプトの言語
18. MATSU だけの機能（シェル、プレビュー、巨大ファイル、自動保存、データベース、エンコード・デコード）
19. アプリの配線: ヘルプのコマンド、ダイアログのヘルプボタン、機能コード → ページの表、パッケージに `help/` を同梱
20. 公開: Pages のワークフロー（持ち主が Pages の設定を変えたあと）

- 0 の後、1〜18 は互いに独立で、並列に書ける
- 19 は、少なくとも 3 と 8 が入ってから（ページの URL が決まってから）
- 20 は、ユーザーの判断（Pages を使うこと）のあと。それまでは、ローカルの写しとオンライン（GitHub の `docs/`）で動く

## 判断してほしいこと

1. **サクラのヘルプの文を写すか**（ライセンス）。サクラのヘルプの文は GFDL 1.1 以降で、写すと、そのページは GFDL のままになる。CLAUDE.md は GPL・LGPL・AGPL を使わないと決めているが、GFDL には触れていない。推奨: **写さない**（案 4 の B）。すべて MATSU の言葉で書き、ライセンスは MIT OR Apache-2.0 の 1 つに保つ。写すなら、コマンドとダイアログの説明を GFDL のまま `docs/help/ja/sakura/` に分けて置く（案 4 の A）
2. **MATSU が書いたヘルプのライセンス**（ライセンス）。推奨: コードと同じ MIT OR Apache-2.0。代わりの案は CC BY 4.0 など文書用のもの。コードのサンプルは MIT OR Apache-2.0 のままがよい（利用者が写して使うため）。
3. **新しい道具を CI に入れること**（CI の新しい道具）。mdBook と Pagefind（公開の実行ファイルのダウンロード＋チェックサム。どちらも道具であり、依存には入らず、`deny.toml` に関係しない）。mdBook は MPL-2.0、Pagefind は MIT。推奨: 入れる。ジョブは Linux だけ、数分（型 E に収まる）。必須のチェックにするかは持ち主が決める。
4. **GitHub Pages を有効にすること**（公開。リポジトリの設定を持ち主が変える）。Settings > Pages > Source を GitHub Actions にし、Environments > github-pages の「Deployment branches」を `main` だけにする。URL は `https://stofu5678.github.io/matsu_editor/`（見込み）。推奨: 有効にする。ヘルプのコードとローカルの写しは、これが決まる前に作れる。
5. **F1 無印と Ctrl+F1 の動き**（ユーザーが前に決めたこと、サクラの互換の変更）。サクラどおりなら、外部ヘルプが未設定のとき「今すぐ設定しますか?」と出す。推奨: **サクラどおりに残す**（Alt+F1 が MATSU のヘルプ）。代わりの案: 未設定なら MATSU のヘルプを開く。初めての利用者は F1 でヘルプを期待するので、迷う案。ユーザーが決める。
6. **ヘルプの置き場**（`docs/help/` か最上位の `help/` か）。推奨: `docs/help/`（`ci.yml` を変えずに済む）。
7. **ヘルプを配布物に同梱すること**（リリースの判断）。`package.yml` のアーカイブに `help/` を足す（Windows・macOS・Linux の 5 つ）。大きさの見込みは 10〜30 MB（推測）。推奨: 同梱する。大きさを測って、大きすぎれば別のアーカイブ（`matsu-help-<版>.zip`）にする。
8. **ローカルのヘルプの検索**（新しい作りとセキュリティ）。`file://` で Pagefind が動くか未確認。動かないとき、アプリが `127.0.0.1` の小さなサーバーを持つ案がある。推奨: **持たない**。ローカルは検索なし（1 ページ版を Ctrl+F）で、検索はオンラインへ誘導する。
9. **英語のヘルプ**（言語）。推奨: 今回は作らない。日本語が出来てから別の ADR で決める。
10. **マクロの関数の書き方**（量）。サクラは 1 関数 1 ページ（329）。推奨: グループごとの表（30 ページほど）にまとめる。サクラの利用者が引ける（検索で足りる）ことを、実装後に確かめる。

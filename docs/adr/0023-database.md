# ADR-0023: データベースの操作（Oracle だけにしない）

- 状態: 提案中（範囲の決定はユーザーのもの。下の「決めてほしいこと」）
- 日付: 2026-10-24（ユーザーが「DB 操作機能が Oracle だけでいいのか。MySQL、PostgreSQL、SQL Server、SQLite があり、GCP の BigQuery のようなクラウドの DB もある」と指摘して、下書きを頼んだ）

## 背景

サクラのデータベースの機能は、Oracle のものが 2 つだけである。

- 「SQL*Plusで実行」（`F_PLSQL_COMPILE_ON_SQLPLUS`、F10、マクロ `ExecSQLPLUS`）
- 「SQL*Plusをアクティブ表示」（`F_ACTIVATE_SQLPLUS`、Shift+F11、マクロ `ActivateSQLPLUS`）

MATSU には、どちらもまだない。キーを押すと「… はまだ使えない」と出る。

調べた結果（くわしくは [docs/poc/database.md](../poc/database.md)）:

- サクラは SQL*Plus を動かさない。起動中の Windows の GUI 版 SQL*Plus（`sqlplusw.exe`）のウィンドウを探し、`@ファイル名` をクリップボード経由で貼り付けさせる。`FindWindow` と `SendMessage` に頼るので、Windows でしか成り立たない
- Oracle は 11g から、GUI 版 SQL*Plus を同梱しなくなったとされる（公式の告知ではなく、利用者の報告による）。サクラのままでは、今の配布物だけでは動かない（古い GUI 版を別に手に入れた場合は確かめていない）
- 今のデータベースには、それぞれコマンドラインのクライアント（`sqlplus`・SQLcl、`mysql`、`psql`、`sqlcmd`、`sqlite3`、`bq`）があり、ファイルを渡して実行でき、認証も各クライアントが持っている

つまり、サクラの 2 つの機能は、そのまま写しても、今の配布物だけでは使えず、macOS と Linux では成り立たない。「いま編集中の SQL を、データベースに実行させる」という意図を、今の形で実現するのが問題になる。

## 案

詳細は [docs/poc/database.md](../poc/database.md) の 3。

- A: サクラの 2 つの機能を一般化する。接続の設定（プロファイル）ごとに、クライアントを呼ぶコマンドの雛形を持ち、いまのファイル（または選択範囲）を実行して、結果を出力パネルに出す。エラーの行から SQL の行へ移れる。依存を足さず、パスワードはクライアントに任せる。結果は文字の出力で、表ではない
- B: 内蔵のクライアントを作る。接続、クエリ、結果の表（非エディタのタブが要る。ADR-0024 として別に下書き中で、まだ決まっていない）、OS のキーチェーン、キャンセル、巨大な結果の分割読み。依存と保守が重い。サクラにない機能
- C: マクロとプラグイン（ADR-0007）で、利用者とサンプルが各言語のドライバーから使う。MATSU は出力パネルへの書き出しを用意する。費用はほぼないが、利用者の手間が大きい

## 推奨

A を先にやり、C をサンプルのマクロとして並べる。B は、A を使ってから、表の結果が欲しいとユーザーが決めたときに別の ADR で扱う。

理由:

- MATSU の目標はサクラの再現で、サクラが持つのは「ファイルをクライアントに実行させる」機能である。A はその意図を、今のクライアントで満たす
- 依存を足さない。Rust のドライバーは MIT / Apache-2.0 が多いが、Oracle のクレートは UPL-1.0/Apache-2.0 で、Oracle のクライアントライブラリが実行時に要る。TLS・非同期・資格情報の保管を MATSU が抱えるのは重い
- パスワードを MATSU が預からない。クライアントの仕組み（`~/.pgpass`、`mysql_config_editor`、Wallet、`gcloud auth`、Windows 統合認証）に任せる

A の動き（案）:

- F10（`ExecSQLPLUS`）は、既定の接続でいまのファイルを実行する。サクラと同じく、変更があれば保存を確かめ、ファイル名がなければ使えない（`CViewCommander_File.cpp`）。コマンドの ID はサクラのまま
- 接続を名前で選ぶ実行のコマンドも足す（名前は実装のときに決める）
- 「アクティブ表示」には、前面に出す相手のウィンドウがない。いちばん近い形（ADR-0018 の型 B）として、出力パネルを表示する

## 接続の設定

- `matsu.ini` はサクラの `sakura.ini` と同じ形式なので、サクラにない項目は別のファイルに置くことを ADR-0010 が認めているので、隣に別のファイル `databases.ini` を置く（案）。接続ごとに、種類、雛形（`psql -h … -d … -f $F` など）、文字コード、作業フォルダーを書く
- MATSU は、パスワードを平文で書かない。雛形に直接書くことも画面で止め、プロセス一覧やコマンド履歴に残さない
- ファイルの形式と置き場所は、利用者のデータなので、ユーザーが決める

## 色分け

サクラのタイプは `PL/SQL` の 1 つだけ。MySQL・PostgreSQL・SQL Server・SQLite・BigQuery は、コメント・文字列・キーワードが少しずつ違う（[docs/poc/database.md](../poc/database.md) の 5）。ADR-0017 の前例に従って足す。サクラの PL/SQL のタイプは変えない。

## 決めてほしいこと

1. 範囲: A だけ、A + C（推奨）、B まで。B は別の ADR にするか
2. 対応するデータベース: Oracle（`sqlplus`・SQLcl）、MySQL/MariaDB、PostgreSQL、SQL Server、SQLite、BigQuery の雛形を、初めから例として持つか（推奨）。DuckDB や Snowflake は足すか。実機で確かめていない雛形は、確かめたと書かない
3. 外部のクライアントの実行: ADR-0018 のセキュリティの項に当たる。利用者が自分で書いた雛形を動かすだけ（外部コマンド実行と同じ）でよいか
4. GPL のクライアント（`mysql`）は、同梱せず、外部のプログラムとして呼ぶだけとする解釈でよいか（CLAUDE.md のライセンスのルールは依存とコードの写しについてなので、確認する）
5. 接続の設定: `databases.ini` を別に置く案でよいか。形式と置き場所
6. F10 の動き: 既定の接続が未設定のときは、設定を促すメッセージにする案でよいか。Oracle の雛形を既定にするか
7. 色分け: 方言ごとのタイプを 5 つ足すか、「SQL」の 1 つにまとめるか。いつやるか
8. 「アクティブ表示」: 出力パネルを表示する形でよいか（型 B）

## 計画（推奨の A + C の場合の PR の順）

1. `databases.ini` の読み書き（`matsu-config`）。形式の決定が要る
2. 雛形の展開と実行（`F_PLSQL_COMPILE_ON_SQLPLUS`、`F_ACTIVATE_SQLPLUS`）。保存の確認、ファイル名がないときの扱い、出力パネルへの出力
3. 出力のエラー行から SQL の行へ移る（クライアントごとの正規表現。実機で確かめる）
4. SQL の方言のタイプ（色分け）
5. サンプルのマクロ（Python などから各ドライバーで実行し、出力パネルに書く）
6. `/security-review`（雛形の展開、履歴に残るもの）

## 見送った案

- サクラの動きをそのまま写す案: `sqlplusw.exe` が Oracle の今の配布物になく、Windows でしか動かない
- 最初から内蔵のクライアントを作る案（B）: 依存・資格情報・TLS・結果の表（非エディタのタブが前提で、まだ決まっていない）の費用が大きい。サクラにない機能で、A で足りるかを見てからでよい

## 影響

- 決定後に、ADR-0010 の設定ファイルの項に `databases.ini` を足す
- 案 A の実装は、外部コマンド実行（`crates/matsu-ui/src/exec/`）を使う

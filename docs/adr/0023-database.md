# ADR-0023: データベースの操作（Oracle だけにしない）

- 状態: 決定（2026-10-24 にユーザーが、下の「決めたこと」の 8 項目すべてを推奨どおりに決めた）
- 日付: 2026-10-24（ユーザーが「DB 操作機能が Oracle だけでいいのか。MySQL、PostgreSQL、SQL Server、SQLite があり、GCP の BigQuery のようなクラウドの DB もある」と指摘して、下書きを頼んだ）

## 背景

サクラのデータベースの機能は、Oracle のものが 2 つだけである。

- 「SQL*Plusで実行」（`F_PLSQL_COMPILE_ON_SQLPLUS`、F10、マクロ `ExecSQLPLUS`）
- 「SQL*Plusをアクティブ表示」（`F_ACTIVATE_SQLPLUS`、Shift+F11、マクロ `ActivateSQLPLUS`）

MATSU には、どちらもまだない。キーを押すと「… はまだ使えない」と出る。

調べた結果（くわしくは [docs/poc/database.md](../poc/database.md)）:

- サクラは SQL*Plus を動かさない。起動中の Windows の GUI 版 SQL*Plus（`sqlplusw.exe`）のウィンドウを探し、`@ファイル名` をクリップボード経由で貼り付けさせる。`FindWindow` と `SendMessage` に頼るので、Windows でしか成り立たない
- Oracle は 11g から、GUI 版 SQL*Plus を同梱しなくなったとされる（公式の告知ではなく、利用者の報告による）。サクラのままでは、今の配布物だけでは動かない（古い GUI 版を別に手に入れた場合は確かめていない）
- 今のデータベースには、それぞれコマンドラインのクライアント（`sqlplus`・SQLcl、`mysql`、`psql`、`sqlcmd`、`sqlite3`、`bq`）があり、ファイルを渡して実行でき、認証も各クライアントが持っている

つまり、サクラの 2 つの機能は、そのまま写しても、今の配布物だけでは使えず、macOS と Linux では成り立たない。「いま編集中の SQL を、データベースに実行させる」という意図を、今の形で実現するのが問題になる。

## 案

詳細は [docs/poc/database.md](../poc/database.md) の 3。

- A: サクラの 2 つの機能を一般化する。接続の設定（プロファイル）ごとに、クライアントを呼ぶコマンドの雛形を持ち、いまのファイル（または選択範囲）を実行して、結果を出力パネルに出す。エラーの行から SQL の行へ移れる。依存を足さず、パスワードはクライアントに任せる。結果は文字の出力で、表ではない
- B: 内蔵のクライアントを作る。接続、クエリ、結果の表（非エディタのタブが要る。ADR-0024 として別に下書き中で、まだ決まっていない）、OS のキーチェーン、キャンセル、巨大な結果の分割読み。依存と保守が重い。サクラにない機能
- C: マクロとプラグイン（ADR-0007）で、利用者とサンプルが各言語のドライバーから使う。MATSU は出力パネルへの書き出しを用意する。費用はほぼないが、利用者の手間が大きい

## 推奨

A を先にやり、C をサンプルのマクロとして並べる。B は、A を使ってから、表の結果が欲しいとユーザーが決めたときに別の ADR で扱う。

理由:

- MATSU の目標はサクラの再現で、サクラが持つのは「ファイルをクライアントに実行させる」機能である。A はその意図を、今のクライアントで満たす
- 依存を足さない。Rust のドライバーは MIT / Apache-2.0 が多いが、Oracle のクレートは UPL-1.0/Apache-2.0 で、Oracle のクライアントライブラリが実行時に要る。TLS・非同期・資格情報の保管を MATSU が抱えるのは重い
- パスワードを MATSU が預からない。クライアントの仕組み（`~/.pgpass`、`mysql_config_editor`、Wallet、`gcloud auth`、Windows 統合認証）に任せる

A の動き（案）:

- F10（`ExecSQLPLUS`）は、既定の接続でいまのファイルを実行する。サクラと同じく、変更があれば保存を確かめ、ファイル名がなければ使えない（`CViewCommander_File.cpp`）。コマンドの ID はサクラのまま
- 接続を名前で選ぶ実行のコマンドも足す（名前は実装のときに決める）
- 「アクティブ表示」には、前面に出す相手のウィンドウがない。いちばん近い形（ADR-0018 の型 B）として、出力パネルを表示する

## 接続の設定

- `matsu.ini` はサクラの `sakura.ini` と同じ形式なので、サクラにない項目は別のファイルに置くことを ADR-0010 が認めているので、隣に別のファイル `databases.ini` を置く（案）。接続ごとに、種類、雛形（`psql -h … -d … -f $F` など）、文字コード、作業フォルダーを書く
- MATSU は、パスワードを平文で書かない。雛形に直接書くことも画面で止め、プロセス一覧やコマンド履歴に残さない
- ファイルの形式と置き場所は、利用者のデータなので、ユーザーが決める

## 色分け

サクラのタイプは `PL/SQL` の 1 つだけ。MySQL・PostgreSQL・SQL Server・SQLite・BigQuery は、コメント・文字列・キーワードが少しずつ違う（[docs/poc/database.md](../poc/database.md) の 5）。ADR-0017 の前例に従って足す。サクラの PL/SQL のタイプは変えない。

## 決めたこと

2026-10-24 にユーザーが、8 項目すべてを推奨どおりに決めた。

1. 範囲: A + C。B（内蔵のクライアント）は、ユーザーが望んだときに別の ADR で扱う
2. 対応するデータベース: Oracle（`sqlplus`・SQLcl）、MySQL/MariaDB、PostgreSQL、SQL Server、SQLite、BigQuery の雛形を、初めから例として持つ。実機で確かめていない雛形は、確かめたと書かない。DuckDB や Snowflake は今は足さない
3. 外部のクライアントの実行: 利用者が自分で書いた雛形を、外部コマンド実行と同じに動かす
4. GPL のクライアント（`mysql`）: 外部のプログラムとして呼ぶだけで、同梱しない
5. 接続の設定: 別のファイル `databases.ini` に置く（ADR-0010 が、サクラにない項目を別のファイルに置くことを認めている）。パスワードは書かない
6. F10 の動き: 既定の接続が未設定のときは、設定へ導くメッセージを出す
7. 色分け: 推奨どおり（方言のタイプを足す。ADR-0017 の前例に従う。実装は後の PR）
8. 「アクティブ表示」: 出力パネルを表示する（型 B）

## 計画（推奨の A + C の場合の PR の順）

1. `databases.ini` の読み書き（`matsu-config`）。形式の決定が要る
2. 雛形の展開と実行（`F_PLSQL_COMPILE_ON_SQLPLUS`、`F_ACTIVATE_SQLPLUS`）。保存の確認、ファイル名がないときの扱い、出力パネルへの出力
3. 出力のエラー行から SQL の行へ移る（クライアントごとの正規表現。実機で確かめる）
4. SQL の方言のタイプ（色分け）
5. サンプルのマクロ（Python などから各ドライバーで実行し、出力パネルに書く）
6. `/security-review`（雛形の展開、履歴に残るもの）

## 見送った案

- サクラの動きをそのまま写す案: `sqlplusw.exe` が Oracle の今の配布物になく、Windows でしか動かない
- 最初から内蔵のクライアントを作る案（B）: 依存・資格情報・TLS・結果の表（非エディタのタブが前提で、まだ決まっていない）の費用が大きい。サクラにない機能で、A で足りるかを見てからでよい

## 影響

- ADR-0010 の設定ファイルの項に `databases.ini` を足す（後の PR で）
- 案 A の実装は、外部コマンド実行（`crates/matsu-ui/src/exec/`）を使う

## 追記（2026-10-24）: 色分けのタイプ（ユーザーが決めた）

ユーザーは「サクラエディタの仕様には縛られずできる限り拡張はしたい」と決めた（2026-10-24）。決めたこと 7 の色分けは、サクラの上限（型の数 30、`.sql` は PL/SQL）に縛られずに、方言ごとに行う。

- 汎用の「SQL」と、方言の MySQL（MariaDB）・PostgreSQL・SQL Server（T-SQL）・SQLite・BigQuery の 6 つのタイプを足した（ADR-0017 の MATSU 独自のタイプ。`settings/extra_types.rs`）。方言のタイプは、共通の「SQL」の強調キーワードと、その方言の語の 2 つを使う
- 型の数の既定を 30 から 36 に上げた（サクラの 17、独自の 16、空き 3）。`nTypesCount` のないファイルと、サクラの既定の 30 を書いたファイルは 36 として読み、30 より後の番号は空きとして使う。ほかの数は、ファイルの選んだとおりに読む（最大 60）。MATSU は `nTypesCount` を書かないので、古いファイルはそのまま読める
- `.sql` は汎用の「SQL」になった。サクラの「PL/SQL」は `plsql,pls,plb,pck,pkb,pks` を持つ。サクラの PL/SQL が持っていた拡張子は `sql` と `plsql` の 2 つだけで、Oracle のパッケージなどの拡張子は MATSU が足した。「SQL」のタイプのアウトラインは PL/SQL のもの（`.sql` が前から持っていたもの）
- ファイルの `Types(4)` が `sql` を持っている（サクラが書いたファイルなど）なら、そのファイルが優先で、`.sql` は PL/SQL のまま（ADR-0017 のとおり）
- 方言は `.sql` の拡張子では見分けられないので、方言のタイプは、利用者がタイプの一覧から選ぶか、専用の拡張子（`mysql` `pgsql` `psql` `tsql` `sqlite3` `bqsql`）で選ばれる

## 追記（2026-10-25）: セキュリティレビュー（計画の 6）の結果

データベースの機能を、自分で読み、Codex に 4 回、セキュリティの観点で見てもらった。見つかったものを直し、テストを足した。決まりになったこと:

- 雛形の `$F`:
  - 区切りの外に書いたとき（`-f $F`）は、名前を OS のシェルの 1 語として引用する（`sh` は単一引用符、`cmd.exe` は二重引用符。`cmd.exe` は `"` `%` `!` と制御文字の入った名前を断る）。
  - 雛形の引用符の中や、引用符に接するところに書いたとき（`-f '$F'`、`psql -c '\i $F'`）は、クライアントや別のシェルがその引数を自分で読むので、安全な書き方が決まらない。名前が英数字と `. _ - / + , : = @ ~`（`cmd.exe` は `\` も）だけのときだけ、そのまま入れる。
  - 名前が自由に書けるのは、雛形が「知っているクライアント（`psql` `mysql` `sqlcmd` `sqlplus` `sqlite3` `bq` など）1 つと引数」のときだけ。別のプログラム（シェルの `-c`、`eval`、PowerShell、利用者のスクリプト）や、`;` `&` `|` `<` `>` `$(` バッククォートの入った雛形は、名前を二度読むおそれがあるので、同じ「安全な文字だけ」にする。
  - `$` は外部コマンド実行の展開（`ExpandParameter`）に渡す前に `$$` にする。1024 文字を超える行は、切らずに断る。
- パスワード: `-p…`、`-P`、`--password=`、`password=` / `pwd=`、`PGPASSWORD=` など、URI の `user:pass@` と `?password=`、`%XX` で隠したもの、シェルの `\` で隠したもの、MySQL の短いオプションの並び（`-vpsecret`）、`Kind=` に頼らずプログラム名（`env mysql …` の中も）で種類を決める。見つけたら実行しない。手がかりであって、すべては見つけられない。
- 出力パネルの行から開く場所（エラー行のジャンプ）: 出力には、データベースの中身など他人が書いたものが出る。`\\host\share` や `//host/…` などのネットワークの場所、`\\?\` `\\.\`、Windows のデバイス名（`CON` `NUL` `COM1` など）は場所にしない。クリックしたときに通常のファイルでなければ開かない。Windows では、道の途中にリンクがあっても開かない（リンクの先がネットワークのときに、確かめるだけで接続するため）。
- ファイル: `databases.ini` の例は、私的な権限（0600）で、リンクをたどらずに（`create_new`）作る。設定ファイルの一時ファイルは、前から同じ作り方。データベースの機能は、ほかに一時ファイルを作らない（SQL は標準入力で渡す）。
- 履歴: 接続のコマンドは、外部コマンド実行の履歴（`matsu.ini` の `[Cmd]`）に入らない。
- 残る危険（直さないもの）: エラー行のジャンプで、確かめてから開くまでの間にディレクトリをリンクに入れ替える競合（同じユーザーのファイルシステムを書き換えられる者が要る）。`databases.ini` を書き換えられる者は、マクロと同じにコマンドを動かせる。

## 追記（2026-10-31）: 文言と、接続を選んで実行するコマンド（ユーザーが決めた）

2026-10-31 にユーザーが、「DB の実行機能がまだ SQL*Plus のままで、データベースと抽象化されていない」と指摘し、下を決めた（実装は #297）。上の本文は、サクラの元の名前と当時の案の記録として残す。

- 表示する名前（ADR-0018 の型 F）を、データベースの機能として分かる言葉にした。関数名、コード、マクロ名（`F_PLSQL_COMPILE_ON_SQLPLUS` 30171 `ExecSQLPLUS`、`F_ACTIVATE_SQLPLUS` 30170 `ActivateSQLPLUS`）は、キー割り当てとマクロの互換のために変えない。
  - 「SQL*Plusで実行」は「データベースで実行」（F10）
  - 「SQL*Plusをアクティブ表示」は「データベースの出力を表示」（Shift+F11）
- 「動き（案）」の「接続を名前で選ぶ実行のコマンドも足す（名前は実装のときに決める）」の名前を決めた。MATSU だけの関数 `F_PLSQL_COMPILE_ON_DATABASE_CHOICE`（コード 32703、マクロ `ExecDatabaseChoice`、キー割り当てなし）で、メニューの文言は「接続を選んでデータベースで実行...」。ツールメニューの「データベースで実行」の後ろに置く。
  - `databases.ini` の使える接続を一覧（名前・種類・コマンド）で見せ、選んだ 1 つで F10 と同じ流れ（保存の確認、パスワードの検査、出力パネル、エラー行の移動）で実行する。接続が 1 個でも一覧を出す。`databases.ini` は読むだけで、既定の接続は変えない。
  - 既定の接続がない F10 のメッセージで、このコマンドを案内する。

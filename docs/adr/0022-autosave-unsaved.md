# ADR-0022: 保存していない文書を自動で残し、次の起動で戻す

- 状態: 提案中（利用者のデータ（保存・削除・新しいファイル）と `matsu.ini` のキーに関わるので、ADR-0018 によりユーザーが決める）
- 日付: 2026-10-24（ユーザーが「無保存ファイルの自動保存機能を実装」と頼み、下書きを書いた）
- 土台にする決定: [0005](0005-text-buffer-and-large-files.md)（元のバイト列 + 編集）、[0010](0010-sakura-compatible-settings.md)（`matsu.ini`）、[0015](0015-tabs-and-groups.md)（タブとグループ）、[0016](0016-single-instance.md)（1 つのプロセス）、[0020](0020-huge-files.md)（巨大ファイル）

## 背景

今の MATSU Editor では、次のものは、MATSU か OS が突然止まると失われる。

- まだ一度も保存していない文書（無題）
- 名前のある文書の、保存していない変更

終了するときは、文書ごとに「保存しますか」と聞かれる（サクラと同じ。`crates/matsu-ui/src/file_ops/close.rs`、`CEditDoc::OnFileClose`）。

Windows 11 のメモ帳、VS Code（hot exit）、Sublime Text（`hot_exit`）などは、保存していない内容を残し、次の起動で戻す。

### 今のコードにあるもの（2026-10-24 の main で読んだ）

- サクラの「自動保存」（`CAutoSaveAgent`）は実装済み。一定の分ごとに、名前のある変更済みの文書を、本物のファイルに上書きする。無題は保存しない（`crates/matsu-ui/src/file_watch/auto_save.rs`）。設定は `file_ops/prefs.rs` の `auto_save` と `auto_save_interval`（既定はオフ、5 分）。
- サクラの保存時のバックアップ（`file_ops/backup`）。
- 保存は、同じフォルダーに一時ファイルを書いて rename で置き換える（`crates/matsu-core/src/file/save.rs`）。
- `matsu.ini` は、Windows は `<exe のフォルダー>\matsu.ini`（持ち運び用）か `%APPDATA%\matsu-editor\`、macOS は `~/Library/Application Support/matsu-editor/`、Linux は `$XDG_CONFIG_HOME/matsu-editor/`（なければ `~/.config/matsu-editor/`）にある（`crates/matsu-config/src/location.rs`）。履歴の保存（`crates/matsu-config/src/history`）も同じ場所を使う。`-PROF` を使うと、プロファイル名の下位フォルダーになる。
- 1 つの `matsu.ini` につき 1 つのプロセスが動く（ADR-0016）。別のプロセスとして動かす起動のオプションもある。
- ファイルのロックは `crates/matsu-platform/src/file_lock`（Windows は共有モード、macOS と Linux は `flock`）。
- 文書は、元のバイト列と編集（追加バッファ）のピースの並びで持つ（ADR-0005）。巨大ファイルは範囲ごとに読む元データで持つ（ADR-0020）。無題には番号がある（`SharedDocument::untitled_number`）。

この機能は、サクラの自動保存とも、保存時のバックアップとも別物である。本物のファイルには**一切書かない**。残したものは MATSU が自分のフォルダーに持ち、保存するか閉じるかで消える。サクラの 2 つの機能は、そのまま残す。

## 参考にした公開資料

コードは読んでいない。公開された説明だけを見た。

- VS Code のドキュメント「Basic editing — Hot Exit」（<https://code.visualstudio.com/docs/editing/codebasics>、2026-10-24 に確認）。`files.hotExit` の値は `off`、`onExit`、`onExitAndWindowClose`。既定は「終了のときに保存していない変更を覚える」で、アプリが予期せず終わったときのバックアップも同じ仕組みで取る。バックアップは `%APPDATA%\Code\Backups`、`~/Library/Application Support/Code/Backups`、`~/.config/Code/Backups` に置く。
- Sublime Text のドキュメント（<https://www.sublimetext.com/docs/settings.html>）は、設定名 `hot_exit` を挙げるだけで、動作の説明は見つからなかった。
- GPL のコード（Notepad++、Emacs、Zed のエディタのクレート）は読んでいない。

## 1. 何を残すか

| 案 | 内容 |
|---|---|
| A | 無題の文書だけ |
| B | 無題の文書と、名前のある文書の保存していない変更 |

推奨は B。名前のある文書の変更も、突然止まったときに失われる点は同じで、メモ帳も VS Code も両方を残す。実装も、文書の中身を書き出す処理はどちらも同じ。

残さないもの: 保存していない変更のない文書、Grep の結果のウィンドウ、出力ウィンドウ。読み取り専用（ビューモード）かどうかでは決めない。ビューモードは途中で切り替えられ、開いたあとに解除して編集した文書もあるため、「保存していない変更があるか」だけで決める。

「保存していない変更」には、本文の変更のほかに、文字コードまたは BOM だけの変更（`format_changed()`。閉じるときにサクラが別の文言で聞く）を含める。

名前のある文書の残した内容は、本物のファイルには書かない。

## 2. いつ書くか

| 案 | 内容 |
|---|---|
| A | 入力が止まってから数秒後（デバウンス） |
| B | 一定の間隔 |
| C | 終了と、ウィンドウを閉じるときだけ |

推奨は A + 保険。

- 最後の変更から 2 秒後に書く。入力し続けている間も、最後に書いてから 30 秒たったら書く。
- ウィンドウが前面でなくなったとき、閉じるとき、終了するときにも、変更があれば書く。
- 保存していない変更のない文書は書かない。本文は文書の版番号で、文字コードと BOM は `format_changed()` で判断する。キャレット、先頭行、ブックマーク、タブとウィンドウの並びの変更だけでは書き込みを始めず、次に書くとき、前面でなくなったとき、終了のときにまとめて書く（これらは捨てても本文は失われないため）。
- 書く処理はバックグラウンドで行う。入力のスレッドでは、そのときの文書の内容（ピースの並びと追加バッファ）を取るだけにする。1 つの文書について、書き込みは同時に 1 つまで。書いている間にさらに変更があったら、終わってから 1 回だけ書く。ピースの並びの複製の費用は、実装の PR で測り、入力が遅れるなら間隔を延ばす。
- 保存、閉じる、元に戻して変更なしになった、で消すときは、その文書についてまだ終わっていない書き込みを無効にしてから消す。書き込みは 1 本の専用スレッドが順番に行い、消す処理もその列に入れる。書き込みの確定（rename）の直前に、その文書の世代番号が今も有効かを確かめ、無効なら書かずに一時ファイルを捨てる。こうしないと、保存したあとに古い内容が書かれ、次の起動で戻ってしまう。
- 書くのに失敗したとき（ディスクがいっぱい、権限がない）は、入力を止めない。次の機会にもう一度試す。ステータスバーに 1 回だけ「未保存の文書を残せません」と出す。直るまで、終了のときは 5 章の「保存しますか」を省かず、必ず聞く。
- 終了のとき（5 章の案 2）は、書き込みの列を空にして、そのときの最新の内容と `session.ini` を書き終えてから閉じる。待っている間に文書が変わったら、もう一度確かめる。書き終えられなければ、閉じずに聞く。OS のログアウトでは待てる時間が短いので、間に合わなかった文書は、直前の世代が残る（失うのは最後の数秒分）。

間隔の数字（2 秒、30 秒）は、設定に出さない。実装で測って決める。

## 3. どこにどう置くか

場所は、`matsu.ini` と同じフォルダーの下の `unsaved/`（`-PROF` を使うときは、そのプロファイルのフォルダーの下）。

```
unsaved/
  session.ini        ウィンドウ、グループ、タブの並び、前面のタブ、文書の ID の一覧
  <id>.doc           文書 1 つ分（情報と本文を 1 つのファイルにする）
  lock               8 章のロック
  rejected/          戻せなかったもの（下の「起動時の掃除」）
```

- `<id>` は、時刻とプロセス ID と連番から作る 32 桁の 16 進数にする（乱数の依存を足さないため）。
- `<id>.doc` の作りは、1 行目が形式の名前と版（`MATSU-UNSAVED 1`）、2 行目が情報の部分のバイト数、そのあとに情報（INI）、そのあとに本文。情報と本文を別のファイルにすると、rename が 2 回になり、途中で止まったときに新しい本文と古い情報（たとえば Shift_JIS から UTF-8 に変えたのに、古い文字コード）が組み合わさるため、1 つにして 1 回の rename で入れ替える。
- 情報には、タイトルまたは無題の番号、元のパス（あれば）、元のファイルの更新時刻と大きさ、文字コード、BOM の有無、改行コード、文書のタイプ、キャレットの位置、先頭行、ブックマークを書く。
- 本文は UTF-8（BOM なし）で書く。改行は文書が持っているまま。文字コードは、保存するときのために情報に記録する。UTF-8 にするのは、どの文字コードの文書でも、変換できない文字で書き込みに失敗しないため。なお MATSU は、文字コードに合わない元のバイトを U+10FF00〜U+10FFFF の文字で持ち、通常の UTF-8 の保存ではそのバイトに戻して書く（`encoding/utf8.rs`）。残すときは、これらの文字も普通の UTF-8（4 バイトの並び）としてそのまま書く専用の書き方を使い、元のバイトに戻さない。そうしないと、無効なバイトを含む文書で、本文が壊れたと見なされる。テストで、無効なバイトを含む文書を残して戻し、元の文字コードで保存して同じバイトになることを確かめる。
- 情報の INI は `matsu.ini` と同じ形式にする（`matsu-config` の `Profile` が使える。依存を足さない）。JSON にすると `serde_json` などの依存が増えるので、推奨しない。
- 書き方は、同じフォルダーに一時ファイル（`<id>.doc.tmp`）を作り、書いて、ファイルの内容をディスクに送り（fsync）、rename で置き換え、フォルダーもディスクに送る（`crates/matsu-core/src/file/save.rs` の保存と同じ手順）。途中で止まっても、半端なファイルは `.tmp` として残り、本物の名前のファイルは前の完全なものか、ないかのどちらかになる。OS ごと止まったときも、本文がディスクに届いてから `session.ini` が新しくなる順番を守る。
- 順番: 新しい文書は、`<id>.doc` を先に書き（上の手順を終えてから）、そのあとで `session.ini` に加える。消すときは、先に `<id>.doc` を消し、そのあとで `session.ini` から外す。`session.ini` に載っているのにファイルがない文書は、戻すときに飛ばす。`session.ini` に載っていないファイルは、書いている途中に止まった新しい文書だけである（消す操作は、ファイルを先に消すため、消したはずの文書が使われていないファイルとして残ることはない）。
- 権限: macOS と Linux は、フォルダーを 0700、ファイルを 0600 にする。Windows は `%APPDATA%` が利用者ごとなので、既定のままにする。持ち運び用（exe のフォルダーの `matsu.ini`）では、その場所の権限による（7 章）。

### いつ消すか

| 場面 | 消すか |
|---|---|
| 保存した（上書き・名前を付けて保存。成功したあと） | 消す。以後の変更で、また作る |
| 閉じるときの「保存しますか」に「いいえ」 | 消す |
| 変更のない文書を閉じた | そもそも残していない |
| 終了で「保存しますか」を省いた（5 章の案 2） | 残す |
| 戻したあと、保存した | 消す。戻したまま閉じて「いいえ」でも消す |
| 変更をすべて元に戻して、変更なしの状態になった | 消す |

### 起動時の掃除

- `.tmp` は、ロックを取ったプロセスが、起動のときに消す。
- `session.ini` に載っていない `<id>.doc` は、書いている途中に止まった新しい文書。捨てずに、最初のウィンドウの最後のタブとして戻す（4 章）。読めないものは、下のとおり `rejected/` に移す。
- 戻さなかった・戻せなかったファイル（壊れている、など）は、`unsaved/rejected/` に移して、30 日たったら消す。ユーザーの文章を黙って消さないため。

## 4. 戻し方

| 案 | 内容 |
|---|---|
| A | 次の起動で、確認なしに自動で戻す（メモ帳、VS Code と同じ） |
| B | 起動のときに「前回の未保存の文書を戻しますか」と聞く |

推奨は A。戻したことは、ステータスバーに「前回の未保存の文書を N 件戻しました」と出す。B は、毎回の起動で 1 つ操作が増え、戻さないと選ぶと、突然止まったときの安全網の意味が薄れる。

- 戻す場所: 保存したときのウィンドウ、グループ、タブの並びに合わせる（ADR-0015）。ウィンドウの位置と大きさは、今の動きのまま。
- 戻す役: ADR-0016 の受け手のプロセスが、起動のときに 1 回だけ。コマンドラインで渡されたファイルは、戻した文書のあとに開く。同じファイルが戻した文書の中にあれば、新しく開かずに、そのタブを前に出す（サクラの `ActiveAlreadyOpenedWindow` と同じ）。
- 文書の状態: 変更ありの状態で戻す。無題は元の番号で戻す（空いていれば。ぶつかる場合は次の番号）。文字コード、BOM、改行、タイプ、キャレット、先頭行、ブックマークを戻す。
- 戻さないもの: 元に戻す（Undo）の履歴、選択範囲、検索の状態、キーボードマクロの記録。Undo の履歴は、本文と別の形になり、費用に合わないため。戻した文書では、Undo は戻した時点から始まる。
- 名前のある文書の元のファイルが、そのあいだに変わっていたとき: 残した本文を戻す。そのとき元のファイルの更新時刻と大きさは、情報に書いた、開いたときのものを使う。戻した文書には「戻した文書で、元のファイルの確認がまだ」という印を付け、保存の直前に（ファイルの監視が動いているかどうかによらず）元のファイルの更新時刻と大きさを今のものと比べる。違えば「このファイルは外部のエディタ等で変更されています」と聞いてから上書きする。今の「外部で変更された」の検査（`file_watch`）は、監視が切れているとき・通知だけの設定のとき・次の確認の前に保存したときには働かないので、これに頼らない。戻すときにも、ステータスバーに「ディスク上のファイルが変わっています」と出す。
- 元のファイルが消えていたとき: 名前を保ったまま戻す。保存すると、そのパスに作る（サクラが存在しないパスを開いたときの動きと同じ）。
- 本文のファイルが壊れていた・読めなかったとき: その文書は戻さず、`rejected/` に移して、ステータスバーに知らせる。ほかの文書は戻す。

## 5. 終了するとき

| 案 | 内容 |
|---|---|
| 1 | サクラどおり、「保存しますか」を聞く。残す機能は、突然止まったときの保険だけ |
| 2 | 残す機能がオンのとき、終了では聞かない（hot exit）。次の起動で戻る |

推奨は、1 を既定にして、2 を設定で選べるようにする。理由は、プロジェクトの目的がサクラの操作感の再現であり、サクラで終了すると聞かれる場面で、何も聞かずに閉じると、保存したつもりの利用者が驚くため。メモ帳や VS Code と同じにしたい利用者は、2 を選べる。

2 のときの範囲は、VS Code の `onExit` に倣う。

| 操作 | 1 | 2 |
|---|---|---|
| タブを 1 つ閉じる | 聞く | 聞く（利用者が文書を捨てる意思を示した操作なので） |
| 最後でないウィンドウを閉じる | 聞く | 聞く |
| 最後のウィンドウを閉じる、「マツエディタの全終了」、OS のログアウト | 聞く | 聞かない。全部残す |

2 でも、2 章の書き込みが失敗している文書があるときは、聞く。聞いて「いいえ」と答えたときは、その文書の残したものを消す（3 章の表）。

## 6. 巨大ファイル

残すたびに文書の全文を書くと、巨大な文書では、時間とディスクを使い切る。

| 案 | 内容 |
|---|---|
| A | 大きさの上限を超える文書は、残さない（「保存しますか」は従来どおり） |
| B | 上限を超える文書は、変更だけを残す。元のファイルの範囲と、追加した文字のピースの並びを書く。戻すときに、元のファイルが変わっていないか（大きさ、更新時刻）を確かめる |

推奨は、最初は A、B は別の PR で必要になったら足す。

- 上限: 文書全体が 64 MiB を超えるもの。`matsu.ini` の `[MATSU]` の `KeepUnsavedMaxMB`（0 は上限なし。既定 64）。
- 上限を超えた文書は、ステータスバーに 1 回「大きいため未保存の内容を残しません」と出し、5 章は案 1 の動き（聞く）にする。
- B は、元のファイルが変わっていたら戻せない（ピースが指す範囲がずれる）。そのときは、追加した文字だけを `rejected/` に取り出す。ADR-0020 の「外から変わった」の検出と合わせる。費用が大きく、使う人が少ないので、先送りでよい。

## 7. プライバシーとセキュリティ

残したものは、利用者が打った内容の平文の写しである。無題の文書に貼ったパスワードも、ファイルになる。

- 暗号化はしない（鍵をどこに置くかが問題になり、守れる範囲が狭いため）。権限（3 章）で、ほかの利用者から守る。
- 利用者ができること: 設定でオフにする。`unsaved/` を消す。オフにしたとき、`unsaved/` にあるものをどうするかは、8 章と 10 章。
- 消したファイルは、SSD やファイルシステムのジャーナル、OS のバックアップに、内容が残ることがある。上書きして消すことはしない（SSD では効かないため）。取扱説明（README か docs）に書く。
- 共有のフォルダーに置いた持ち運び用のとき、ほかの人が読めることがある。設定の説明文に書く。

## 8. 設定と複数のプロセス

### 設定

サクラにない項目なので、`matsu.ini` の `[MATSU]`（サクラが使わないセクション。既存の `SavePreserveOwnerGroup` と同じ並び）に置く。

| キー | 値 | 既定 | 内容 |
|---|---|---|---|
| `KeepUnsaved` | 0 / 1 | 1 | 保存していない文書を残して、次の起動で戻す |
| `KeepUnsavedNoAsk` | 0 / 1 | 0 | 5 章の案 2。終了のとき「保存しますか」を聞かない |
| `KeepUnsavedMaxMB` | 整数 | 64 | 6 章の上限（0 は上限なし） |

- 「共通設定」の「ファイル」のページの、自動保存の下に、「保存していない文書を残し、次の起動で戻す」「終了のとき保存の確認をしない」の 2 つのチェックを足す。上限は、設定ファイルでだけ変えられる。
- 既定をオンにする案と、オフにする案がある。推奨はオン。理由は、データを失うのを防ぐ機能で、オフだと、必要になったときには間に合わないため。ただしこれは、利用者のデータに関わる既定なので、ユーザーが決める（10 章）。
- 設定を変えたとき: オンにした → その時点の変更済みの文書を書く。オフにした → `unsaved/` の中身をどうするか聞く（消す、残す、の 2 択）。消すときは、書き込みの列を空にしてから、`session.ini` と `<id>.doc` と `rejected/` だけを消す。`lock` とフォルダー自体は消さない（動いているプロセスのロックを壊し、別のプロセスが同じ名前で新しいロックを取れてしまうため）。

### 複数のプロセス

- `unsaved/lock` を、プロセスが生きている間持つ。Windows は共有を許さない開き方、macOS と Linux は `flock`（`matsu-platform` の `file_lock`）。プロセスが終われば OS が解放するので、止まったあとに残るロックはない。
- ロックを取れたプロセスだけが、`unsaved/` を書き、戻す。通常は ADR-0016 のとおり 1 つのプロセスだけが動くので、取れる。
- 取れなかったプロセス（別のプロセスとして動かしたとき、持ち運び用を共有のフォルダーから 2 人が動かしたとき）は、この機能を使わない。使わないことを、ステータスバーに 1 回知らせる。その文書は 5 章の案 1 のとおり、聞く。
- ネットワークドライブでは `flock` が効かないことがある。そのときも使わない。
- 利用者が違えば `%APPDATA%` などが違うので、ぶつからない。

## 9. 進め方

PR の順番。

1. `matsu-config` に `unsaved` のモジュール。ファイルの形式、一時ファイル + rename の書き込み、ロック、フォルダーの走査、`.tmp` と使われていないファイルの掃除。UI に依存しない。
2. 書く側。文書の版番号と変更の検出、デバウンスとバックグラウンドの書き込み、保存や閉じるときに消す、設定の 3 キーとファイルのページ。
3. 戻す側。起動のときの読み込み、ウィンドウ、グループ、タブの復元、外から変わったファイルの扱い。
4. 終了のときの動き（`KeepUnsavedNoAsk`）。
5. （必要になったら）巨大ファイルの変更だけを残す案。

テスト。

- 書き込みの列: 保存や破棄と書き込みが重なっても、古い内容が確定しない。
- 終了の前に、最新の内容が書き終わっている。
- 書いて読んで、同じ内容と情報（文字コード、BOM、改行、キャレット、ブックマーク、日本語、CRLF）になる。
- 書いている途中で止まる（一時ファイルを書いたあと、rename の前に止める。`session.ini` を書く前に止める）。前の完全な状態か、`session.ini` に載っていない `<id>.doc` だけが残り、戻せる。
- 保存、「いいえ」、戻したあとの保存で、ファイルが消える。
- 書き込みの失敗（書き込めないフォルダー。Linux は読み取り専用にして確かめる）で、入力が止まらず、終了で聞く。
- 複数のウィンドウ、グループ、タブを、同じ並びで戻す。無題の番号。同じファイルを重ねて開かない。
- ロック。2 つ目のプロセスが書かない。
- 壊れた `<id>.doc` と `session.ini` で、ほかの文書は戻る。

コーディネーターが、Windows Sandbox と Mac の VM で確かめること。

1. 無題に文字を打ち、名前のある文書にも変更を加える（2 つのグループ、タブ 3 つ）。
2. 外からプロセスを強制終了する（Windows は `taskkill /F /PID`、macOS は `kill -9 <PID>`。名前での一括終了はしない）。
3. もう一度起動する。文書とタブの並びが戻り、ステータスバーに知らせが出る。
4. 戻した文書を保存して閉じると、`unsaved/` のファイルが消える。
5. 戻す前に、元のファイルを別のプログラムで書き換えておくと、保存のときに「外部で変更されています」と聞く。
6. `KeepUnsavedNoAsk=1` で全終了して、聞かれずに閉じ、次の起動で戻る。
7. 2 つ目のプロセスを起動して、この機能を使わない知らせが出る。

## 見送った案

- サクラの自動保存を無題にも広げる（保存ダイアログを開く）: 動作中にダイアログが出て、入力を邪魔する。
- 元のファイルの隣に `.swp` のようなファイルを置く（Vim のように）: 利用者のフォルダーを汚す。無題には使えない。
- Undo の履歴まで戻す: 形式が重くなる。

## 影響

- `matsu-config` に `unsaved` のモジュールが増える。`matsu-ui` の文書、閉じる処理、起動の処理が `unsaved` を呼ぶ。コアの文書は UI に依存しないままで、`unsaved` には本文を範囲で渡す（全文を 1 つの文字列にしない）。
- 依存は増えない。
- `docs/` に、残す場所、消えるときの条件、7 章の注意を書く。

## 10. 判断してほしいこと

推奨を先に書く。

1. 何を残すか: B（無題 + 名前のある文書の変更）でよいか。A（無題だけ）にするか。
2. 書くとき: 2 秒後 + 最長 30 秒 + 前面でなくなったとき・閉じるとき、でよいか。
3. 置き場所と形式: `matsu.ini` と同じフォルダーの `unsaved/`、本文は UTF-8、情報は INI でよいか。
4. 戻し方: 確認なしで自動で戻す（A）でよいか。聞く（B）にするか。
5. 終了のとき: 既定は聞く（案 1）、`KeepUnsavedNoAsk` で聞かない（案 2）でよいか。それとも、既定から案 2（メモ帳や VS Code と同じ）にするか。
6. 機能の既定: オン（推奨）でよいか。
7. 巨大ファイル: 64 MiB を超えたら残さない（A）でよいか。上限の既定値は 64 でよいか。変更だけを残す案（B）はいつか必要か。
8. 暗号化はしない、上書き消去はしない、でよいか。
9. オフにしたとき、`unsaved/` の中身を消すか、聞くか、残すか。推奨は聞く。
10. 戻せなかったファイルを `rejected/` に 30 日置く（黙って消さない）でよいか。
11. 複数のプロセスでは、2 つ目は使わない（8 章）でよいか。別々のフォルダー（プロセスごと）で動かす案もあるが、掃除が難しくなる。
12. 設定の名前（`KeepUnsaved`、`KeepUnsavedNoAsk`、`KeepUnsavedMaxMB`）と、設定画面の言葉でよいか。

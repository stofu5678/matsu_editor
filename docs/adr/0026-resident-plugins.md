# ADR-0026: 常駐するプラグイン（サクラの `plugin.def` を読み、イベントで起動する）

- 状態: 提案中（ユーザーが決める。下の「判断してほしいこと」の 12 項目に、推奨を付けてある）
- 日付: 2026-10-25（ユーザーが 2026-10-25 に、Phase 8 でプラグインの ADR を書くと決めた）
- 関連: [ADR-0007](0007-macros-and-plugins.md)（「常駐するプラグインの部分は提案中」と残した。この ADR はその部分）、[ADR-0008](0008-commands-and-keybindings.md)、[ADR-0010](0010-sakura-compatible-settings.md)、[ADR-0018](0018-decision-policy.md)、[ADR-0024](0024-super-app.md)（決めたこと 8: プラグインのタブはこの ADR のあと）、[ADR-0025](0025-script-languages.md)

## 背景

サクラのプラグインは、MATSU に残っている最大の穴である（[docs/sakura-gaps.md](../sakura-gaps.md) の「プラグイン」「設定」「ダイアログ」の表）。共通設定の「プラグイン」のページは枠だけで、`plugin.def` も、ジャックも、`F_PLUGCOMMAND`、`F_PLUGIN_LIST` もない。`matsu-plugin` クレートは名前に反して、1 回走って終わるマクロのホストである。

ADR-0007 は、マクロの部分を決め、常駐するプラグインには次の原則だけを残した。

- プラグインは、起動のきっかけになるイベント（サクラのジャック）を宣言し、そのイベントが起きるまで起動しない
- キー入力ごと・行ごとに走る処理は、プラグインのコードにさせず、ルールを記述したデータで持たせる
- 通信の形（JSON-RPC）は、マクロ（1 回走って終わる）とプラグイン（常駐してイベントを受ける）を分け、プラグインは「別の形で後で決める」

この ADR は、その「後で決める」部分を提案する。実装はしない。決まったら、PR を順に出す（「PR の順番」）。

### サクラの既存のプラグインを MATSU で動かせるか

- 種別は `wsh` と `dll` の 2 つ。`wsh` のハンドラは、スクリプトのファイル名で、サクラは拡張子から Windows のスクリプトエンジンを探して動かす（`CWSHPlugin::InvokePlug` が `CWSHMacroManager::Creator(拡張子)`）。つまり JScript（`.js`）や VBScript（`.vbs`）で、これらは Windows にしかない。ADR-0025 のとおり、MATSU は `.js` を QuickJS で動かし、VBScript は足さない
- `dll` は、ヘルプが「現在未実装」と書いている（`implementation01.html`）。コードは、DLL が書き出す引数なしの関数を呼ぶだけで（`CDllPlugin.cpp:56-87`）、プラグインに渡すオブジェクトがない。実際に使われているかは調べていない。DLL は C++ のサクラの内部に依存し、OS と CPU ごとのバイナリでもあるので、MATSU は読み込まず、メッセージを出す
- 動くのは、`Editor` `Plugin` `Outline` `Indent` `Complement` のオブジェクトだけを使う JScript。`WScript.*` や `ActiveXObject`（ファイルシステムの操作など）を使う部分は動かない。サクラの利用者が公開しているプラグインのうち、どれがこの条件に合うかは**調べていない**（実装の前の確認に残す）

### 他のエディタ（公開の文書による）

- Visual Studio Code: 拡張機能は、宣言した「起動イベント」が起きたときに起動する（[Activation Events](https://code.visualstudio.com/api/references/activation-events)）。信頼していないフォルダーでは「制限モード」になり、自動でコードが走るのを防ぐ。拡張機能は、制限モードで動くかどうかを宣言する（[Workspace Trust](https://code.visualstudio.com/api/extension-guides/workspace-trust)）。この ADR の遅延起動と、同意の考え方の参考にする
- ADR-0007 が参照した LSP と同じく、別プロセスと JSON-RPC の形は広く使われている。GPL のエディタのコードは読んでいない

### MATSU の今の作り

- `crates/matsu-plugin/src/session.rs`: 1 つのスクリプトにつき 1 つの子プロセスを起動し、標準入出力で JSON-RPC を話す。時間の制限は `DEFAULT_TIMEOUT`（30 秒）。ダイアログや `Sleep` の待ちは時間に数えない（`hold` / `release`）。時間切れや中断では子プロセスを終わらせる。マクロが終われば、プロセスも終わる
- 外部の言語（Node.js・Python・Ruby・PHP と、ADR-0025 で足すもの）は、利用者の処理系で動く。同梱の言語（Lua・QuickJS・MicroPython・mruby）は、`matsu-script` の 1 つのプロセスで動く（`Engine`）。同梱の処理系は、サンドボックスに入れていない。たとえば Lua は `io` を使える（`crates/matsu-script/src/lua.rs:78-80`）。ほかの処理系は確かめていない
- マクロ API の表は 1 つ（`catalog.rs`）。サクラのマクロ関数に加えて、プラグイン用のオブジェクトを足す作りは、言語ごとの生成物とブートの変更になる（ADR-0025 の「今の作り」）
- UI 側: 共通設定の `Page::Plugin` は枠だけ。`func_name.rs` と `common_settings/func_lookup.rs` は「プラグインのコマンドはまだない」と書いている。補完は `support/completion.rs` に「プラグインの候補元は未対応」とある。タイプ別設定の「支援」ページの補完の種類・スマートインデントの種類は灰色

## 案

### 1. サクラとの互換（どこまで読み、何を動かすか）

`plugin.def` と個別フォルダーの形を、そのまま読む。MATSU 専用の追加は、サクラが読み飛ばす別のセクション `[Matsu]` に書き、1 つのプラグインがサクラでも MATSU でも動けるようにする。

| サクラの物 | MATSU のふるまい |
|---|---|
| `plugin.def` の `[Plugin]` `[Plug]` `[Command]` `[Option]` `[String]` `[Wsh]`、`local\plugin_*.def`、`plugins\<名前>.ini`、ReadMe、ID の規則、数の上限（40・49・99） | 同じ形で読み書きする。上限もサクラに合わせる |
| `Type=wsh` で、ハンドラが `.js` | 同梱の QuickJS で動かす |
| `Type=wsh` で、ハンドラが `.vbs` | 動かさない。一覧に「VBScript は使えません」と出す（ADR-0025） |
| `Type=wsh` で、ハンドラが別の拡張子（`.py` など） | ADR-0007 の拡張子の表のとおり、その言語の処理系で動かす。サクラが Windows のスクリプトエンジンに任せた拡張子と同じ名前に当たるだけで、互換は求めない |
| `Type=script`（MATSU の追加） | `wsh` と同じに扱う。名前から Windows のスクリプトを連想させないための別名。MATSU 専用のプラグインはこちらで書く |
| `Type=dll` | 読み込まない。「DLL プラグインは使えません」と出す |
| `WScript.*`、`ActiveXObject` | 提供しない。エラーは、行番号つきで出力パネルに出す（マクロと同じ） |
| 上限、`Id` の重複 | サクラと同じメッセージの趣旨で拒否する |

`[Matsu]` に足す候補（サクラは無視する）: `Resident`（`UseCache` の代わりに MATSU だけで常駐を指定する）、`SmartIndent.Chars`（スマートインデントを呼ぶ文字。次の「3」）、`MinVersion`。必要になった PR で足し、増やしすぎない。

### 2. 起動と、ホストの作り

**1 つのプラグインの、1 つの言語につき、1 つのホスト（子プロセス）** にする。全プラグインで共有しない（1 つが落ちても、ほかが巻き込まれない。プラグインごとに言語も処理系も違う）。1 つの `plugin.def` に違う拡張子のハンドラが混ざっているときは、言語ごとにホストを起こす（混ぜることは許すが、勧めない）。

- **遅延起動**: ホストは、そのプラグインが宣言したジャックのイベントが、最初に起きたときに起動する。設定を読んだだけでは起動しない（ADR-0007 の原則）。`EditorStart` を宣言したプラグインは、ウィンドウができたときに起動する
- **常駐か、都度か**: サクラの `UseCache` に合わせる。`UseCache=1`（または `[Matsu] Resident=1`）なら、ホストを残して次の呼び出しに使う。0（既定。サクラも 0）なら、呼び出しごとに起動して終わらせる。サクラの `UseCache` はプラグ（ハンドラ）ごとにスクリプトを残す（`CWSHPlugin.cpp:57-89`）ので、MATSU では「ハンドラごとの状態は、常駐のホストの中でハンドラのファイルごとに分ける」ことで合わせる。理由: 都度起動は、プラグインに状態を持たせないので安全で、サクラの既定の動きと同じになる。起動の時間は、同梱の処理系で数 ms、Node.js・Python で 20〜40 ms、PowerShell で 700 ms を超えることがある（ADR-0025）。そのため、キーで呼ぶジャック（SmartIndent・Complement）は常駐を必須にし、都度起動のプラグインには付けられないようにする。常駐のホストは、プラグインを無効にするか、MATSU を終わらせるまで残す
- **1 つのホストの呼び出しは、順番に 1 つずつ**。複数の文書から同時に来たら待たせる。待たせて意味のないもの（補完・スマートインデント）は、前の呼び出しが終わっていなければ捨てる
- **文書は、呼び出しを起こした文書**。マクロの `Editor.*` は「今の文書」に作用する。プラグインは、起こした文書を呼び出しの間だけ固定する（別のタブに切り替えられても、変わらない）。その文書が閉じられたあとの呼び出しはエラーで返す。補完とスマートインデントは、呼び出しの間に文書の版やキャレットが動いていたら、結果を捨てるMATSU は 1 つのプロセスで複数のウィンドウとタブを持つ（ADR-0015・0016）ので、サクラの「エディタのプロセスごとにプラグインを読む」とは違い、ホストは MATSU 全体で 1 つ。「エディタの開始・終了」は、ウィンドウの開始・終了に当てる
- **通信**: ADR-0007 の通信の形（標準入出力、ASCII の 1 行 1 メッセージ、`initialize`）に、常駐用の呼び出しを足す。`initialize` の `params.kind` が `plugin` のとき、ホストはブートのあと待機する。エディタが `plugin/invoke`（ジャック名、プラグの番号、引数）を送ると、ハンドラが走り、その間の `Editor.*` の呼び出しは、マクロと同じ形で届く。ハンドラが終わると `plugin/invoke` の応答が返る。細かい形は 1 本目の PR で `docs/poc/json-rpc.md` に書く
- **言語**: ADR-0007 の拡張子の表と ADR-0025 の順。同梱の処理系は、`matsu-script` が、スクリプトを読み込んだまま待機できるようにする。外部の処理系は、各言語のブートが同じ待機の形を話す
- **時間の制限**（提案。最初は固定で、設定は要望が出てから）:

| ジャック | 制限 | 超えたとき |
|---|---|---|
| `Command` | マクロと同じ 30 秒。中断できる（ダイアログの待ちは数えない） | 子プロセスを終わらせ、出力パネルに出す |
| `DocumentOpen` `DocumentClose` `DocumentAfterSave` `EditorStart` `EditorEnd` | 5 秒 | 同上。操作そのものは続ける |
| `DocumentBeforeSave` | 5 秒 | 同上。**保存は続ける**（プラグインの失敗でデータを失わないため） |
| `Outline` | 10 秒 | 解析をやめ、組み込みの解析にはしない（空の一覧とメッセージ） |
| `Complement` | 1 秒 | 間に合わなかった候補は捨てる |
| `SmartIndent` | 0.5 秒 | 何も挿入しない |

- **落ちた・応答しない**: 子プロセスを終わらせ、出力パネルに「プラグイン名・ジャック・理由」を 1 行出す（マクロの `describe` と同じ形）。次のイベントでは起動し直す。**3 回続けて失敗**したら、そのプラグインを「停止」にして、利用者が一覧で入れ直すまで呼ばない。エディタは落ちない（ADR-0007）
- **入れ子のイベントは配らない**: プラグインのハンドラが走っている間に、その操作（ハンドラが保存を呼ぶ、など）で起きたイベントは、どのプラグインにも配らない。ホストが自分の呼び出しを待って止まるのを避けるため。サクラは同期の入れ子を許す（動きが変わる）
- **途中までの編集は戻さない**: 制限の時間で止めても、止めるまでにハンドラが済ませた編集は残る。1 回の呼び出しの編集は 1 つのアンドゥの単位にして、利用者が 1 回で戻せるようにする。「何も挿入しない」「保存を妨げない」は、ハンドラが編集を始める前に止まった場合の話で、途中の編集までは保証しない
- **ウィンドウを止めない**: 呼び出しは別スレッドで待ち、画面は固まらせない。保存前と閉じる前のように、結果を待つものだけは、制限の時間まで待つ（0.3 秒を超えたら、状態バーに「プラグインを待っています」と出す）

### 3. ジャックの順番と、「キー入力ごとにコードを走らせない」原則

実装の順番（理由つき）:

| 順 | ジャック | 理由 |
|---|---|---|
| 1 | `Command` | 利用者が自分で選んだときだけ走る。いちばん安全で、メニュー・キー・ツールバーの全体を通せる |
| 2 | `EditorStart` `EditorEnd` `DocumentOpen` `DocumentClose` `DocumentBeforeSave` `DocumentAfterSave` | 自動で走る最初のもの。セキュリティの仕組み（下）が前提。ホストの仕組みを使うだけで、新しい画面はいらない |
| 3 | `Outline` | アウトラインのパネルと、タイプ別設定の「解析方法」に結ぶ。FL（アウトラインの解析）の仕組みの上に載せるので、そのあと |
| 4 | `Complement` `ComplementGlobal` | 補完のウィンドウに候補を足す |
| 5 | `SmartIndent` | キー入力に結ぶので、いちばん慎重にやる |

キー入力ごとに走るジャックは、サクラの動きをそのまま写さず、次のようにする（サクラと違いが出るので「判断してほしいこと」に挙げる）。

- **`SmartIndent`**: サクラは 1 文字ごとに呼び、プラグインが「論理桁が 1 のときだけ」などと自分で判定する（`implementation03.html` の疑似コード）。MATSU は、**改行を入力した直後だけ**呼ぶ。ほかの文字で呼ばれたいプラグインは、`[Matsu] SmartIndent.Chars=}` のように文字を**データとして宣言**する（ADR-0007 の「ルールはデータで」）。宣言のない文字では呼ばない。呼ぶときも、常駐のホストで、0.5 秒の制限をつけ、結果は入力とは別のアンドゥの単位にする（サクラと同じ）
- **`Complement`**: サクラは、補完のウィンドウが開いている間、文字を打つたびに探し直す。MATSU は、**補完のコマンド（`F_HOKAN`）でウィンドウを開くときに 1 回だけ**呼び、そのあと文字を打ったときの絞り込みは、集めた候補を MATSU 側で絞る。自動で開く補完では呼ばない。候補は、ほかの候補源が出た後に、プラグインの分が届き次第足す
- この絞りは、ADR-0007 の「キー入力ごとにプラグインのコードを走らせない」に対する**小さな例外**になる（宣言した文字と改行のときだけ、時間の制限つきで、プラグインのコードを走らせる）。例外にするかどうかは、判断してほしいことの 5
- 色分けのように、行ごとに走るものは、ADR-0007 のとおりプラグインのジャックにしない（サクラにもないジャックなので、増やさない）

### 4. セキュリティ

プラグインは、イベントで**自動的に**、利用者の権限でコードを走らせる。外部の言語（Node.js・Python など）のプラグインは、その言語ができることをすべてできる。同梱の処理系もサンドボックスに入れていない（上の「MATSU の今の作り」）。そのため、**防ぎ方は「同意」であり、閉じ込めではない**。画面にも、そう書く。

提案:

1. プラグインの機能は、**既定でオフ**（サクラと同じ）。共通設定の「プラグインを有効にする」を入れるまで、何も読まない・走らせない
2. プラグインは、**1 つずつ**有効にする。フォルダーを `plugins\` に置いただけでは走らない。「新規プラグインを追加」で見つけたとき（サクラと同じ入り口）に、**確認の画面**を出す: 名前・作者・バージョン・配布先・フォルダー、使うジャック（「ファイルを保存する前に自動で動く」のように、日本語で）、使う言語と処理系、「このプラグインはあなたの権限で、制限なしに動きます」の注意。「追加」を押しても**有効にはならず**、一覧で「有効」にしたときに初めて走る（サクラは、追加がそのまま有効）
3. **変更の検出**: 有効にした時点の、プラグインのフォルダーの中の全ファイル（オプションの `.ini` は別の場所なので含まない）の SHA-256 を記録し（`Plugin.AddCommand` で別のスクリプトを足せるので、ハンドラだけでは足りない）、あとで変わっていたら、そのプラグインを「変更あり」で止め、一覧で入れ直すまで走らせない。理由: 他人が `plugins\` にファイルを置き換える・ZIP で更新される経路を、黙って通さないため。開発者向けの逃げ道（開発中のプラグインは確認を省く）は、要望が出てから
4. プラグインが呼べる API は、**マクロと同じ表**（`catalog.rs`）。外部プログラムを動かす関数（サクラの `F_EXECMD`。`Funccode_x.hsrc:419`）も含む。外部の言語では、API を制限しても意味がないので（その言語で直接実行できる）、制限は設けない。確認の画面の注意で補う
5. **拡張子の割り当てで、プラグインの処理系を決める**（ADR-0007）。処理系のパスは `matsu.ini` で変えられるので、変えられたときも「変更あり」と同じ扱いにするかは、実装のときに決める
6. 取り込むときの確認の画面は、ZIP でも同じ。ZIP の取り込みは、フォルダーの外に書かない（`..` や絶対パスを拒否）。サクラの ZIP 取り込みの安全は確かめていない

セキュリティは AI が決められない領域（ADR-0018）。ユーザーが決める。

### 7. プラグインのタブ（ADR-0024 の決めたこと 8）

向きと順番だけを決める。設計は別の ADR で行う。

- 向き: プラグインが GUI のコードを書くのではなく、プラグインが**データを渡し**、MATSU が ADR-0024 のタブの約束に沿って見せる。最初の種類は、読み取り専用の文章（Markdown など）と結果の表で、ADR-0024 のプレビューのタブと結果の表のタブに結ぶ。端末や Web ビューはプラグインに開放しない
- 順番: (1) この ADR の `Command` ジャックと同意の仕組みが入る (2) ADR-0024 の最初のタブ（プレビュー）が入る (3) プラグインが「このタブを開く」と頼む API を、別の ADR で決める
- この ADR の PR は、プラグインのタブの API を作らない

## 推奨

上の案のとおりにする。理由:

- サクラの形を読めて、既存の公開プラグインの一部は、そのまま動く可能性がある
- 1 プラグイン 1 ホストと遅延起動は、ADR-0007 の原則そのもので、既存の `matsu-plugin` の作りの延長にできる
- 自動で走るものは、既定オフ・1 つずつの同意・変更の検出で、「黙って走る」道を塞ぐ。閉じ込めは作れないので、そう書いて、利用者に見せる
- キー入力に結ぶジャックは、サクラのままだと、1 文字ごとに別プロセスへ往復することになる。改行のあとだけ・宣言した文字だけ・補完のウィンドウを開くときだけに絞れば、ADR-0007 の原則を守れる

## 判断してほしいこと

番号ごとに推奨がある。「推奨どおり」と答えれば、すべて推奨で決まる。6（セキュリティ）と 7（利用者のデータ）は ADR-0018 でユーザーが決める領域で、9 はユーザーが前に決めた「サクラに合わせる」方針の例外になる。

1. **サクラの形を読む範囲**（案の 1）。推奨: `plugin.def` と個別フォルダーを読む。`Type=wsh` は拡張子で処理系を決めて動かし、`.vbs` と `dll` は断って理由を出す。MATSU 専用の追加は `[Matsu]` と `Type=script`
2. **ホストの形**（案の 2）。推奨: 1 プラグイン 1 ホスト、遅延起動、`UseCache` で常駐/都度、既定は都度。呼び出しは 1 つずつ。3 回続けて失敗したら停止
3. **時間の制限の値**（案の 2 の表）。推奨: 表のとおり（固定）
4. **ジャックの順番**（案の 3）。推奨: Command → イベント 6 つ → Outline → Complement → SmartIndent
5. **キー入力ごとのジャックの扱い**（案の 3。サクラと動きが変わり、ADR-0007 の原則の小さな例外になる）。推奨: SmartIndent は改行のあとと宣言した文字だけ。Complement は補完のウィンドウを開くとき 1 回。自動で開く補完では呼ばない
6. **セキュリティ**（案の 4。ADR-0018 でユーザーの領域）。推奨: 既定オフ、プラグインごとに確認の画面と有効化、変更の検出、API の制限なし（注意を明記）
7. **設定の置き場所**（案の 5。利用者のデータ）。推奨: `[Plugin]` はサクラと同じ形で `matsu.ini`、同意は別の `plugins.ini`、オプションは `plugins\<名前>.ini`
8. **プラグインのフォルダー**（案の 5）。推奨: `matsu.ini` の階層の `plugins\` と、実行ファイルの隣の `plugins\`。ZIP の取り込みは、PR の最後に回す
9. **サクラとの違いを許すこと**: サクラは、追加がそのまま有効で、確認は 1 回、時間の制限もない。MATSU は有効化を分け、制限をつける（ユーザーが前に決めた「サクラに合わせる」ことの例外）。推奨: 許す。理由は、7 と 5 のとおり
10. **画面の範囲**（案の 6）。推奨: 設定のページとオプションのダイアログ、コマンドの実行時登録、メニュー・ツールバー・キーの結び、タイプ別設定の選択肢まで。アイコンの BMP は、最後
11. **プラグインのタブ**（案の 7）。推奨: 向きと順番だけ決める。API は別の ADR
12. **ADR-0007 の状態**。推奨: この ADR が決まったら、ADR-0007 の状態を「決定（第 2 弾の言語は 0025、常駐するプラグインは 0026 で置き換え）」にする。ADR-0007 の本文は書き換えない。この PR では、状態の行に、この ADR を指す一言だけを足した

## コーディネーターが確かめること（Windows Sandbox と Mac VM）

実装の PR ごとに、サンプルのプラグインで確かめる。

- Windows Sandbox（ARM64 が優先。ADR-0009）: 共通設定のページで、追加の確認の画面が出る。追加しただけでは走らない。有効にすると走る。`Command` がメニューとキーで動く。保存の前後のイベントが順番どおりに走る。わざと無限ループするサンプルが、制限の時間で止まり、保存は成功する。わざと落ちるサンプルが 3 回で「停止」になる。スクリプトのファイルを書き換えると「変更あり」で止まる。日本語のフォルダー名・プラグイン名（Shift_JIS と UTF-8 の `plugin.def`）が読める
- Mac VM: 同じ流れ。`plugins\` の場所、`matsu.ini` と `plugins.ini` の場所、メニューへの項目の出方
- 両方: 補完に候補が足される。改行のあとに SmartIndent が動き、アンドゥが 1 回で戻る。プラグインの実行中も、ウィンドウが固まらない

## 見送った案

- **全プラグインで 1 つのホスト**: 1 つの異常で全部が止まる。言語もプラグインごとに違う
- **本体に DLL や WebAssembly を読み込む**: ADR-0007 が見送った理由と同じ。落ちたときにエディタも落ち、止めにくい。DLL プラグインはヘルプが未実装と書いている
- **Windows のスクリプトエンジン（VBScript など）で動かす**: ADR-0025 で足さないと決めた
- **サクラと同じ「追加がそのまま有効」**: `plugins\` に置かれたフォルダーを「追加」した時点で有効になり、以後は確認なしに走る。MATSU は、追加と有効化を分ける
- **すべてのキー入力でプラグインを呼ぶ**: ADR-0007 の原則に反する。1 文字ごとに別プロセスに往復し、遅れが入力に出る
- **プラグインの権限の宣言を、MATSU の側で強制する**: 外部の言語では強制できない。見せかけの安全になる。注意の表示と同意で補う
- **自動更新・プラグインの配布の仕組み（ストア）**: 範囲が大きい。ZIP の取り込みまでにする
- **最初からプラグインのタブを作る**: ADR-0024 が見送った理由と同じ

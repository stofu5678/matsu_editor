# ADR-0030: 右クリックで生成 AI に送る

- 状態: 決定（2026-11-13 に、ユーザーが「判断してほしいこと」の 7 項目をすべて推奨どおりに決めた）
- 日付: 2026-11-13（ユーザーの企画の 4 番目）
- 関連: [ADR-0028](0028-terminal-tab.md)（決めたこと 2、3、6）、[ADR-0029](0029-oneliner.md)（ワンライナー）、[ADR-0026](0026-resident-plugins.md)、[ADR-0018](0018-decision-policy.md)、[ADR-0024](0024-super-app.md)
- 下調べの詳細（ツールごとのフラグ、提供元の規約、ほかのエディタ、確かめていないこと）: [docs/poc/ai-send.md](../poc/ai-send.md)

## 背景

- ユーザーの企画（2026-11-11）: 「右クリックで生成 AI に送る」。文字列をプロンプトで解釈させ、解釈した結果を次の行に送り返してもらう。Smalltalk の inspect のように使える。裏でシェルが動いていて、別タブでプロンプトも確認できる
- ADR-0028 の決めたこと 2: 端末に文字を送れるのは、利用者のキーと貼り付けと、利用者がその場で選んだ MATSU 自身のコマンドだけ。この企画では、送る文字を先に見せる。詳しくはこの ADR で決める。マクロとプラグインからは送れない。決めたこと 3: 自動で動かさず、端末の出力をファイルに残さない。決めたこと 6: `MATSU_` の変数は子に渡り、秘密を入れない
- ADR-0029（右クリックのワンライナー。ユーザーが 2026-11-13 に決めた）: ワンライナーは設定の一覧にして、マクロとは別にする。選択（なければ文書全体）を stdin に渡す。出力先は、置き換え（既定）、次の行に挿入、出力パネルから選ぶ。シェルのタブと同じシェルのプログラムを、「1 行を実行する」引数（`-c`、PowerShell は `-EncodedCommand`）で起動する（動いている対話のセッションには送らない）。エラー出力は分けて受け取り、文書に入れない
- 外部コマンド実行（`crates/matsu-ui/src/exec/`）は、選択を stdin に渡し、出力を 1 回の取り消しで入れる

## 調べた結果

### コマンドライン AI ツール

| | 非対話 | 本文 | ツールを切る方法 | ライセンス |
|---|---|---|---|---|
| Claude Code | `claude -p` | stdin（10 MB まで） | `--tools ""`。重ねて `--permission-mode dontAsk` | 独自（OSS ではない） |
| Codex CLI | `codex exec` | stdin（指示の引数があれば `<stdin>` として足す） | `--sandbox read-only`（既定）。ツールを全部切る方法は確認できず | Apache-2.0 |
| Gemini CLI | `gemini -p` | stdin | 文書で確認できず。個人の無料利用は Antigravity CLI に移ったと文書にある | Apache-2.0 |
| Copilot CLI | `copilot -p` | `-p` があると stdin は無視される（本文は引数） | `--available-tools`、`--deny-tool`（空で全部切れるかは未確認） | 確認できず |
| `llm` | `llm 'prompt'` | stdin | 既定でツールなし（推測） | Apache-2.0（未確認） |
| Ollama | `ollama run MODEL "prompt"` | stdin（生成モデルでの文書の例は未確認） | ツールなし（推測） | MIT |

- どの文書も、ツールを切れば攻撃を防げるとは約束していない。それでも、ツールを切れば、本文に書かれた命令でコマンドやファイルの書き換えが動く道は閉じる
- Claude Code の `-p` は、`--bare` なしだと、作業フォルダのプロジェクトの hooks と `.mcp.json` を、信頼の確認なしで動かす。`--bare` は OAuth を読まない
- Claude Code は、失敗（認証がないなど）を「結果として stdout に出す」。終了コードを見ないと、エラー文を答えとして挿す
- ツールは自分でも履歴を残す（Claude: `~/.claude/projects/` に 30 日、`llm`: SQLite に平文）。止めるフラグがある（`--no-session-persistence`、`--ephemeral`、`-n`）
- 外に出すデータの扱いは提供元で違う。API 系（Anthropic、OpenAI）は学習に使わない。個人向けのプランや Google の無料の API は、使う・人が読むことがある。Ollama のローカル実行は外に出ないが、クラウドのモデルは出る（`OLLAMA_NO_CLOUD=1` で切れる）

### Smalltalk と、ほかのエディタ

- Smalltalk の Do it は実行だけ、Print it は結果を出す（Squeak は選択の直後に入れる）、Inspect it は別の窓に開く。この企画の出力先 3 つに、そのまま対応する
- VS Code と JetBrains は、答えを差分で見せて、利用者が受け入れる。Zed は選択を置き換える。送る内容を事前に全文見せるのは、文書で確かめられた範囲では gptel の dry-run だけ

### 今の MATSU

- 外部コマンド実行は、Windows が `cmd.exe /C`、macOS と Linux が `/bin/sh -c`。標準出力と標準エラーが 1 本に混ざる。AI の警告や進捗が、答えに混ざる
- 端末は `write` と `encode_paste` で文字を送れる。`read_lines` で画面を読める。ただし TUI の画面は、折り返し・罫線・書き直し・代替画面があり、答えの本文を正確に取れない（推測）
- 端末の子の終了は `ChildExit` で分かるが、シェルの中のコマンドの終わりは分からない（OSC 133 は作らない決め）

## 案と推奨

### 1. 作り方

- 案 a: AI をワンライナーの一種にする。端末を通さずパイプで動かし、答えを標準出力で取る。プロンプトと答えは、読み取り専用のログのタブに出す
- 案 b: 対話の AI ツールをシェルのタブで動かし、MATSU が、見せたあとでプロンプトを打つ。答えは画面から読む
- 案 c: 非対話のコマンドをシェルのタブで動かし、`tee` で出力も捕まえ、終わったら挿入する

推奨は案 a（ADR-0029 の仕組みの上に作る）。

理由: 答えを正確に取れるのは a だけ。b は TUI の画面から本文を取るので当てにならない。c は、本文を端末に打つとシェルの履歴に文書の全文が残り、`tee` の一時ファイルは「端末の出力をファイルに残さない」（ADR-0028 の決めたこと 3）の精神に反し、コマンドの終わりも分からない。a は端末に文字を送らないので、決めたこと 2 とも衝突しない。弱みは、ユーザーの言う「裏でシェルが動く」が文字どおりではなくなること。案 6 で、見えるようにして補う。

### 2. 送る前の確認

推奨: AI のワンライナーは、実行の前に必ず確認の窓を出す。窓には、実行するコマンド、指示の文、本文の最初と終わり、文字数と行数、送り先（利用者が付けた名前）を出し、「送る」を押すまで何も送らない。窓の「次から聞かない」は、そのワンライナーごとの設定で、既定は聞く。

理由: 本文はサービスの外に出る。送る前に全文を見せる作りは、ほかのエディタにもほとんどない。MATSU が、AI の利用を利用者の手にとどめられる。

### 3. ツールを切る

推奨: MATSU は、AI のツールを自分では切らない（コマンドは利用者が書くため）。代わりに、設定の画面に「ひな形」を出す。ひな形は、ツールを切るフラグを入れた形にする（例: `claude -p --tools "" --no-session-persistence`、`codex exec --sandbox read-only --ephemeral -`）。ひな形の形は、版ごとにフラグが変わるので、ひな形の PR で `--help` と突き合わせる。確認の窓には、ツールが切られているか MATSU には分からないこと、と一言添える。

理由: MATSU が提供元の独自のフラグを解析すると、版の追従が重い。ひな形なら、利用者が見て、変えられる。

### 4. 本文の渡し方

推奨: 本文は stdin だけで渡す。引数には入れない。引数に入れないと動かないツール（Copilot CLI）のひな形は出さない。文書全体が大きいとき（目安は 100 KB。ほかに合う数があれば変える）は、確認の窓で大きさを強調し、既定を「送らない」にする。

理由: 引数は他のプロセスから見え、長さにも上限がある。

### 5. 答えの扱い

推奨:
- 出力先は ADR-0029 の 3 つ（置き換え、次の行に挿入、出力パネル）から選ぶ。AI のひな形の既定は「次の行に挿入」（企画のとおり）
- 終了コードが 0 でないときは、何も挿入せず、ログのタブにエラーを出す
- 標準エラーは、答えに混ぜない（ログのタブには出す）。そのために、AI のワンライナーは、標準出力と標準エラーを分けて取る。今の `exec` は混ぜる作りなので、分ける口を足す（Sakura 互換の外部コマンド実行の動きは変えない）
- 入れた答えは 1 回の取り消しで戻せ、入れた文字が選択される（今の外部コマンド実行と同じ）。続けて別の答えを求めるときの入力に、そのまま使える（Smalltalk の Print it に近い）

### 6. ログのタブ

推奨: 読み取り専用のタブ（タブの種類を 1 つ足す）に、実行ごとの記録を並べる。記録は、コマンド行、指示、本文、答え、標準エラー、終了コード、かかった時間。メモリだけで持ち、ファイルに書かず、自動保存（ADR-0022）にも入れない。閉じれば消える。最新の 50 件ほど（数は実装で決める）まで残す。実行中の様子（動いているコマンド行）もここに出し、「裏でシェルが動いている」を見えるようにする。同じコマンドを自分で試したいときは、コマンド行をコピーして、シェルのタブに貼れる（利用者の貼り付けなので、決めたこと 2 の範囲）。

理由: 「別タブでプロンプトも確認できる」を満たす。ファイルに書かないので、決めたこと 3 と同じ考え方。

### 7. 秘密

推奨: 確認の窓で、本文に API キーやトークンの形（`sk-`、`ghp_`、`-----BEGIN ... PRIVATE KEY-----` など）が見つかったら、その行を強調して警告する。送るかどうかは利用者が決める。見つけられないものがあることも、窓に書く。

理由: 確実には見つけられない（推測）。それでも、うっかりを減らせる。

### 8. 実行する場所と環境

推奨: AI のワンライナーは、文書のフォルダではなく、空の一時フォルダを作業フォルダにして動かす（Claude Code の `-p` は、作業フォルダのプロジェクトの設定を信頼の確認なしで動かすため）。環境変数は、親を引き継ぐ。MATSU が API キーを渡したり、保存したりしない（認証はツール自身に任せる）。

### 9. 続きの会話

推奨: 最初は作らない。1 回の実行は、会話の続きなしで、ツールにも履歴を残させない形（ひな形の `--no-session-persistence` など）にする。続きが要るという声があれば、ツールごとのセッション ID の扱いを、別に決める。

### 10. ツールを同梱しない・動かすツールを MATSU が決めない

推奨: AI のツールは同梱せず、導入も案内しない。ひな形は、設定の画面に出す例（Claude Code、Codex CLI、Ollama）にとどめる。Gemini CLI と Copilot CLI は、使う道が変わっている・本文を引数に入れる必要がある、のでひな形に入れない。ほかのツールは、利用者が自分でワンライナーを書く。

理由: MATSU のライセンス（MIT OR Apache-2.0）に、独自ライセンスのツールを巻き込まない。提供元の規約は、利用者と提供元の間のもの。

### 11. 設定と置き場所

推奨: ADR-0029 のワンライナーの一覧に、「AI」の印を持つ項目として足す（印があると、確認の窓とログのタブが付く。標準エラーの分離は、ADR-0029 で全部のワンライナーに付く）。`matsu.ini` では、`[OneLiner]` に `AI[000]=1` のようなキーを足す（既定は 0）。「次から聞かない」も、`AskBeforeSend[000]=0` のようなキーで同じ節に持つ。

## 決めたこと

2026-11-13 に、ユーザーが「判断してほしいこと」の 7 項目を、すべて推奨どおりに決めた。

1. **作り方**: AI をワンライナー（ADR-0029）の一種にし、端末を通さずパイプで動かす。企画の「裏でシェルが動き、別タブでプロンプトも確認できる」は、ログのタブで満たす（ユーザーが「パイプ＋ログのタブ」を選んだ）
2. **送る前の確認**: 毎回、確認の窓を出す。「次から聞かない」はワンライナーごとで、既定は聞く
3. **ツールを切る**: ひな形のフラグだけで切る。MATSU は保証しないことを、確認の窓に書く
4. **秘密**: 本文に API キーなどの形があれば、確認の窓で警告するだけ
5. **ログ**: メモリだけで持つ。ファイルに書かず、自動保存にも入れない
6. **動かせるツール**: MATSU は一覧を持たず、利用者の書いたコマンドだけを動かす。ひな形は Claude Code、Codex CLI、Ollama。ツールは同梱しない
7. **`matsu.ini`**: `[OneLiner]` に `AI[000]`（AI の印）と `AskBeforeSend[000]`（次から聞かない）を足す
8. **作業フォルダ**: 空の一時フォルダで動かす（プロジェクトの設定を読ませない）

## 判断してほしいこと

1. 文書の本文が外のサービスに出ること（案 2）: 確認の窓を毎回出し、「次から聞かない」はワンライナーごと・既定は聞く。これで足りるか。推奨: 足りる
2. 動かせるツールと提供元（案 10）: MATSU は一覧を持たず、利用者の書いたコマンドだけを動かす。ひな形は Claude Code、Codex CLI、Ollama。推奨: この形
3. プロンプト・インジェクション（案 3）: ツールを切るのは、ひな形のフラグだけで、MATSU は保証しない。ツールを動かす設定を利用者が選べる。推奨: この形。確認の窓に、保証できないと書く
4. 秘密の警告（案 7）: 形による簡易な警告だけ。推奨: この形
5. ログ（案 6）: メモリだけ、ファイルに書かない。推奨: この形
6. 「裏でシェルが動き、別タブで確認」の読み替え（案 1）: 端末ではなくパイプで動かし、別タブはログのタブ。ADR-0028 の決めたこと 2 は「端末に送れるもの」の定めなので、この案は端末に何も送らず、決めたことを変えない。ユーザーの企画の文面とは違うので、確認してほしい。推奨: この形。文字どおり端末で動かすなら案 c（本文がシェルの履歴に残る）か案 b（答えを取れない）になる
7. `matsu.ini` の形（案 11）: ADR-0029 の `[OneLiner]` に、AI の印（`AI[000]`）と「次から聞かない」（`AskBeforeSend[000]`）のキーを足す。推奨: この形
8. ライセンスと依存（案 10）: ツールを同梱せず、新しい依存も足さない。ひな形は例の文字列だけ。推奨: この形

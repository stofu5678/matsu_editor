# ADR-0021: 名前を MATSU Editor（マツエディタ）に改める

- 状態: 決定（2026-10-22 にユーザーが「MATSU Editor で全部改名する方向」と決め、下の「決めたこと」の 6 つも推奨どおりに決めた）
- 日付: 2026-10-22

## 背景

「UME Editor」は、動画編集ソフト「Ume Movie Editor（UME）」（デスクトップとモバイル向け）と名前がぶつかる。2026-10-22 にユーザーが気づいた。

ほかにも「UME」と呼ばれる編集ソフトが多い。ユーザーが検索の AI 要約で見つけたもの（2026-10-22。調整役は 1 つずつは確かめていない）:

- Umo Editor: Vue 3 と Tiptap で作られた、Web の文書エディタ（オープンソース）
- Neo UMEditor / UME lite: ブラウザで動く、軽いアウトラインエディタ
- Ume Movie Editor: 動画を再エンコードせずに切り貼りする動画編集ソフト（上のもの）
- Universal Minecraft Editor（UME）: Minecraft のセーブデータ（NBT）の編集ソフト
- UltimateModEditor（UME）: ゲーム「Game Dev Tycoon」の MOD を作るソフト

エディタの名前として「UME」を使い続けると、検索でも呼び名でも埋もれる。

ユーザーが挙げた候補は MATSU・TAKE・MOMO の 3 つ。調べた結果（2026-10-22、米国向けの Web 検索を数回。商標の検索ではない）:

| 名前 | 同じ名前のソフト | ほかに気になること |
|---|---|---|
| MATSU Editor | 見つからない | 日本語の「待つ」と同じ音 |
| TAKE Editor | 見つからない | 英語の普通の単語で、検索に埋もれる。英語圏では「テイク」と読まれ、動画の「Takes for Mac」「NewTake」と紛らわしい |
| MOMO Editor | 見つからない | 大手の SNS「Momo（陌陌）」と決済アプリ「MoMo」が同じ名前。英語圏ではネットのデマ「Momo チャレンジ」を連想させる |

ユーザーは MATSU を選んだ。由来は松竹梅の「松」で、サクラ（桜）・ウメ（梅）と同じく、和の植物の名前になる。

利用者はまだいない（最初のリリース v0.1.0 を 2026-10-22 に出したばかり）。改名するなら今がいちばん安い。

## 決定

名前を MATSU Editor に改める。製品名だけでなく、識別子、リポジトリ、手元のフォルダまで、すべて変える。

### 名前の書き方

CLAUDE.md の名前のルール（2026-10-17 のユーザーの判断）を、次で置き換える。

| 場所 | 今 | これから |
|---|---|---|
| 英字で書く製品名（ウィンドウのタイトル、メニュー、README、文書） | UME Editor | MATSU Editor |
| カタカナで書く場所（サクラの表示名に「サクラエディタ」が入るもの。メニューの「サクラエディタの全終了」など） | ウメエディタ | マツエディタ |
| リポジトリ | `stofu5678/ume_editor` | `stofu5678/matsu_editor` |
| クレート | `ume-*` | `matsu-*` |
| 実行ファイル | `ume`、`ume-script` | `matsu`、`matsu-script` |
| macOS のアプリ | `UME Editor.app` | `MATSU Editor.app` |
| アプリの識別子 | `io.github.stofu5678.ume-editor` | `io.github.stofu5678.matsu-editor` |
| 設定ファイル | `ume.ini` | `matsu.ini` |
| 設定の置き場所 | `%APPDATA%\ume-editor` など | `%APPDATA%\matsu-editor` など |
| リリースのアセット | `ume-<版>-<対象>` | `matsu-<版>-<対象>` |
| 環境変数（テストと CI） | `UME_*` | `MATSU_*` |
| 単一起動のソケットとロック、一時ファイル | `ume-*` | `matsu-*` |
| マクロのメッセージボックスの見出し | 「UME Editor マクロ」 | 「MATSU Editor マクロ」 |

小文字しか使えない場所や慣習で小文字にする場所は、`matsu` と書く。

### 変えないもの

- サクラの名前を写したもの: `sakura.ini` 互換の書式（ADR-0010）、`_sakurafiletree.ini`、機能の名前（`F_*`）、マクロの関数名
- 歴史の記録: 出したリリース v0.1.0（UME Editor 0.1.0）、`CHANGELOG.md`、過去の ADR・PR・コミットの文面。これから書く文書だけ新しい名前にする。ただし、ADR-0013（モジュールの構造）は今のクレートの構成を示す文書として読むので、クレートの名前を新しい名前に直した（2026-11-01 にユーザーが判断）
- 調整役のサンドボックスの作業フォルダ（`C:\Users\yamab\ume-sandbox`、Mac の `~/ume-mac-sandbox`）。作業用なので、変えなくてよい

### 利用者のデータの引き継ぎ

- 起動したとき、新しい場所に `matsu.ini` がなく、古い場所に `ume.ini` があれば、古いフォルダの中身を新しいフォルダへコピーする。`ume.ini` は `matsu.ini` の名前にする
  - 古い場所: Windows は実行ファイルの隣の `ume.ini`（持ち運び用）と `%APPDATA%\ume-editor\`、macOS は `~/Library/Application Support/ume-editor/`、Linux は `$XDG_CONFIG_HOME/ume-editor/`（なければ `~/.config/ume-editor/`）
- 古いファイルは消さず、書き換えもしない（失敗しても元に戻れるように）
- 引き継いだことを 1 回だけ知らせる（ステータスバーのメッセージ）
- 引き継ぎのコードは 1.0 まで残し、そのあとで消す
- 古い UME（v0.1.0）と新しい MATSU は、単一起動の仕組み（ADR-0016）が別々になり、同時に動いても互いを見つけない。問題にしない

### アイコン

今の絵は梅（#198）。松の絵に替える。絵はユーザーが用意する（梅の絵と同じく、Claude のチャットで作ったものを取り込む）。2026-10-22 にユーザーが用意した（`~/project/tmp/matsu_icons.zip`。梅のときと同じ 9 つのファイル: 16・32・48・256・512 の PNG、ICO、SVG を 3 つ）。改名の PR で替える。

### 進め方

1. この ADR をユーザーがマージする
2. 改名の PR を 1 つ出す。製品名、カタカナ、識別子、クレート、実行ファイル、設定の引き継ぎ、アイコン、CI とスクリプト、文書、CLAUDE.md の名前のルールをまとめて変える
   - 全体に触るので、ほかの PR と必ずぶつかる。開いている PR がない時期に、1 人の担当が行う。改名の間はほかの PR を出さない
   - CI に、古い名前が残っていないかを確かめる検査を足す。歴史の記録（`CHANGELOG.md`、過去の ADR）、引き継ぎのコード、サクラの名前などは除く
3. 改名の PR を main に入れた直後に、ユーザーが GitHub でリポジトリの名前を変える（リポジトリの設定はユーザーの作業）
   - GitHub は古い URL（Web、`git clone`、`git push`）を新しい名前へ転送する。PR、issue、リリース、Actions の設定、ブランチ保護、secrets はそのまま引き継がれる
   - 古い名前 `ume_editor` は、同じアカウントで使い回さない（使い回すと転送が切れる）
4. 調整役が、リポジトリの中の URL を新しい名前に直す PR を出す（`Cargo.toml` の `repository`、README、docs、`THIRD_PARTY_NOTICES.txt` など）
5. 調整役が、手元のフォルダを `~/project/ume_editor` から `~/project/matsu_editor` に移す。担当がだれも動いていないときに、次の順で行う
   1. 動いている担当とバックグラウンドの作業を止め、終わったワークツリーを消す
   2. フォルダを移し、`git worktree repair` でワークツリーの参照を直し、`git remote set-url` で新しい URL にする
   3. 作業メモ（`.claude/handoff/`）とスクリプトの中のパスを直す
   4. Claude Code の作業メモ（`~/.claude/projects/` の下の、パスから作った名前のフォルダ）を、新しいパスの名前のフォルダへ写す
   5. Windows の clone（`C:\Users\yamab\source\repos\ume_editor`）は、ユーザーが必要に応じて移す（調整役は触らない）
6. 次のリリース（0.2.0）から MATSU Editor の名前で出す。release-please の `package-name` も `matsu-editor` にする（タグは今のとおり `vX.Y.Z`）
7. アイコンは、改名の PR で松の絵に替える（絵はもう用意できている）

## 決めたこと（2026-10-22、ユーザーがすべて推奨どおりに決めた）

1. 設定ファイルの名前を `matsu.ini` に変える（`ume.ini` のままにする案もあった。引き継ぎは要らないが、古い名前が残る）
2. 古い設定は、起動したときに新しい場所へコピーし、古いファイルは残す。引き継ぎのコードは 1.0 まで残す
3. アイコンは松の絵に替え、絵はユーザーが用意する（同じ日に用意できた）
4. 出した v0.1.0 は UME Editor のまま残す。消したり名前を変えたりしない
5. 改名の PR は 1 つにまとめ、開いている PR がない時期に行う
6. 手元のフォルダの移動は、調整役が上の手順で行う

## 影響

- 2026-10-22 の main（790f770）で、432 個のファイルに「ume」「UME」が入っている。「UME Editor」は 591 か所、「ウメエディタ」は 17 か所。大半は機械的な置き換え
- 古い URL は、GitHub の転送で動き続ける
- 改名の間（進め方の 2〜5）は、ほかの PR を止める
- 利用者のデータ: 古い設定は残したまま、コピーで引き継ぐ。消えるものはない

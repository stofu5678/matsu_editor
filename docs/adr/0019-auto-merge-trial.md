# ADR-0019: 自動マージの試行

- 状態: 決定（試行）
- 日付: 2026-10-21（ユーザーが「自動マージも試してください」と決めた）

## 背景

ADR-0014 で、Phase 5 からは自動のチェックとレビューが通った PR を AI がマージし、人は ADR の変更、依存の追加、データが消えるおそれのある処理だけを判断すると決めた。ADR-0018 で、AI が決めてよい判断の型と、人に聞くことを決め、マージを始める時期と条件は別に決めることにした。

2026-10-21 時点で、次の自動の確認がそろった。

- 5 つの OS の CI と、実際の実行ファイルを動かす E2E
- サクラ本体と UME に同じキーマクロを流して、保存の結果を比べるテスト（121 件すべて一致）
- Windows サンドボックスでの確認（ユーザーの実機での確認に代えた。2026-10-21 にユーザーが判断）
- マージ待ちの PR をまとめて試すこと（2026-10-20 に、同時にマージした PR どうしで main が壊れたため）

## 決定

調整役（メインのセッションの AI）は、次をすべて満たす PR を、自分で squash マージしてよい。

1. 「判断してほしいこと」がない（ADR-0018 の人に聞くことに当たらない）
2. CI がすべて通っている
3. 調整役の Codex のレビューで指摘がない（指摘を退けたときは、理由を PR に書く）
4. ほかのマージ待ちの PR とまとめて試し、clippy とワークスペースのテストが通っている
5. 画面に関わる変更は、Windows サンドボックスで確かめてある

それ以外の PR は、ユーザーがマージする。担当（エージェント）はマージしない。

調整役は、マージしたものをそのつど一覧でユーザーに知らせる。ユーザーは、いつでも元に戻せる（revert の PR）。

## 見直し

試行の間、調整役は、マージしたあとに main の CI が落ちたものと、ユーザーが戻したものを作業の記録に残す。問題が続く種類の PR は、条件から外す。

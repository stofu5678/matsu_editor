# ADR-0014: 開発の進め方とバージョンの付け方

- 状態: 決定（ループの細かいルールは Phase 5 の前に `CLAUDE.md` に書く）
- 日付: 2026-10-10

## 背景

サクラエディタには仕様（ソースとヘルプ）があるので、機能の実装のかなりの部分を AI に任せられる。人の時間は、まとまった機能ができてからの操作の確認に使いたい。また、gem や npm と違い、版ごとの公開に人の作業が要らない形にできるので、それを活かしたい。

## 決定

### 自動のループ

- Phase 5（並列実装）から、人のレビューを挟まずに、AI が実装・テスト・レビュー・マージを繰り返す形にする
- Phase 1〜4 は今までどおり人が判断する。この間に、コマンドの API、テストの形、自動のチェックを固める
- ループのルールは、このリポジトリの `CLAUDE.md` に書く。`~/project/CLAUDE.md` の push 前の手順は、このリポジトリでは `CLAUDE.md` の記述で上書きする
- 人のレビューの代わりに、次がすべて通ったものだけを自動でマージする
  - サクラのヘルプとソースから作ったテスト（カーソル位置付きのテキストで期待値を書く形）と、E2E のテスト
  - 5 つの OS の CI と、そのほかの自動のチェック（ライセンス、脆弱性、綴り、文書の警告など）
  - Claude と Codex のレビュー
- 次は自動でマージせず、人が判断する
  - ADR の変更（設計の判断）
  - 依存の追加（ライセンスの確認は cargo-deny で自動にするが、何に依存するかは人が決める）
  - 保存など、利用者のデータが消えるおそれのある処理
- 人は、まとまった機能ができたところで、操作して確かめる

### バージョン

- main にマージするたびに、5 つの OS 用のビルドを自動で作り、毎日版（プレリリース）として公開する
- 版の番号は、main のコミット（Conventional Commits の形の PR のタイトル。PR は squash でマージする）から自動で決める。`feat` で minor、`fix` で patch を上げる。release-please などの仕組みを使い、リリースの PR も自動でマージする
- しばらくは 0.x とする。1.0 にする時期は人が決める
- 配布するアプリへの署名（macOS の公証、Windows の署名）は、最初の設定だけ人が行い、あとは CI で自動にする。macOS は Apple Developer Program への登録が要る

## 実施の時期

- PR のタイトルの形（Conventional Commits）と自動のチェックは、2026-10-10 から CI で確かめる
- 毎日版とリリースの自動化は、配布できる実行ファイルができてから（Phase 1）作る

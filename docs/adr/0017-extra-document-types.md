# ADR-0017: サクラにない言語のタイプを組み込む

- 状態: 決定
- 日付: 2026-10-17（同じ日に、ユーザーが「よく使う言語を足す」案を選んだ）。2026-11-01 に、本文の名前を今の名前に直した（[ADR-0021](0021-rename-to-matsu.md)）

## 背景

サクラエディタが最初から持つタイプ（タイプ別設定）は 17 で（ADR-0010 の「タイプ別設定（文書タイプ）の扱い」）、JavaScript、TypeScript、Rust などのタイプはない。そのため、サクラでも MATSU Editor でも、`.js` のファイルは「基本」のタイプになり、色が付かない。Python のタイプのキーワードは Python 3 の予約語だけで、`print` などの組み込み関数には色が付かない。

ユーザーが実機で色分けを確かめたとき（2026-10-17）、JavaScript に色が付かないことが問題になった。サクラでは、利用者がタイプを自分で足す。MATSU Editor にはタイプ別設定の画面がまだない。

## 決定

よく使う言語のタイプを、MATSU Editor 独自の組み込みのタイプとして足す（2026-10-17 にユーザーが選んだ）。

- 足す言語は、JavaScript、TypeScript、JSON、CSS、Markdown、Rust、Go、Ruby、シェルスクリプト、YAML から始める。拡張子、コメント、文字列、キーワードは、各言語の仕様から決める。ほかのエディタの定義ファイルからは写さない（GPL のものがあるため）
- Python のタイプに、組み込み関数（`print` など）を 2 つ目の強調キーワードとして足す
- サクラの 17 のタイプは、番号も中身も変えない
- MATSU Editor 独自のタイプは、17 番より後の番号のうち、設定ファイル（`matsu.ini`）が自分のタイプに使っていない番号に、決まった順で入れる。使っていない番号とは、`Types(N)` の節がない番号と、サクラが書き出す空きの節（名前が `設定N` で、拡張子がないもの）の番号である。サクラから写した設定ファイルにも空きの節があるので、そのまま使える
- 設定ファイルが自分のタイプに使っている番号は、サクラと同じく、そのタイプとして読む（「基本」の写しから始めて、ファイルのキーを重ねる）。サクラで作ったタイプは、サクラと同じに見える
- 独自のタイプが入る番号は設定ファイルによって変わる。空きの番号が足りなければ、入らないタイプがある。設定ファイルに書き出すときは、そのタイプのすべてのキーを書く（次に読んだときに同じタイプになるように）
- 強調キーワードのセットも、同じ決まりで、サクラの 17 のセットより後の空いた番号に入れる
- 共通設定の「強調キーワード」ページ（2026-10-19）で OK を押して `[KeyWords]` を書くときは、独自のセットを含めて、すべてのセットを書く。このとき `bUmeExtraSetsInFile=1` を添える。このキーがあるファイルでは、独自のセットは名前（`Rust` など）で探し、足し直さない（利用者が消したセットは、消えたままになる）。キーがないファイル（サクラが書いたものを含む）は、これまでどおり空いた番号に足すが、同じ名前のセットがあれば、それを独自のセットとして使う。タイプの設定ファイルに書かれたセットの番号は、セットを消したときにサクラと同じに付け替える（消したセットは -1、それより後は 1 つ前）

## 見送った案

- サクラと同じく、17 のタイプのままにして、タイプ別設定の画面ができてから利用者が足す案: その画面ができるまで、JavaScript などに色が付かない
- 独自のタイプを決まった番号（17 番から）に置く案: サクラから写した設定ファイルにある空きの節や、利用者が作ったタイプと重なり、混ざったタイプになる

## 影響

- `matsu-config` の組み込みのタイプ（`settings/builtin_types.rs`）と強調キーワード（`settings/keyword_data/`）に、独自の分を足す。ADR-0010 の「タイプ別設定（文書タイプ）の扱い」は、サクラの 17 のタイプについての決まりとして残る
- タイプの一覧（`F_TYPE_LIST`）やマクロの `ChangeType` が使う番号は、設定ファイルによって変わることがある
- サクラにない色分けのしかた（JavaScript のテンプレート文字列など）が要るときは、サクラの仕組み（引用符、正規表現キーワードなど）でできる範囲にとどめるか、別に決める

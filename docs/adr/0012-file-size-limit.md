# ADR-0012: ファイルの大きさに上限を設けない

- 状態: 決定
- 日付: 2026-10-10（2026-10-15 に改訂）
- 変えるもの: [ADR-0001](0001-project-approach.md) の進める順序（巨大ファイルを最後に回す）

## 背景

[ADR-0005](0005-text-buffer-and-large-files.md) では、2GB を超えるファイルを範囲ごとに読む方式を、メモ帳相当の次（Phase 2）に作ることにしていた。印刷とスクリプトの互換を先に進めたいので、順番を変えた。

最初は「サクラと同じく 2GB まで」と決めた。2026-10-15 に、これはユーザーの勘違いだったと分かった。64 ビット版のサクラには上限がない（`CFileLoad::GetLimitSize` は `_WIN64` で `ULLONG_MAX` を返し、`CFileLoad::IsLoadableSize` は巨大ファイルを許す設定のときに上限を見ない。どちらも `sakura_core/io/CFileLoad.cpp`）。2GB は 32 ビット版の上限だった。

## 決定

ユーザーの決定（2026-10-15）: 「サクラエディタと同じで無制限でいい」。

- ファイルの大きさに上限を設けない。64 ビット版のサクラと同じ。実際の上限はメモリ。メモリに載らないファイルは、読み込みの失敗（メモリ不足）として断る
- 呼び出し側が上限を決めたいとき（テストなど）のために、`Document::with_limit` と `OpenOptions::max_len` は残す。上限を超えたときだけ `TooLarge` を返す
- バッファの行の索引と、ピースの位置は 64 ビットで持つ。索引は、上位 32 ビットが変わる位置だけを別に記録して、改行 1 つあたり 5 バイトのまま 4GiB を超える位置を指せるようにした（素直に 64 ビットにすると 9 バイトになる）
- `usize` が 32 ビットの環境（CI には無い）では、メモリに載せられる 4GiB を超えるファイルを `TooLarge` で断る
- 範囲ごとに読む方式は、ロードマップの最後のフェーズ（Phase 6）で作る。その目的は、上限を外すことではなく、巨大なファイルをメモリに全部読まずに速く開くこと
- ADR-0005 の作り（ピースツリー 1 つで編集し、元データの持ち方だけを差し替える）は変えない。差し替えの入口は Phase 1 から用意する

## 影響

- 文書へのアクセスを範囲指定で行うルール（[CLAUDE.md](../../CLAUDE.md)）は残す。巨大なファイルで全文を 1 つの文字列にすると、メモリと時間を使い切るため
- Phase 6 までは、巨大ファイルを開くと、ファイルの大きさ分のメモリを使い、読み込みに時間がかかる

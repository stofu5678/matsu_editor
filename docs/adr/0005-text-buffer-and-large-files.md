# ADR-0005: テキストバッファと巨大ファイル

- 状態: 決定（細部は Phase 1・6 で詰める。大きさの上限は設けない: [0012](0012-file-size-limit.md)）
- 日付: 2026-10-08（2026-10-15 に、0012 の改訂に合わせて直した）

## 背景

サクラエディタはファイル全体を行のリストに読み込む（32bit 版は約 2GB が上限、64bit 版は上限なし）。このプロジェクトでも全体を読む方式を基本にし、とても大きなファイルは範囲ごとにも読めるようにする。

## 決定

- ファイルは全体をメモリに読み込む。大きさの上限は設けない（[0012](0012-file-size-limit.md)）。とても大きなファイルは、表示や検索に必要な範囲ごとに読み込めるようにする（Phase 6）。どの大きさから範囲ごとに読むかは設定で変えられるようにする
- 2 つの方式で編集の仕組みを分けない。編集はピースツリー（元データへの参照と、編集で入った文字列をつなぐ木）1 つで行い、元データの持ち方だけを差し替える
- 元データは元の文字コードのバイト列のまま持ち、表示や検索に必要な部分だけ変換する。編集で入った文字は UTF-8 で持つ
- 全体を読み込む場合も、先頭が読めた時点で表示し、残りはバックグラウンドで読む

## 理由

- 編集・Undo・検索・保存のコードを 1 つにでき、同じテストを両方の方式で回せる
- 編集していない部分は元のバイト列のまま保存できるので、変換できない不正なバイトも壊れない
- SJIS・EUC-JP・UTF-8 では改行のバイトが文字の一部に現れないので、改行の位置で区切れば、範囲ごとに読んでも文字化けしない

## 範囲ごとに読む方式での制限

- 行番号は、改行位置を調べ終わるまで概算で表示する
- 「すべて選択してコピー」には上限を設ける
- 「すべて置換」は新しいファイルに書き出す形にする
- 遠く離れた行にまたがる色分け（ブロックコメントなど）は簡易にする

## 保存

- 一時ファイルに書いてから置き換える
- 編集していない範囲は、元のファイルからそのまま写す

## 残っている確認

- UTF-16 は 2 バイト単位、ISO-2022-JP は状態を持つ文字コードなので、範囲の区切り方を個別に確かめる

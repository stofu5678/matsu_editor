## 背景

- ユーザーの企画（2026-11-11）の 2 番目。「シェル（今 md ファイルのプレビューだけ載せてる別タブ別機能）」「生成 AI の CLI を載せたり応用が効くので、少し手間がかかっても実装したい」
- 続く企画の土台になる。3 番目は「右クリックでシェルのワンライナーに通して加工する」、4 番目は「右クリックで生成 AI に送り、答えを次の行に返す。裏でシェルが動き、別のタブでプロンプトも見える」
- ADR-0024 は、ターミナルを「別の ADR で決める（依存 `alacritty_terminal` の追加と安全の扱いもそこで）」とした。ADR-0024 の推奨では、結果の表と画像のあとだった。これを、ユーザーの企画の順で先にする

- `alacritty_terminal` の新しい依存は `vte`、`rustix-openpty`、`signal-hook`、`miow`、`home`、`cursor-icon` で、どれも MIT か Apache-2.0 を選べる。`deny.toml` の許可リストは変えずに通る見込み（`cargo deny` は実装の PR で確かめる）
- `alacritty_terminal` は、マイナー版ごとに API が変わる。GPUI と同じく `=0.26.0` のように版を固定して上げる
- Zed の端末のクレートは GPL なので、読まず、使わない（CLAUDE.md）

### 生成 AI のコマンドライン・ツールが端末に求めるもの

Claude Code、Codex CLI、Gemini CLI の文書を読んだ。

- ほぼ必須: 代替画面、256 色と 24 ビット色、大きさの変更、括弧付き貼り付け、同期出力（ちらつき防止）の解釈。`alacritty_terminal` はどれも持つ
- あるとよい: マウスの報告。後でよい: Kitty キーボード（改行は Ctrl+J で入れられる）、リンク（OSC 8）、通知
- Windows の ConPTY には、差分の描画で古い文字の断片が残る既知の問題がある（Claude Code の文書。全体を描き直す設定で避けられる）

### 日本語

- 幅: `alacritty_terminal` は、東アジアの曖昧な幅の文字（`○ ─ │` など）を 1 桁で数え、変えられない。エディタはサクラに合わせて 2 桁。生成 AI のツールは 1 桁で数えているとみられる（確かめていない）
- IME: 変換中の文字は端末に送らず、MATSU が持ってカーソルの位置に重ねて描き、確定したときに送る。エディタの入力の作り（GPUI の `EntityInputHandler`）を端末のビューにも作る

### 描画

エディタの描き方（`EditorElement`）の骨格と、桁の幅の測り方を使い回せる。200 × 60 のセルなら、行ごとに同じ色の塊をまとめて、1 フレームに 60 回の整形になる。ふつうのフレームの時間に収まる見込みだが、測っていない。

### 今の MATSU との関係

- 外部コマンドの実行（`F_EXECMD`）は、サクラと同じく、マクロから確認なしで動く。マクロとプラグインが端末に文字を送る口を作らなければ、端末を足しても、マクロでできることは増えない
- タブの枠組み（ADR-0024）: `TabContent`、`TabPanel`、`MenuKind`、閉じる確認の `CloseCheck`。端末の種類と、「実行中のプロセスがある」という閉じる確認を足す
- macOS で Finder から起動したときの PATH（#364）: 端末はシェルを `login` 経由で起動するので、シェルが自分で PATH を作る

## 案と推奨

### 1. 部品

推奨は `alacritty_terminal`（`=0.26.0` で固定）。状態・解釈・起動・読み取りのスレッドがそろっていて作る量が少なく、手入れも続いている。生成 AI のツールが求める機能も持つ。弱みは曖昧幅を選べないことだが、2 のとおり 1 桁で困らない見込み。

見送り: `portable-pty` + `vt100`（読み取りのスレッドと状態のつなぎを自分で書く。`portable-pty` の手入れが止まっている）。`termwiz` / `wezterm-term`（crates.io にない部分の取り込みが要り、依存が多い）。`libghostty-vt`（若く、ネイティブのビルドが 5 つの環境の CI で重い）。

### 2. 文字の幅

推奨: 端末の曖昧幅は 1 桁にし、エディタの設定（2 桁）には合わせない。端末で動くプログラムの多くが 1 桁で数えるため。罫線など、日本語のフォントで全角の形に描かれる文字は、セルの幅に押し込んで描く。2 桁がほしいという声があれば、`alacritty_terminal` を取り込んで改変する（Apache-2.0 なので、改変したと書けば可能）。

### 3. 起動するシェルと場所

推奨（型 B・C）: 既定のシェルは、macOS は `login` 経由のログインシェル、Linux は `$SHELL`（なければパスワードの記録のシェル）、Windows は PowerShell 7（`pwsh` が見つかれば）、なければ Windows PowerShell。設定で変えられる（`cmd` など）。作業フォルダは今の文書のフォルダ、文書がなければホーム。

### 4. 端末に文字を送れるもの（セキュリティ）

推奨: 利用者のキー入力と貼り付けと、利用者がその場で選んだ MATSU 自身のコマンドだけにする。企画 4 の「生成 AI に送る」がこれに当たる。送る文字を先に見せる形にし、詳しくは企画 4 の ADR で決める。マクロとプラグインからは送れないようにする（その API を作らない）。

理由: 端末は対話のシェルで、送った文字はそのまま実行されうる。そこで動く生成 AI のツールにも入り、利用者から見えにくい。企画 3（ワンライナーで加工）は、端末を通さず、今の外部コマンドの実行（パイプ）で作れる。

### 5. 自動で動かすもの、記録

推奨:
- タブを開いたときは、シェルを起動するだけにする。コマンドを自動で送らない。フォルダや文書の種類に応じて端末を開く、ということもしない
- 端末の出力をファイルに残さない。スクロールバックは保存しない。未保存の文書の自動保存（ADR-0022）にも入れない（出力にパスワードやトークンが出ることがあるため）
- シェルの履歴は、シェル自身が書く。MATSU は触らない
- シェルとの連携（OSC 133 など、プロンプトの位置や終了コードを知る仕組み）は、最初は作らない

### 6. 貼り付け

推奨: 括弧付き貼り付けを使う。貼り付ける文字から、改行とタブを除く制御文字（ESC など）を取り除く。括弧を抜けて実行させる手口を防ぐためである。端末で動くプログラムが括弧付き貼り付けを求めていないときに複数行を貼るなら、確認を出す（貼った改行がそのまま実行されるため）。

### 7. 端末からの出力の扱い

推奨:
- クリップボード（OSC 52）: 書き込みは許し、読み取りは許さない。端末で動くプログラムに、クリップボードを読ませないため
- タブの題（OSC 0 と 2）: 長さを決めて切り、制御文字を除く
- リンク（OSC 8）: `http` と `https` だけを開き、開く前に URL を見せる
- 問い合わせへの答え（色や大きさなど）: `alacritty_terminal` の作りのまま

### 8. 環境変数

推奨: 親（MATSU）の環境を引き継ぎ、`TERM=xterm-256color` と `COLORTERM=truecolor` を足す。MATSU が内部で使う変数（`MATSU_` で始まるもの）は渡さない。MATSU 自身の環境は変えない（`set_var` を使わない。#364 と同じ方針）。API キーなどを、MATSU が渡したり保存したりはしない。

### 9. キー

推奨（型 C）: 端末のタブでは、キーは原則として端末に送る。例外は、タブの切り替えなどのウィンドウの操作と、コピーと貼り付け。Windows と Linux は Windows Terminal と同じく、Ctrl+C は選択があればコピー、なければ端末に送り、Ctrl+V は貼り付け。macOS は Cmd+C と Cmd+V。

### 10. 閉じるとき

推奨（型 C）: 子のプロセスが動いていれば、閉じる前に確認を出す。終わらせ方は、macOS と Linux はシグナル（SIGHUP）、Windows は ConPTY を閉じる。読み残しで止まらないよう、閉じる処理は別のスレッドで行う。ウィンドウを閉じたあとも子を生かす作り（tmux のような形）は作らない。

### 11. 設定と置き場所

推奨: `matsu.ini` の、サクラにない節（`[Terminal]`）に置く（ADR-0024 の決めたこと 7）。最初の項目は、シェル（プログラムと引数）とスクロールバックの行数。行数の既定は 5000 行にする（1 行 120 桁なら約 14 MB。`alacritty_terminal` の既定の 10000 行は、タブを何枚も開くと重い）。

### 12. コードの置き場所

推奨（型 B）: 新しいクレート `matsu-terminal` を作る。UI に依存せず、`alacritty_terminal` を包み、端末の状態、起動、キー入力の符号化を持つ。画面（描画、IME、マウス）は `matsu-ui` の `terminal/` に置く。タブを開く関数は、MATSU 独自の `F_` 関数として 1 つ 1 ファイルにする。

### 13. `conpty.dll`

推奨: 同梱しない（Windows の ConPTY を使う）。同梱すると新しい ConPTY を使えるが、配布物とライセンスの確認が要る。差分の描画の断片で困ったら、そのときに別に決める。

## 決めたこと

2026-11-11 に、ユーザーが 9 項目をすべて推奨どおりに決めた（「すべて推奨どおり」）。

1. **依存**: `alacritty_terminal`（`=0.26.0`）と、それが入れる新しい依存（`vte`、`rustix-openpty`、`signal-hook`、`miow`、`home`、`cursor-icon`）を足す
2. **端末に文字を送れるもの**: 利用者のキー入力と貼り付けと、利用者がその場で選んだ MATSU 自身のコマンドだけ。マクロとプラグインからは送れない（API を作らない）
3. **自動で動かさない、記録しない**: タブを開いたらシェルを起動するだけ。出力をファイルに残さず、スクロールバックを保存せず、自動保存にも入れない
4. **貼り付け**: 括弧付き貼り付けを使い、改行とタブを除く制御文字を取り除く。括弧付き貼り付けを求めていないプログラムに複数行を貼るときは確認を出す
5. **端末からの出力**: クリップボード（OSC 52）は書き込みだけ許し、読み取りは許さない。タブの題は長さを切って制御文字を除く。リンクは `http` と `https` だけを、URL を見せてから開く
6. **環境変数**: 親の環境を引き継ぎ、`TERM=xterm-256color` と `COLORTERM=truecolor` を足す。`MATSU_` で始まる変数は渡さない。MATSU 自身の環境は変えない
7. **設定**: `matsu.ini` の `[Terminal]` に置く。最初の項目はシェル（プログラムと引数）とスクロールバックの行数で、行数の既定は 5000 行
8. **文字の幅**: 端末の曖昧幅は 1 桁。エディタの設定（2 桁）には合わせない
9. **`conpty.dll`**: 同梱しない

推奨のうち型 B・C のもの（3. 起動するシェルと場所、9. キー、10. 閉じるとき、12. コードの置き場所）も、推奨のとおりに作る。

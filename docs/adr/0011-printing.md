# ADR-0011: 印刷

- 状態: 決定（細部は Phase 4 で詰める）
- 日付: 2026-10-10（2026-10-11 に、PoC の結果で決定にした）

## 背景

サクラエディタは印刷と印刷プレビューを持つ（ヘッダー・フッター、行番号、折り返し、段組）。印刷の仕組みは OS ごとに大きく違い、UI フレームワークの GPUI には印刷の機能がない。

## 決定

- ページへの割り付け（折り返し、行番号、ヘッダー・フッター、段組）は OS に依存しない部分で行い、結果を「ページごとの、文字とその位置の一覧」にする
- 印刷プレビューは、その一覧を GPUI で描く。3 つの OS で同じものになる
- 印刷ダイアログとプリンターへの出力だけを、OS ごとのモジュールで作る
  - Windows: `PrintDlgW` の印刷ダイアログと GDI（サクラと同じ）
  - macOS: macOS の印刷の仕組み（AppKit の `NSPrintOperation` の印刷パネルに、Core Text と Core Graphics で描く）
  - Linux: PDF を作り、xdg-desktop-portal の印刷の仕組みに渡す
- 文字は、割り付けで決めた位置に 1 つずつ置く。プレビューと OS ごとの印刷には「このグリフをここに描く」だけを頼む。こうすると、プレビューと 3 つの OS の印刷で文字の位置が揃う

## 注意

- Linux でよく使われる GTK の印刷ダイアログは LGPL なので使わない（[CLAUDE.md](../../CLAUDE.md) のライセンスのルール）。ポータルが別のプロセスで出すダイアログは、アプリに組み込まないので使ってよい
- PDF を作るときは、日本語のフォントを必要な文字だけ埋め込む

## PoC で確かめること

- 3 つの OS で、印刷ダイアログを出し、日本語の 1 ページを印刷できるか（Linux は PDF に出力して確かめてもよい）
- 共通の割り付けの結果から、プレビューと印刷の両方を作れるか

## PoC の結果

2026-10-11 に、UI の試作（[poc/gpui-textview](../../poc/gpui-textview/README.md)）で確かめた。詳しくは[印刷の試作の結果](../poc/printing.md)。

- 3 つの OS で、印刷ダイアログを出し、日本語のページを紙に印刷できた。Linux は、WSL2 に CUPS を入れてプリンターを登録して確かめた。Windows では、ダイアログで B5 の横向きを選んでも印刷できた
- 共通の割り付けの結果から、プレビューと印刷の両方を作れた。PDF に出力して比べると、プレビューと 3 つの OS の印刷で、文字が同じ位置に出た
- PDF は krilla（MIT OR Apache-2.0）で作った。ポータルは、D-Bus のライブラリ zbus で直接呼んだ。ポータルのライブラリ ashpd（0.13.13）は、GTK のダイアログが返す設定を読めなかったため

## 残っている確認

Phase 4 で決める。

- Windows 11 の印刷ダイアログの中のプレビュー。`PrintDlgW` で出すダイアログには出ない（サクラも `PrintDlgW` を使う）。出すには、Windows の新しい印刷の仕組み（`IPrintManagerInterop`）に対応する
- Linux の印刷ダイアログを、アプリのウィンドウに結び付けること（GPUI からウィンドウのハンドルを取る）
- PDF で、フォントにない文字を代わりのフォントで描くこと（krilla は代わりのフォントを選ばない）
- 試作で省いたもの（禁則処理、印刷ページ設定のダイアログ、ページの範囲など。[結果](../poc/printing.md)の「サクラとの違い」）

# ADR-0029: 右クリックのワンライナー（登録した 1 行のコマンドで、選んだ文字列を加工する）

- 状態: 決定（2026-11-13 に、ユーザーが「判断してほしいこと」の 5 点をすべて推奨どおりに決めた）
- 日付: 2026-11-13（ユーザーが 2026-11-13 に、企画の 3 番目の意図を補い、3 点を決めた）
- 関連: [ADR-0028](0028-terminal-tab.md)（シェルのタブ。シェルの設定）、[ADR-0024](0024-super-app.md)（決めたこと 7: MATSU だけの節）、[ADR-0018](0018-decision-policy.md)、[ロードマップの Phase 9](../roadmap.md)
- 下調べの詳細（他のエディタ、シェルごとの渡し方、Windows での実験、確かめていないこと）: [docs/poc/oneliner.md](../poc/oneliner.md)

## 背景

- ユーザーの企画（2026-11-11）の 3 番目「右クリックでシェルで加工」。メモには「シェルのワンライナーを新たな外部スクリプトとして登録できるようにする」とあった
- 2026-11-13 に、ユーザーが意図を補った。「右クリックで実行するシェルはマクロやスクリプトとは別に、ワンライナーを登録しておいて、文字列に対して加工を行う、というもの」
  - ロードマップの「ワンライナーを外部のスクリプトとして登録できる」という書き方は、この意図とずれていた
  - 調整役の「シェルのタブの上に作る」という説明も、ずれていた
- 同じ日に、ユーザーが次の 3 点を、調整役の推奨どおりに決めた
  1. 文字列を選んでいないときは、文書全体を加工する
  2. 結果の置き場所は、ワンライナーごとに選ぶ（置き換える（既定）、次の行に入れる、アウトプットに出す）
  3. ワンライナーは、シェルのタブと同じシェルで実行する

## 調べた結果

### 今の MATSU にあるもの

- **外部コマンド実行**（`F_EXECMD`、サクラ互換、`crates/matsu-ui/src/exec/`）
  - 選んだ範囲（なければ文書全体）を標準入力に送り、出力で置き換える。元に戻すは 1 回
  - 実行のあいだは「コマンド実行中」の箱を出し、キャンセルで止められる
  - Windows は `cmd.exe /C`、macOS と Linux は `/bin/sh -c` で動かす
  - 標準出力とエラー出力を 1 つにまとめる（サクラと同じ）
  - macOS では、Finder から起動しても、ログインシェルの `PATH` を使う
- **登録マクロ**（サクラの `[Macro]`、50 個）
  - キー・メニュー・ツールバーは、マクロ n を関数 `F_USERMACRO_0 + n` として呼ぶ
  - メニューの `F_USERMACRO_LIST` は、登録した一覧に広がる
- **右クリックメニュー**（カスタムメニュー 0）
  - 保存したメニューにも、MATSU の項目を版ごとに足せる（版 1: LF・CR でコピー、版 2: エンコードとデコード）
  - カスタムメニューは、一覧に広がる特別な項目も持てる
- **シェルのタブの設定**（`[Terminal]` の `Shell=`、ADR-0028）
  - 空なら既定のシェルを使う。Windows は `pwsh.exe` があればそれ、なければ Windows PowerShell。macOS はログインシェル。Linux は `$SHELL`
  - Windows では 1 本のコマンドライン、Unix では語に分けたもの

### 他のエディタ

出典は docs/poc/oneliner.md の 1 章。

- 「名前とコマンド 1 行」の一覧を設定に持つのは、VS Code の拡張の Filter Text（`filterText.commandList`）と Edit with Shell（`favoriteCommands`）
- Kate の External Tools は、一覧の 1 件ごとに、標準入力と出力先（置き換え、挿入、新しい文書、クリップボード、パネル）を持つ
- TextMate（バンドル）、BBEdit（Text Filters のフォルダ）、CotEditor（Scripts のフォルダ）は、スクリプトのファイルとして持つ
- 選んでいないときに文書全体を加工するのは、BBEdit とサクラの外部コマンド実行
- 終了コードが 0 以外のとき、BBEdit は何も変えずにエラーを出す（12.6.1 のリリースノート）。Vim と Emacs は、既定でエラー出力を結果に混ぜる。Kate の Text Filter は、混ぜるか、分けて見せるかを選べる

### シェルと文字コード

この PC（Windows on Arm64）で、WSL から起動して試した結果。

- **Windows PowerShell 5.1 の入力:** 標準入力を `$input` で読むと、起動時のコードページ（日本語の Windows では CP932）で読む。あとから UTF-8 にしても効かない
  - `[Console]::In.ReadToEnd()` なら、先に UTF-8 にしておけば正しく読める（絵文字も）
- **PowerShell から外部プログラムへ:** 渡す文字コード（`$OutputEncoding`）は、5.1 の既定が US-ASCII で、日本語が `?` になる
- **PowerShell の出力:** 行ごとに CRLF を付ける。入力の最後に改行がなくても付ける
- **PowerShell の終了コード:** `-Command` は、終了コードを 0 か 1 に丸める（外部プログラムの 5 が 1 になる）
- **PowerShell の `-Command -`:** 「スクリプトを標準入力から読む」意味になる。文字列を標準入力で渡すことと両立しない
- **cmd.exe:** `sort` と `more` は、`chcp 65001` をしても、UTF-8 の日本語を正しく扱わない（CP932 として扱う）。`findstr` はバイトをそのまま通す
- **起動の時間**（5 回の中央値。WSL から起動したので、そのぶん長い）: cmd 29 ms、Windows PowerShell 5.1 157 ms、sh 2 ms、bash 3 ms
- **zsh の起動ファイル:** `-c` では `.zshenv` だけを読む。`-l` を付けると `.zprofile` と `.zlogin` も読む。どちらでも `.zshrc` は読まないので、別名（alias）は使えない
- **確かめていないこと:**
  - PowerShell 7
  - macOS の zsh
  - Windows から直接起動したときの、大きな入出力。WSL から cmd 経由で 3 MB 以上を流すと止まったが、WSL の中継のせいかもしれない

## 案と推奨

### 1. 登録の形と置き場所

推奨: `matsu.ini` の MATSU だけの節 `[OneLiner]` に、登録マクロと同じ番号の形で、50 個まで持つ。

```ini
[OneLiner]
Name[000]=重複を除いて並べ替え
Command[000]=sort -u
Output[000]=0
Name[001]=JSON を整える
Command[001]=jq .
Output[001]=0
```

- `Output` は、0 が置き換える、1 が次の行に入れる、2 がアウトプットに出す。ほかの値は 0 として読む
- `Command` が空の番号は、登録していないものとする
- 「入力して実行」の履歴（案 5）は、同じ節に `Recent[00]=` から 20 個まで持つ
- 知らないキーは残す（ほかの MATSU だけの節と同じ）

理由:
- 登録マクロと同じ番号の形にすると、キー・メニュー・ツールバーが「n 番のワンライナー」を関数として呼べる（案 2）
- ファイルを作らないので、マクロやスクリプトと混ざらない

### 2. 関数とメニュー

推奨:
- **関数:** MATSU だけの番号で、次の 3 種類を足す。キー割り当て・カスタムメニュー・ツールバーに置け、マクロからも呼べる
  - `F_ONELINER_0`〜`F_ONELINER_49`: n 番を実行する
  - `F_ONELINER_LIST`: メニューの中で、登録した一覧に広がる特別な項目
  - `F_ONELINER_DIALOG`: ワンライナーを入力して実行する
- **右クリックメニュー:** 「ワンライナー」のサブメニューを足す
  - 中身は、登録した一覧、区切り、「ワンライナーを入力して実行...」「ワンライナーの設定...」
  - 保存した右クリックメニューにも、版 3 として足す
- **メインメニュー:** 「ツール」の「外部コマンド実行」の近くに、同じサブメニューを足す
- 文書が読み取り専用のときは、「置き換える」と「次の行に入れる」のものを灰色にする

### 3. 入力と出力

決まっていること: 選んだ範囲を標準入力に送る。選んでいなければ、文書全体を送る。結果の置き場所は、ワンライナーごとに選ぶ。

推奨:
- **文字列の渡し方:** 標準入力だけで渡す。コマンドラインにも、環境変数にも入れない
  - 外部コマンド実行にある `$F` などの置き換えはしない（PowerShell の `$_` や sh の `$1` とぶつかるため）
- **改行:** LF にそろえて送る。出力の改行（CRLF・LF・CR）は、文書の改行コードにそろえる
- **置き換える:** 選んだ範囲（または文書全体）を出力で置き換え、入れた文字列を選んだ状態にする
  - 入力の最後に改行がなく、出力の最後に改行があれば、1 つだけ取り除く（`sort` や PowerShell が足すため）
- **次の行に入れる:** 入力の最後がある行の次に、出力を行として入れる
  - 出力の最後に改行がなければ足す
  - 入力は変えない。入れた行を選んだ状態にする
- **アウトプットに出す:** アウトプットウィンドウに出す。文書は変えない
- **元に戻す:** 1 回で戻る
- **箱型の選択:** 外部コマンド実行と同じに扱う

### 4. シェルと起動のしかた

決まっていること: シェルのタブと同じシェルで動かす。

推奨:
- **使うシェル:** シェルのタブの設定（`[Terminal]` の `Shell=`）から、実行ファイルだけを使う
  - 設定の引数は使わない。`-NoExit` や `/K` など、タブのための引数が混ざるため
  - 設定が空なら、シェルのタブの既定と同じにする
- **「1 行を実行する」引数:** MATSU が、実行ファイルの名前から決める
  - `pwsh`、`powershell`: `-NoProfile -NonInteractive -Command <前置き + 1 行>`
  - `cmd`: `/D /S /C "<1 行>"`
  - そのほか（`sh`、`bash`、`zsh`、`fish` など）: `-c <1 行>`
- **起動ファイル:** 読ませない（PowerShell のプロファイル、`.zshrc`）
  - zsh は `-c` でも `.zshenv` を読む
  - 別名（alias）や、`.zshrc` の関数は使えない
  - macOS の `PATH` は、外部コマンド実行と同じく、MATSU が調べたログインシェルのものを渡す
- **PowerShell の前置き:** 入出力を UTF-8 にし、標準入力を `[Console]::In` で読んで、行ごとに 1 行のコマンドへ流す
  - 利用者は `$input`（行の並び）で書ける。例: `$input | Sort-Object -Unique`
  - 最後のコマンドの成否と、外部プログラムの終了コードを、そのまま終了コードにする
- **文字コード:** PowerShell と Unix のシェルは UTF-8 にする
  - cmd は、OEM コードページにする（日本語の Windows では CP932）。cmd の `sort` などが、これで読むため
  - CP932 で書けない文字（絵文字など）が入力にあれば、実行しないで知らせる
- **作業フォルダ:** 文書のフォルダ。ファイルのない文書はホーム（シェルのタブと同じ）
- **環境変数:** MATSU の環境をそのまま渡し、何も足さない

### 5. 入力して実行するダイアログ

推奨: 「ワンライナーを入力して実行」（`F_ONELINER_DIALOG`）を作る。

- 1 行の欄（履歴つき）と、結果の置き場所を選んで実行する
- 「登録...」で、名前を付けて、空いている番号に登録できる
- 履歴は、外部コマンド実行とは別に持つ

### 6. 失敗、エラー出力、止まらないコマンド

推奨:
- **エラー出力:** 文書に入れない。標準出力と分けて受け取る（外部コマンド実行は、サクラと同じく、まとめたまま）
- **終了コードが 0 以外:** 文書を変えず、アウトプットに終了コードとエラー出力を出す
- **終了コードが 0 でエラー出力があるとき:** 結果を入れ、エラー出力をアウトプットに出す
- **標準入力:** 送り終えたら閉じる。送ることと受け取ることは、別々に進める
- **時間:** 上限は置かない
  - 実行のあいだは、外部コマンド実行と同じ「コマンド実行中」の箱を出す
  - キャンセルすると、コマンドとそれが起動したプロセスを止める。文書は変えない
- **出力をためる:** 終わるまでためてから、文書に入れる（失敗なら入れないため）
  - ためる量には上限を置き、超えたら止めて何も変えない。値は実装の PR で決める

### 7. 設定の画面

推奨: 共通設定に「ワンライナー」のページを足す。

- 登録マクロのページと同じく、番号の一覧から選んで、名前・コマンド・結果の置き場所を直す
- OK で節を書き、キャンセルでは何も変えない

### 8. 誰が登録し、誰が実行するか（セキュリティ）

推奨:
- **登録:** 利用者だけができる（設定の画面、「入力して実行」の「登録...」、`matsu.ini`）
  - マクロとプラグインは、登録したワンライナーを関数として実行できる。足したり変えたりする API は作らない
  - マクロは、外部コマンド実行で、もともと任意のコマンドを実行できる
- **確認:** 実行のたびには出さない。利用者が登録したものだけを、利用者が選んで動かすため
- **自動では動かさない:** ファイルを開いたとき・保存の前などのイベントで動く仕組みは作らない
- **記録:** 入力と出力をファイルに残さない（アウトプットウィンドウは、メモリの中だけ）

### 9. 名前

推奨（型 F）: 機能の名前は「ワンライナー」にする。

- メニューは「ワンライナー」「ワンライナーを入力して実行...」「ワンライナーの設定...」
- 設定のページも「ワンライナー」

## 決めたこと

2026-11-13 に、ユーザーが背景の 3 点と、「判断してほしいこと」の 5 点を、すべて推奨どおりに決めた。

1. **入力**: 選んだ範囲を標準入力に送る。選んでいなければ、文書全体を送る
2. **結果の置き場所**: ワンライナーごとに選ぶ（置き換える（既定）、次の行に入れる、アウトプットに出す）
3. **シェル**: シェルのタブと同じシェルで動かす。タブの設定から実行ファイルだけを使い、「1 行を実行する」引数は MATSU が足す。起動ファイル（PowerShell のプロファイル、`.zshrc`）は読まない
4. **`matsu.ini`**: `[OneLiner]` に `Name[000]`・`Command[000]`・`Output[000]` を 50 個まで持つ。履歴は `Recent[00]` を 20 個まで
5. **文字コード**: PowerShell と Unix のシェルは UTF-8、cmd は OEM コードページ（日本語の Windows では CP932）。書けない文字があれば実行しない
6. **失敗のとき**: エラー出力は文書に入れない。終了コードが 0 以外なら、文書を変えず、アウトプットに出す
7. **セキュリティ**: 文字列は標準入力だけで渡す。登録は利用者だけ（マクロとプラグインは実行だけできる）。実行のたびの確認はなし。自動では動かさない

推奨のうち型 C・F のもの（案 2 の関数とメニュー、案 3 の細かい点、案 5 のダイアログ、案 7 の設定の画面、案 9 の名前）も、推奨のとおりに作る。

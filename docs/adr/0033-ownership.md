# ADR-0033: 所有権の決まりと、ownership の観点のレビュー

- 状態: 提案（ユーザーが決めたら「決定」にする）
- 日付: 2026-11-15（ユーザーが 2026-11-14 に「タスクがなくなってきたら、設計レベルの ownership をきちんと整備して、ownership 観点でのレビュアーを追加したい」、2026-11-15 に進め方の案を「案の通り」と決めた）
- 関連: [ADR-0019](0019-auto-merge-trial.md)（自動マージの条件）、[ADR-0018](0018-decision-policy.md)（判断の方針）、[ADR-0014](0014-development-process.md)
- 決まりの中身: [docs/ownership.md](../ownership.md)

## 背景

2026-11-09 に X で「LLM の書く Rust は、コンパイラを通すためだけの clone・Arc・to_vec だらけ」という投稿があった。そこで 2026-11-11 に、コードの数を測った（本番のコード 146,818 行）。

- `.clone()` は 1,000 行あたり 8.8（gpui-component は 17.1、GPUI 本体は 16.2）。`Rc`・`RefCell` も少ない。「clone だらけ」にはなっていなかった
- 所有権まわりの Clippy の lint を足した（#374）
- 2026-11-15 に同じ道具で測り直した（本番のコード 162,360 行）。コードは 1 割増えたが、`.clone()` は 8.2 に減った

数は悪くない。一方、レビューでは、数に出ない設計の段階の問題が何度も見つかった。「だれが値を持つか」「状態をどう持つか」「長く生きるものをだれが終わらせるか」の問題。

1. 行の状態を文字列で持ち、保存前の同意を同じ行に混ぜた（#449、`crates/matsu-ui/src/common_settings/pages/plugin/rows.rs`）。表示を直す処理を足すたびに、同意や「失敗で停止」が消える不具合が 3 回続いた
2. gpui-component が持つ選択の位置を、MATSU の側でも覚えた（#447、`crates/matsu-ui/src/menu_bar/popup_keys.rs`）。同じ値を 2 か所で持ち、左右キーで食い違った
3. プラグインのハンドラが、エディタ側の待ち受けのループと同じ変数の場所を使った（#444・#448、`crates/matsu-plugin/src/boot/boot.rb`・`boot.ps1`）。ハンドラの `return`・`exit` が待ち受けごと終わらせた
4. 11 月 11 日に挙げた、まだ直していない 5 つ（#378・#379・#381 の「残っていること」）

これらは、clone や Arc を数えても見えない。コンパイラも Clippy も通る。決まりを書いて、レビューで見るのがよい。

## 決めたこと

1. 所有権の決まりは [docs/ownership.md](../ownership.md) に置く。決まりはコードに合わせて育てる（足す・直すときは、その PR で文書も直す）。この ADR は、決まりを置くことと、下の 2〜5 を決める
2. Rust のコードを変える PR は、すべて、ownership の観点のレビューを Codex（Claude と違う見落としを拾える別のモデル）に 1 回かける。調整役が、`docs/ownership.md` を読ませる決まった指示文で回す。指摘は、ほかの Codex の指摘と同じに扱う（直す。または、棄却する理由を PR に書く）。ドキュメントだけの PR にはかけない
3. このレビューを、ADR-0019 の自動マージの条件に加える（ADR-0019 の追記）
4. 今のコードは、テーマごとに 1 PR で直す。新しい機能の PR と並べて進める。直す候補の一覧は `docs/ownership.md` の「直す候補」に置き、直したら消す
5. 数（`ownership-metrics.py` の `.clone()`・`Rc`・`Arc`・`RefCell`・`.to_owned()` の 1,000 行あたりと、所有権の Clippy の lint の件数）を、月に 1 回測って前と比べる。増えていたら、原因を調べてユーザーに知らせる

## 費用と、残ること

- 費用: Rust の PR 1 本につき、Codex のレビューが 1 回増える。Codex の残りの量と相談して、重いときは調整役が時期をずらす
- 数を決まりにはしない。clone の数は、決まりを守った結果であって、目標ではない（無理に減らして読みにくくするのを避ける）
- 残ること: Clippy の lint を足すかは、月ごとの測定を見て決める。決まりの例は、コードが変わると古くなる。レビューで見つけたら、その PR で直す

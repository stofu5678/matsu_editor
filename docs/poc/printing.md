# 印刷の試作の結果（途中経過）

[ADR-0011](../adr/0011-printing.md) の「PoC で確かめること」の結果。試作は UI の試作 [poc/gpui-textview](../../poc/gpui-textview/README.md) に足した（ファイル > 印刷、印刷プレビュー）。2026-10-11 に Mac の分を作った。Windows と Linux はまだ。

## 確かめることと結果

| 項目（ADR-0011） | Mac | Windows | Linux |
|---|---|---|---|
| 印刷ダイアログを出し、日本語の 1 ページを印刷できるか | ⌘P で印刷パネルが出て、取り消せた。印刷パネルと同じ経路で PDF に出力し、日本語のページを確かめた。紙への印刷はまだ | まだ（GDI） | まだ（PDF と xdg-desktop-portal） |
| 共通の割り付けの結果から、プレビューと印刷の両方を作れるか | できた。プレビューと PDF で、文字の位置が同じだった | プレビューは同じコードで動くはず（ビルドしていない） | 同じ |

## 作り

[ADR-0013](../adr/0013-module-structure.md) のクレートの分け方に合わせて、3 つのモジュールに分けた。

| モジュール | 本番でのクレート | 中身 |
|---|---|---|
| `src/print/layout.rs` | `ume-print`（折り返しは `ume-layout`） | ページへの割り付け。GPUI にも OS にも依存しない。単体テストあり |
| `src/print/preview.rs` | `ume-ui` | 印刷プレビュー（GPUI） |
| `src/print/mac.rs` | `ume-platform` | macOS の印刷パネルとプリンターへの出力（AppKit、Core Text）。`unsafe` はここだけ |

### 割り付け

- サクラの印刷設定（`PRINTSETTING`）のうち、フォント、文字の幅と高さ、段組、行間、余白、英文ワードラップ、行番号、ヘッダー・フッター、タブ幅を持つ。既定値もサクラと同じにした（A4、文字の高さ 2.4 mm・幅 1.2 mm、余白は上 10・下 20・左 20・右 10 mm、ヘッダーの左に `$f`、フッターの中央に `- $p -`）。フォントは、サクラの既定の「ＭＳ 明朝」の代わりに、Mac ではヒラギノ明朝 ProN にした
- 1 行の桁数、1 ページの行数、ヘッダー・フッター・行番号・段の位置は、サクラと同じ式で求める（`sakura_core/print/CPrint.cpp` と `CPrintPreview.cpp`）。折り返しと英文ワードラップもサクラに合わせた（`sakura_core/doc/layout/CLayoutMgr_DoLayout.cpp`）。改行も 1 桁と数えるので、ちょうど 1 行に収まる行は、改行だけが次の行に回る（サクラと同じ）
- 結果は「ページごとの、文字列とその位置（0.1 mm 単位）の一覧」。文字は、半角を 1 マス、全角を 2 マスとする格子に置く。サクラが `ExtTextOut` に文字ごとの幅を渡して、フォントによらず桁を揃えるのと同じ
- タブは次のタブ位置まで進め、何も描かない（サクラと同じ）

### プレビュー（GPUI）

- 割り付けの結果を GPUI で描く。文字列を GPUI で整形し（フォントにない文字は代わりのフォントになる）、グリフを 1 つずつ格子の位置に描く（`Window::paint_glyph`）
- サクラのプレビューと同じく、文字の代わりにウィンドウに出す。上の操作バーも、サクラに合わせた（印刷、前・次、ページ番号、縮小・拡大、倍率、戻る、用紙）。倍率は 10〜400 % で、100 % は実際の大きさ（Mac では 1 pt を 1 ピクセル、ほかでは 96 dpi）。用紙は灰色の上に置き、余白の枠を灰色で描く（サクラと同じ）
- 割り付けを試すために、操作バーに「行番号」「2段組」を足した（サクラでは印刷ページ設定のダイアログで変える）

### Mac の印刷

- AppKit の `NSPrintOperation` に、自分でページを分ける NSView（`knowsPageRange:`、`rectForPage:`）を渡す。印刷パネルで選んだ用紙に合わせて、そのつど割り付けをやり直す。PDF を作ってから印刷する形にはしなかった
- 文字は Core Text で整形し、グリフを 1 つずつ格子の位置に描く（`CTFontDrawGlyphs`）。プレビューと同じく、代わりのフォントは整形に任せる
- 印刷パネルは、ウィンドウのシートで出す。GPUI 自身がダイアログを出すときと同じく、GPUI の更新の外（`spawn` したタスク）から出す
- 印刷したら、印刷パネルで選んだ用紙と向きをアプリの印刷設定（`NSPrintInfo` の共有のもの）に残す。サクラも、印刷ダイアログで選んだプリンターの設定を残す

### 操作

サクラに合わせた（`sakura_core/func/CKeyBind.cpp`、`MainMenu.ini`）。

- Ctrl+P（Mac は ⌘P）で印刷、Ctrl+Shift+P（Mac は ⌘⇧P）で印刷プレビュー。ファイル メニューにもある
- 印刷は、プレビューを開いてから印刷パネルを出す。印刷したらプレビューを閉じ、取り消したらプレビューに残る（`CViewCommander::Command_PRINT`、`CPrintPreview::OnPrint`）
- プレビューの中では、← → と PageUp・PageDown でページ、Ctrl+= / Ctrl+-（Mac は ⌘ でも Control でも。文字の大きさのキーと同じ）で拡大・縮小、Esc で戻る。操作バーのアクセスキー（サクラと同じ P・V・N・O・I・Q）は、Alt なしで押す
- プレビューを開いている間は、編集のコマンド（貼り付け、ファイルを開く、文字の大きさなど）は何もしない。サクラも、プレビューの間はプレビューのオン・オフ以外のコマンドを受け付けない（`CViewCommander::HandleCommand`）。ただし試作では、プレビューの中の ⌘P で印刷パネルを出せる

## Mac での結果（2026-10-11）

Apple M1、macOS 26.1。自己確認モード（`--features self-check`）に印刷の確認を足した（手順は [README](../../poc/gpui-textview/README.md) の「自己確認モード」）。最後まで通った。

- 120 行の日本語と英語の文書（折り返す行、タブ、英文ワードラップを含む）で、⌘⇧P でプレビューを開くと、2 ページになった
- プレビューの中のキー: ⌘- と Control+- で縮小し、→ で次のページに移った。⌘V は隠れた文書に貼り付けず、縮小のキーで文書の文字の大きさも変わらなかった。「行番号」と「2段組」にすると 1 ページに収まり、Esc でプレビューを閉じた
- 印刷パネルと同じ NSView で PDF に出力した。A4 縦で 2 ページ（595 × 842 pt）、A4 横で 3 ページ（842 × 595 pt）。用紙を変えると、割り付けもやり直された（A4 横では 1 行 222 桁・1 ページ 54 行）
- PDF を画像にして、プレビューの画像と比べた。ヘッダー（ファイル名）、折り返し、タブ、英文ワードラップ、フッター（`- 1 -`）が、同じ位置に出た
- ⌘P で印刷パネルがシートで出た。パネルの中のプレビューを描く処理も、落ちずに走った。Esc で取り消すと、プレビューに残って「印刷を取り消しました」と出た。アプリの用紙の設定は変わらなかった

最初は画面がロックされていて、キーを押す確認を走らせられなかった（その間は、自己確認モードを一時的に変えて、プレビューと PDF への出力だけを確かめた）。ロックが解けてから走らせると、次の 2 つの不具合が見つかったので直した。

- プレビューの中で ⌘- を押すと、プレビューが縮小されず、隠れた文書の文字が小さくなった。GPUI は、文脈（key context）のないキーの割り当てを、いちばん深い文脈のものと同じに扱い、同じ深さなら後から足した割り当てを優先する。プレビューのキーを、アプリ全体のキーより先に足していたのが原因。後から足すようにした
- 印刷パネルを出すと、試作が落ちた（デバッグ ビルドだけ）。パネルの中のプレビューは、`NSPrintPreviewGraphicsContext` という NSProxy を通して描かれ、`CGContext` のメッセージは本物の描画先へ転送される。objc2 はデバッグ ビルドで、メッセージを送る前にそのクラスにメソッドがあるかを確かめるが、転送は考えないので、「メソッドがない」として止まる。`CGContext` だけ、確かめずに送るようにした（この確かめはデバッグ ビルドだけで、リリース ビルドでは起きない）

まだ確かめていないこと:

- 紙への印刷と、印刷パネルのプレビューの見た目（ユーザー）。自己確認モードは、パネルを出して取り消すだけで、パネルの中は画像にしていない

### サクラとの違い（試作で省いたこと）

- 半角か全角か: サクラは印刷用のフォントで文字の幅を測る。試作は Unicode の East Asian Width で決めた（幅の曖昧な文字は全角）
- 文字の高さ: サクラは GDI のフォントの高さとして渡す。試作は文字の大きさ（em）として渡した。日本語のフォントでは、ほぼ同じ大きさになる
- 作っていないもの: 禁則処理（行頭・行末、句読点と改行のぶら下げ）、カラー印刷、ヘッダー・フッターのフォント、`$d` などの日付と時刻（`$f`・`$F`・`$p`・`$P` だけ）、行番号を折り返しごとに振る設定、印刷ページ設定のダイアログ、印刷中の取り消し
- ページの範囲や部数は、印刷パネルに任せた

### 分かったこと

- 割り付けを GPUI と OS から切り離せた。文字の位置は割り付けで決め、GPUI や Core Text には「このグリフをここに描く」だけを頼む形にすると、プレビューと印刷で同じ結果になる
- GPUI のキーの割り当てでは、文脈のないものが、いちばん深い文脈のものと同じ扱いになる。プレビューのように画面を切り替える「モード」では、モードの割り当てをアプリ全体の割り当てより後に足すか、アプリ全体の割り当てにも文脈を付ける必要がある。本番でキー割り当ての表を作るときに気をつける
- AppKit の印刷パネルは、描画先を NSProxy で包んで渡すことがある。objc2 のデバッグ ビルドの確かめは、これを誤って止める。本番の `ume-platform` で印刷を書くときも同じ
- ADR-0013 の「`ume-layout` を画面と印刷で共有できるか」は、まだ確かめきれていない。試作の画面は折り返しをしないので、画面と印刷で同じ折り返しを使うところまでは試していない。印刷の折り返しは、文書の行を受け取って行の区切りを返すだけの関数にしたので、画面でも使える形ではある

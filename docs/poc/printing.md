# 印刷の試作の結果

[ADR-0011](../adr/0011-printing.md) の「PoC で確かめること」の結果。試作は UI の試作 [poc/gpui-textview](../../poc/gpui-textview/README.md) に足した（ファイル > 印刷、印刷プレビュー）。2026-10-11 に、Mac の分と、Windows・Linux の分を作った。

Windows と Linux の分は、同じ日に別のセッションがブランチ `poc/print` で、別の作りの割り付けとプレビューの上に作った（Windows は GDI、Linux は PDF と xdg-desktop-portal）。割り付けとプレビューは Mac の分のものを土台にすると決め（2026-10-11、ユーザー）、`poc/print` の Windows と Linux の部分を、この割り付けに載せ替えた。`poc/print` の Mac の部分（PDF を作って PDFKit で印刷する）は使わない。ADR-0011 は、Mac では Core Graphics で描くとしているため。

## 確かめることと結果

| 項目（ADR-0011） | Mac | Windows | Linux |
|---|---|---|---|
| 印刷ダイアログを出し、日本語の 1 ページを印刷できるか | ⌘P で印刷パネルが出て、取り消せた。印刷パネルから PDF に出力でき、日本語のページを確かめた（自己確認モードとユーザー）。紙への印刷はまだ | Ctrl+P で印刷ダイアログが出て、取り消せた。ダイアログを出さずに GDI で「Microsoft Print to PDF」に印刷し、日本語のページを確かめた。ユーザーは載せ替える前の版で、ダイアログから PDF に出力し、プリンターの印刷キューに入るところまで確かめた。紙への印刷はまだ | Ctrl+P で印刷のポータルのダイアログが出て、「ファイルに出力」で日本語のページを PDF に印刷できた。取り消すとプレビューに残った（ユーザー）。ポータルがないときに PDF を保存する動きも確かめた。紙への印刷はまだ |

## 作り

[ADR-0013](../adr/0013-module-structure.md) のクレートの分け方に合わせて、次のモジュールに分けた。

| モジュール | 本番でのクレート | 中身 |
|---|---|---|
| `src/print/layout.rs` | `ume-print`（折り返しは `ume-layout`） | ページへの割り付け。GPUI にも OS にも依存しない。単体テストあり |
| `src/print/preview.rs` | `ume-ui` | 印刷プレビュー（GPUI） |
| `src/print/mac.rs` | `ume-platform` | macOS の印刷パネルとプリンターへの出力（AppKit、Core Text） |
| `src/print/windows.rs` | `ume-platform` | Windows の印刷ダイアログとプリンターへの出力（GDI） |
| `src/print/linux.rs` | `ume-platform` | Linux の印刷ダイアログとプリンターへの出力（xdg-desktop-portal に PDF を渡す） |
| `src/print/pdf.rs` | `ume-print` | 割り付けの結果から PDF を作る（krilla）。Linux の印刷と `--print-pdf` で使う |

`unsafe` は、OS ごとのモジュール（`mac.rs` と `windows.rs`）だけにある。

### 割り付け

- サクラの印刷設定（`PRINTSETTING`）のうち、フォント、文字の幅と高さ、段組、行間、余白、英文ワードラップ、行番号、ヘッダー・フッター、タブ幅を持つ。既定値もサクラと同じにした（A4、文字の高さ 2.4 mm・幅 1.2 mm、余白は上 10・下 20・左 20・右 10 mm、ヘッダーの左に `$f`、フッターの中央に `- $p -`）。フォントは、サクラの既定の「ＭＳ 明朝」の代わりに、Mac ではヒラギノ明朝 ProN にした
- 1 行の桁数、1 ページの行数、ヘッダー・フッター・行番号・段の位置は、サクラと同じ式で求める（`sakura_core/print/CPrint.cpp` と `CPrintPreview.cpp`）。折り返しと英文ワードラップもサクラに合わせた（`sakura_core/doc/layout/CLayoutMgr_DoLayout.cpp`）。改行も 1 桁と数えるので、ちょうど 1 行に収まる行は、改行だけが次の行に回る（サクラと同じ）
- 結果は「ページごとの、文字列とその位置（0.1 mm 単位）の一覧」。文字は、半角を 1 マス、全角を 2 マスとする格子に置く。サクラが `ExtTextOut` に文字ごとの幅を渡して、フォントによらず桁を揃えるのと同じ
- タブは次のタブ位置まで進め、何も描かない（サクラと同じ）

### プレビュー（GPUI）

- 割り付けの結果を GPUI で描く。文字列を GPUI で整形し（フォントにない文字は代わりのフォントになる）、グリフを 1 つずつ格子の位置に描く（`Window::paint_glyph`）
- サクラのプレビューと同じく、文字の代わりにウィンドウに出す。上の操作バーも、サクラに合わせた（印刷、前・次、ページ番号、縮小・拡大、倍率、戻る、用紙）。倍率は 10〜400 % で、100 % は実際の大きさ（Mac では 1 pt を 1 ピクセル、ほかでは 96 dpi）。用紙は灰色の上に置き、余白の枠を灰色で描く（サクラと同じ）
- 割り付けを試すために、操作バーに「行番号」「2段組」を足した（サクラでは印刷ページ設定のダイアログで変える）

### Mac の印刷

- AppKit の `NSPrintOperation` に、自分でページを分ける NSView（`knowsPageRange:`、`rectForPage:`）を渡す。印刷パネルで選んだ用紙に合わせて、そのつど割り付けをやり直す。PDF を作ってから印刷する形にはしなかった
- 文字は Core Text で整形し、グリフを 1 つずつ格子の位置に描く（`CTFontDrawGlyphs`）。プレビューと同じく、代わりのフォントは整形に任せる
- 印刷パネルは、ウィンドウのシートで出す。GPUI 自身がダイアログを出すときと同じく、GPUI の更新の外（`spawn` したタスク）から出す
- 印刷したら、印刷パネルで選んだ用紙と向きをアプリの印刷設定（`NSPrintInfo` の共有のもの）に残す。サクラも、印刷ダイアログで選んだプリンターの設定を残す

### Windows の印刷

- サクラと同じく、`PrintDlgW` で印刷ダイアログを出し、返ってきたプリンターの DC に GDI で描く。用紙の大きさはプリンターから取り（`PHYSICALWIDTH` と `PHYSICALHEIGHT`）、その用紙で割り付けをやり直す。ページの範囲は選べないようにし（`PD_NOPAGENUMS`）、部数はプリンターのドライバーに任せた。「ファイルへ出力」は出さない（`PD_HIDEPRINTTOFILE`）。サクラは出すが、選んでもプリンターに印刷する
- ダイアログは、閉じるまで戻ってこないので、GPUI 自身がダイアログを出すときと同じく、別のスレッドから出す。持ち主はアプリのウィンドウにする
- 文字は、文字ごとの送り幅を `ExtTextOutW` に渡して格子に置く（サクラと同じ）。位置はベースラインで渡し（`TA_BASELINE`）、半角用と全角用のフォントを `font_runs` で切り替える。送り幅は、0.1 mm で求めた文字ごとの位置をプリンターの点に直してから差を取る。送り幅を丸めて足していくと、長い行で位置がずれていくため
- 行番号の区切り線は `MoveToEx` と `LineTo` で描く。サクラは 1 ドットのペンで描くが、試作は Mac と同じ 0.5 pt にした
- Windows 11 の印刷ダイアログでは、右側のプレビューに「このアプリはプレビューをサポートしていません」と出る。`PrintDlgW` で出すダイアログは、Windows 11 では新しい印刷の画面になり、そのプレビューは、Windows の新しい印刷の仕組み（`IPrintManagerInterop` と `IPrintDocumentSource`）に対応したアプリにしか出ないため。サクラも `PrintDlgW` を使う（`sakura_core/print/CPrint.cpp`）ので、同じ表示になるはず。試作の印刷プレビューがあるので、当面はこのままにする

### Linux の印刷

- 割り付けの結果を PDF にし（krilla。フォントは使った文字の分だけ埋め込む）、印刷のポータル（`org.freedesktop.portal.Print`）に渡す。デスクトップの印刷ダイアログは、ポータルが出す。GTK の印刷ダイアログを直接使わないのは、LGPL だから（ADR-0011）
- ポータルは、D-Bus のライブラリ zbus で直接呼ぶ。最初は ashpd（GPUI も使うポータルのライブラリ）の印刷の機能で呼んでいたが、「ファイルに出力」で印刷すると失敗した。GTK のダイアログは出力の形式を `pdf`（小文字）で返すのに、ashpd（0.13.13。まだ公開されていない最新のソースも同じ）は `PDF`（大文字）しか受け付けず、ダイアログの設定を読めないため。今は、ダイアログの返事から用紙と `token` だけを読む
- ポータルの `PreparePrint` でダイアログを出し、そこで選ばれた用紙と向きで割り付けをやり直して PDF を作り、`Print` に渡す
- ダイアログは、アプリのウィンドウに結び付けていない。結び付けるには、ウィンドウの Wayland か X11 のハンドルを GPUI から取って渡す必要がある
- ポータルが使えないとき（ダイアログが出る前にポータルがエラーを返したとき）は、PDF を一時ディレクトリに `ume-print-<ランダムな文字>.pdf` として保存し、その場所をプレビューに出す。ファイルは、ほかのユーザーが読めないように作る。ポータルに渡す PDF は、名前のないファイルにする
- krilla は文字の整形も代わりのフォントの選択もしないので、1 文字ずつ印刷のフォントで描く。フォントにない文字（絵文字など）は、空の字形（豆腐）になる。フォントのファイルは fontconfig（`fc-match`）で探す

### 操作

サクラに合わせた（`sakura_core/func/CKeyBind.cpp`、`MainMenu.ini`）。

- Ctrl+P（Mac は ⌘P）で印刷、Ctrl+Shift+P（Mac は ⌘⇧P）で印刷プレビュー。ファイル メニューにもある
- 印刷は、プレビューを開いてから印刷パネル（Windows と Linux では印刷ダイアログ）を出す。印刷したらプレビューを閉じ、取り消したらプレビューに残る（`CViewCommander::Command_PRINT`、`CPrintPreview::OnPrint`）。3 OS で同じ
- プレビューの中では、← → と PageUp・PageDown でページ、Ctrl+= / Ctrl+-（Mac は ⌘ でも Control でも。文字の大きさのキーと同じ）で拡大・縮小、Esc で戻る。操作バーのアクセスキー（サクラと同じ P・V・N・O・I・Q）は、Alt なしで押す
- プレビューを開いている間は、編集のコマンド（貼り付け、ファイルを開く、文字の大きさなど）は何もしない。サクラも、プレビューの間はプレビューのオン・オフ以外のコマンドを受け付けない（`CViewCommander::HandleCommand`）。ただし試作では、プレビューの中の ⌘P で印刷パネルを出せる

## Mac での結果（2026-10-11）

Apple M1、macOS 26.1。自己確認モード（`--features self-check`）に印刷の確認を足した（手順は [README](../../poc/gpui-textview/README.md) の「自己確認モード」）。最後まで通った。

- 120 行の日本語と英語の文書（折り返す行、タブ、英文ワードラップを含む）で、⌘⇧P でプレビューを開くと、2 ページになった
- プレビューの中のキー: ⌘- と Control+- で縮小し、→ で次のページに移った。⌘V は隠れた文書に貼り付けず、縮小のキーで文書の文字の大きさも変わらなかった。「行番号」と「2段組」にすると 1 ページに収まり、Esc でプレビューを閉じた
- 印刷パネルと同じ NSView で PDF に出力した。A4 縦で 2 ページ（595 × 842 pt）、A4 横で 3 ページ（842 × 595 pt）。用紙を変えると、割り付けもやり直された（A4 横では 1 行 222 桁・1 ページ 54 行）
- PDF を画像にして、プレビューの画像と比べた。ヘッダー（ファイル名）、折り返し、タブ、英文ワードラップ、フッター（`- 1 -`）が、同じ位置に出た
- ⌘P で印刷パネルがシートで出た。パネルの中のプレビューを描く処理も、落ちずに走った。Esc で取り消すと、プレビューに残って「印刷を取り消しました」と出た。アプリの用紙の設定は変わらなかった

最初は画面がロックされていて、キーを押す確認を走らせられなかった（その間は、自己確認モードを一時的に変えて、プレビューと PDF への出力だけを確かめた）。ロックが解けてから走らせると、次の 2 つの不具合が見つかったので直した。

- プレビューの中で ⌘- を押すと、プレビューが縮小されず、隠れた文書の文字が小さくなった。GPUI は、文脈（key context）のないキーの割り当てを、いちばん深い文脈のものと同じに扱い、同じ深さなら後から足した割り当てを優先する。プレビューのキーを、アプリ全体のキーより先に足していたのが原因。後から足すようにした
- 印刷パネルを出すと、試作が落ちた（デバッグ ビルドだけ）。パネルの中のプレビューは、`NSPrintPreviewGraphicsContext` という NSProxy を通して描かれ、`CGContext` のメッセージは本物の描画先へ転送される。objc2 はデバッグ ビルドで、メッセージを送る前にそのクラスにメソッドがあるかを確かめるが、転送は考えないので、「メソッドがない」として止まる。`CGContext` だけ、確かめずに送るようにした（この確かめはデバッグ ビルドだけで、リリース ビルドでは起きない）

ユーザーも Mac で印刷を確かめ、問題はなかった（2026-10-11）。紙には印刷せず、印刷パネルから PDF に出力した。

まだ確かめていないこと:

- 紙への印刷

## Windows での結果（2026-10-11）

Windows 11（ARM64、Snapdragon）。フォントは、サクラの既定の「ＭＳ 明朝」と同じ MS Mincho。

- 自己確認モードが最後まで通った。プレビューのキー（Ctrl+- で縮小、→ で次のページ、Ctrl+V が隠れた文書に貼り付けない、行番号と 2 段組、Esc で閉じる）は、Mac と同じ結果だった
- 同じ文書を、ダイアログを出さずに、GDI で「Microsoft Print to PDF」に、krilla で PDF に印刷した。どちらも A4 で 2 ページ。PDF を画像にして比べると、ヘッダー、折り返し、タブ、英文ワードラップ、フッターが、1〜2 ピクセル（0.2 mm）以内の同じ位置に出た。プレビューの画像とも同じ割り付けだった
- GDI は、フォントにない絵文字を代わりのフォントで描いた（krilla の PDF では豆腐になる）
- 100 万行の文書で Ctrl+P を押すと、プレビュー（12,196 ページ）が開き、続けて印刷ダイアログが出た。Esc で取り消すと、プレビューに残って「印刷を取り消しました」と出た。もう一度 Esc を押すと、プレビューが閉じて文書に戻った。キーは、ほかのプロセスから Windows のキー入力として送って確かめた。自己確認モードは、Windows では GPUI の中にキーを送るので、OS の印刷ダイアログには届かない

ユーザーは、載せ替える前の版（ブランチ `poc/print`）で確かめた（2026-10-11）。印刷ダイアログと GDI の作りは今と同じで、割り付けとプレビューが違う。

- プレビューは問題なく動いた
- 印刷ダイアログから「Microsoft Print to PDF」で PDF に出力できた
- プリンターへの印刷は、プリンターのネットワークの不調で紙には出なかったが、印刷キューには入った
- 印刷ダイアログのプレビューには「このアプリはプレビューをサポートしていません」と出た（上の「Windows の印刷」）

まだ確かめていないこと:

- 紙への印刷（載せ替えた後の版で、ダイアログから印刷する）

## Linux での結果（2026-10-11）

WSL2（Ubuntu 24.04、ARM64）と WSLg。フォントは Noto Serif CJK JP。

- 自己確認モードが最後まで通った（Wayland で起動したので、画像の保存とクリップボードの確認は飛ばした）。プレビューのキーは、Mac・Windows と同じ結果だった。同じ文書の PDF は A4 で 2 ページで、ページ数はプレビューと同じだった
- `--print-pdf` で作った PDF を画像にして見ると、Windows の GDI と同じ割り付けだった
- xdg-desktop-portal を入れる前に、印刷の関数を試験用のコードから呼ぶと、ポータルがないというエラーを出して、PDF を `/tmp/ume-print-<ランダムな文字>.pdf` に保存した（ほかのユーザーが読めない 0600 で作られた）
- xdg-desktop-portal と xdg-desktop-portal-gtk を入れると、Ctrl+P でプレビューが開き、ポータルの印刷ダイアログ（GTK）が出た。「ファイルに出力」で印刷すると、プレビューが閉じて「印刷しました」と出て、`~/output.pdf` に A4 で 1 ページの PDF ができた。ヘッダー、本文（明朝体）、フッターの位置は、画像にして確かめた。キャンセルすると、プレビューに残って「印刷を取り消しました」と出た（ユーザー）
- ユーザーが確かめる中で、次の 2 つの不具合が見つかったので直した
  - 「ファイルに出力」で印刷すると、「印刷のポータルを使えません（ZBus Error: unknown variant）」と出て印刷できなかった。ashpd がダイアログの設定を読めなかったため（上の「Linux の印刷」）。ポータルを zbus で直接呼ぶようにした
  - メニュー（ファイル > 印刷プレビュー）からプレビューを開くと、「戻る」でもキーでもプレビューを抜けられなかった。下の「分かったこと」のとおり、メニューが閉じるときに、隠れたエディタにフォーカスを戻していたため。Windows でも同じことが起きた（マウスのクリックを送って再現した）。直した後は、Windows でも Linux でも抜けられた。Mac は OS のメニューバーを使うので起きない

### サクラとの違い（試作で省いたこと）

- 半角か全角か: サクラは印刷用のフォントで文字の幅を測る。試作は Unicode の East Asian Width で決めた（幅の曖昧な文字は全角）
- 用紙: Windows と Linux のプレビューは、A4 縦のままにした（印刷するときは、ダイアログで選んだ用紙で割り付けをやり直す）。サクラは印刷の設定に用紙を持ち、プレビューもその用紙で描く。Mac は、アプリの印刷の設定の用紙で描く
- 文字の高さ: サクラは GDI のフォントの高さとして渡す。試作は文字の大きさ（em）として渡した。日本語のフォントでは、ほぼ同じ大きさになる
- 作っていないもの: 禁則処理（行頭・行末、句読点と改行のぶら下げ）、カラー印刷、ヘッダー・フッターのフォント、`$d` などの日付と時刻（`$f`・`$F`・`$p`・`$P` だけ）、行番号を折り返しごとに振る設定、印刷ページ設定のダイアログ、印刷中の取り消し
- ページの範囲や部数は、印刷パネルに任せた

### 分かったこと

- 割り付けを GPUI と OS から切り離せた。文字の位置は割り付けで決め、GPUI や Core Text には「このグリフをここに描く」だけを頼む形にすると、プレビューと印刷で同じ結果になる
- GPUI のキーの割り当てでは、文脈のないものが、いちばん深い文脈のものと同じ扱いになる。プレビューのように画面を切り替える「モード」では、モードの割り当てをアプリ全体の割り当てより後に足すか、アプリ全体の割り当てにも文脈を付ける必要がある。本番でキー割り当ての表を作るときに気をつける
- AppKit の印刷パネルは、描画先を NSProxy で包んで渡すことがある。objc2 のデバッグ ビルドの確かめは、これを誤って止める。本番の `ume-platform` で印刷を書くときも同じ
- GDI でも、文字ごとの送り幅を渡せば、プレビュー・Mac・PDF と同じ位置に文字を置ける。Windows・Linux・Mac の印刷で違うのは、ダイアログと「このグリフをここに描く」ところだけになった
- Windows 11 で、印刷ダイアログの中にもプレビューを出すには、Windows の新しい印刷の仕組み（`IPrintManagerInterop` と `IPrintDocumentSource`）に対応し、ページを Direct2D で描いて渡す必要がある。サクラもしていないので、出すかどうかは Phase 4（印刷）で決める
- GPUI では、フォーカスのある要素が画面に描かれていないと、キーとアクションはウィンドウのいちばん外側から送られ、ビューの中の処理に届かない。試作のメニューバー（gpui-component の `AppMenuBar` を元にした `menu_bar.rs`）は、閉じるときにいつも元の要素にフォーカスを戻していたので、メニューからプレビューを開くと、フォーカスがプレビューに隠れたエディタに戻っていた。ほかのものがフォーカスを取っていないときだけ戻すようにした（gpui-component の `PopupMenu` と同じ確かめ方）。本番で画面を切り替えるとき（プレビュー、ダイアログ、ペインの切り替え）も、フォーカスの行き先に気をつける
- ADR-0013 の「`ume-layout` を画面と印刷で共有できるか」は、まだ確かめきれていない。試作の画面は折り返しをしないので、画面と印刷で同じ折り返しを使うところまでは試していない。印刷の折り返しは、文書の行を受け取って行の区切りを返すだけの関数にしたので、画面でも使える形ではある
